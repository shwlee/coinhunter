# 프롬프트 생성기 최종 검증 기록

- 검증일: 2026-10-17
- 대상: [구현 계획](prompt-assistant-plan.md)의 1~5단계. 공통 규약·탭·복사·가져오기·검사·적용과 기존 작성 흐름의 회귀.
- 결과: 전체 자동 테스트 195개 및 아래 브라우저 검사 5종 통과. 범위 내에서 추가 수정이 필요한 높음/중간 결함은 발견하지 않았다.
- 환경: Windows, Node.js 18.20.2, Playwright/Edge headless. 사용자 개발 서버와 별도인 임시 포트·계정·데이터를 사용했다.

2026-10-17 후속 UI 검증: 프롬프트 조합을 명시적 생성 버튼으로 전환했다. 전략만 선택한 상태와 추가 요청·코드 포함 상태에서 생성 전 본문 없음, 생성 후 항상 표시, 입력 변경 후 기존 본문 보존·복사/전체 선택 차단, 재생성 후 새 본문 복사, 실패 대체·지연 복사·문서 초기화·모바일을 확장 브라우저 검사로 확인했다. 통합 흐름도 전략→생성→복사로 갱신했다. 아래 5단계 이력의 접힌 미리보기·자동 갱신 설명보다 이 후속 동작을 우선한다.

후속 재검증 결과: 프롬프트·실제 경기 통합·기존 AI 연결·작업실 브라우저 검사 4종 통과. 전체 자동 테스트는 권한 제한 환경에서 194/195개 통과했으며 다중 프로세스 계정 파일 잠금 1건이 EPERM으로 실패했다. 동일한 `node --test test/account-file-lock.test.js`를 샌드박스 밖에서 실행하여 9/9개 통과했다. 저장소/잠금 코드는 수정하지 않았다. 첫 전체 실행은 임시 파일 정리 EPERM 후 종료되지 않아 중단하고 별도 임시 경로에서 다시 실행했다. 아래 195개 전체 통과 기록은 최초 5단계 검증 결과다.

형식 검사는 `npm run format:check`와 동일한 Prettier 인자(`src public scripts test examples maps package.json .prettierrc.json .github`)를 사용해 로컬 실행 파일을 `node`로 직접 실행했고 통과했다. 이 환경의 npm 실행기가 사용자 홈 경로 확인 중 EPERM으로 실패하여 프로젝트 내부 실행 파일로 우회했다. `git diff --check`도 통과했다. 각 브라우저 스크립트 역시 직접 `node scripts/…-smoke.js`로 실행해 동일 검증을 수행했다.

## 통합 흐름의 실제 확인 범위

새 통합 검사는 AI를 끄고 키를 등록하지 않은 로그인 계정으로 시작한다. 전략과 요청을 선택해 복사된 본문을 읽고 신규 작성 의도·가중치·코드 제외 상태를 확인한다. 외부 AI가 돌려준 코드 역할에는 저장소의 가까운 코인 탐색 예제를 사용한다. 이 응답만 대체하며 HTTP 실행 검사·QuickJS 경기·파일 저장은 실제 구현이다.

가져오기 모달에서 단일 JavaScript 블록을 검사하고 적용한다. 적용 전에는 편집기가 바뀌지 않고 적용 후에도 계정에 저장되지 않는다. 임시 대칭 4×4 맵과 시작 위치를 선택해 같은 소스가 실제 경기 요청에 사용되는 것을 확인한다. 플레이어는 코인 4개를 수집하여 40점, `coins-collected` 사유로 종료한다. 알고리즘 호출이 발생하고 패널티·시간 초과·예외는 0회다.

편집기로 돌아와 처음 저장하고 새 페이지에서 다시 불러온다. 현재 코드 포함으로 수정 프롬프트를 복사해 원문 일치를 확인한다. 수정 코드를 검사·적용하고 undo/redo한 뒤 덮어쓴다. 원본 ID를 유지하고 리비전은 2로 증가하며 저장 목록에는 하나만 남는다. 다른 계정의 원문 조회는 404이고 같은 계정의 새 로그인/모바일 재조회는 저장한 소스와 일치한다. 최종 검사/경기 업로드 파일은 남지 않는다.

## 리뷰 항목과 판단

| 항목 | 확인 및 판단 |
| --- | --- |
| 외부 호출·비용 | 기본 프롬프트/가져오기 흐름의 `/api/ai/` 요청과 외부 HTTP 요청은 0회. 직접 AI 요청을 자동 시작하는 경로 없음 |
| 데이터 경계 | 규약 조회는 로그인 전용. 복사 본문에 계정/키/연결 메타데이터를 자동 추가하지 않음. 소스는 포함 선택 시만 복사. 새 프롬프트 이력/자동 저장 없음 |
| 붙여 넣은 코드 | 텍스트로만 취급하고 원문 또는 단일 블록을 검사. 실행 검사는 기존 서버/QuickJS 경계에서 수행. 코드 크기 제한을 새로 추가하지 않음 |
| 경합·문서 보존 | 입력 변경/문서 전환/취소 시 통과 상태를 무효화. 요청 순번·문서 버전으로 늦은 결과 폐기. 적용 전 편집 변경 확인. 기존 원본/문서 이름 유지 및 undo 가능 |
| 기존 유료 요청 | 탭 전환과 수동 가져오기 적용이 진행 요청을 취소/재전송하지 않음. API 후보 적용은 기존 기준 문서 변경 확인 유지 |
| 검사 수명 | 검사 연결 종료는 일회성 preflight 취소에만 전달. 완료/취소 시 임시 파일 정리. 실제 경기의 지속 프로세스·호출별 500ms 규칙은 유지 |
| 사용자 안내 | 검사 통과가 모든 입력·분기를 보장하지 않는다고 표시. 미지원/거부된 자동 복사는 본문 선택으로 대체. 기존 사용 문서의 로컬 템플릿 전용 설명은 현재 기능에 맞게 수정 |

단위/HTTP 검증과 실제 브라우저 흐름을 함께 확인한 결과다. 이 범위에서 추가로 보고할 높음/중간 결함은 없다. 새 통합 스크립트는 테스트용 목업 계정 선택지와 실제 전략 데이터 형식에 맞추어 검증했다.

## 별도 실사용·운영 확인

- 실제 ChatGPT·Claude·Gemini 웹사이트에서 프롬프트를 사용해 생성한 응답의 품질과 출력 규칙 준수는 별도 확인한다. 이번 대체 응답을 실제 AI 생성 성공으로 간주하지 않는다.
- 클립보드는 메모리 대체물로 성공/거부/미지원/지연을 검증했다. 사용자 OS 클립보드나 브라우저의 실제 권한 설정은 변경하지 않았다. 사내 HTTP·실제 모바일 기기의 복사 메뉴는 배포 환경에서 확인한다.
- 401/429·규약 오류·지연 응답과 기존 AI 제공자 응답 일부는 대체했다. 실제 Google 로그인과 제공자 결제/네트워크를 재시험하지 않았다.
- 샘플 실행 24회 및 작은 통합 경기의 성공은 모든 맵·복잡한 알고리즘·모든 실행 분기의 성공 보장이 아니다. 실제 전략은 테스트 플레이로 확인한다.
- Claude/Gemini 직접 생성 어댑터, DB/컨테이너/사내 배포, 배포 전 필수 [개인정보 운영 준비](privacy-operations-plan.md)는 기존 후속 작업으로 남긴다.

사용법은 [로컬 작업실 안내](local-authoring.md)의 작성과 테스트 절을 따른다. 이번 단계는 사용자 서버를 시작/재시작하지 않았다. 새 정적 모듈과 검사 취소 경로를 적용하려면 사용자 서버 재시작과 화면 새로고침이 필요하다.
