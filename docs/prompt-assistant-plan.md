# 알고리즘 작성 도우미·프롬프트 생성기 작업 계획

- 작성일: 2026-10-17
- 상태: 1~5단계 완료. 공통 규약·사이드바·프롬프트 복사·생성 코드 가져오기/검사/적용과 최종 통합 검증·리뷰를 마쳤다. [검증 기록](prompt-assistant-verification.md).
- 목적: API 키 등록 없이 전략을 프롬프트로 만들고, 외부 AI에서 받은 코드를 검사·적용해 알고리즘을 작성한다.
- 관련: [기존 AI 계획](ai-scripting-plan.md), [작업실 계획](algorithm-authoring-plan.md), [AI 생성 구현](ai-generation.md), [개인정보 운영 준비](privacy-operations-plan.md).

## 1. 범위와 기본 원칙

코드 편집기를 중심에 두고 오른쪽 AI 사이드바를 `알고리즘 작성 도우미`로 확장한다. 기본 탭은 `프롬프트`, 다른 탭은 `AI 연결`이다. 기존 API 연결·모델 선택·직접 생성/수정·진행 상태·후보 기능은 유지한다. 직접 편집·파일 가져오기·템플릿 코드 생성·저장·테스트 플레이도 유지한다.

프롬프트 생성에는 외부 AI 호출·API 키·모델 선택·암호화 키·DB가 필요하지 않다. `AI_ENABLED=false`에서도 로그인 사용자는 이용할 수 있다. 게스트는 기존 정책대로 작업실 생성 기능에 접근하지 못한다. 일반 로그인·권한 검사는 계속 필요하다.

외부 AI에 붙여 넣기와 생성 코드 가져오기는 사용자가 수행한다. AI 사이트 자동 조작·로그인·결제·클립보드 읽기는 제공하지 않는다. 프롬프트 생성 자체에는 API 비용이 없지만 외부 AI의 무료 이용 가능 여부를 보장하지 않는다.

첫 버전은 프롬프트 생성·복사·미리보기와 생성 코드 붙여 넣기·검사·명시적 적용까지다. 프롬프트 이력·대화 수집·외부 AI OAuth·자동 재생성·자동 저장·자동 경기 실행은 추가하지 않는다. 진단 첨부와 큰 코드의 부분 수정은 후속으로 둔다.

## 2. UI와 사용자 흐름

```text
코드 편집기                         알고리즘 작성 도우미
                                   [프롬프트] [AI 연결]
                                   전략 템플릿 선택
                                   선택한 전략 우선순위
                                   추가 요청 입력
                                   ─────────────────────
                                   프롬프트 탭
                                   현재 코드 포함 [끔/켬]
                                   [프롬프트 복사]
                                   ▸ 미리보기
                                   [생성된 코드 가져오기]
```

공통 전략·순서·추가 요청 영역은 두 탭이 공유한다. 기존 최대 3개·드래그 순서·가중치 5/3/1·아이템 획득/회피 충돌 검사를 유지한다. API 연결·모델·직접 생성과 진행 영역은 `AI 연결` 탭에서 제공한다. 기존 사이드바 접기·기본 펼침·그립 크기 조절·코드 최대화와 모바일 세로 배치를 유지한다.

### 프롬프트 탭

1. 전략 또는 추가 요청이 하나 이상 있으면 프롬프트를 구성할 수 있다. 규약 준비 중·실패·재시도 상태를 표시한다.
2. `현재 코드 포함`은 기본 끔이다. 빈 코드나 새 알고리즘의 빈 기본 틀은 수정용으로 처리하지 않는다. 작성/불러온 코드가 있을 때 사용자가 켤 수 있다.
3. 켜면 현재 코드 수정, 끄면 신규 작성 의도로 구성한다. 문서 교체 시 스위치를 초기화하고 포함 상태에서 코드가 바뀌면 다음 프롬프트에도 최신 코드를 쓴다.
4. `프롬프트 복사`를 주 액션으로 두고, 아래에 외부 AI에 붙여 넣은 뒤 생성 코드를 가져오라는 짧은 안내를 둔다.
5. 긴 본문은 접힌 미리보기에 표시한다. 본문을 별도 편집하지 않고 전략·요청으로 수정한다. 코드 포함 여부와 본문 길이를 표시한다.
6. 큰 코드를 조용히 자르거나 API 생성의 모델별 상한을 그대로 적용하지 않는다. 외부 AI 입력 한도는 서비스가 확인할 수 없음을 필요시 안내한다.

### 생성된 코드 가져오기 모달

1. 큰 코드 붙여 넣기 영역과 `코드 검사` 버튼을 제공한다.
2. 원문 JavaScript 또는 명확한 JavaScript 코드 블록 하나를 받는다. 여러 코드 블록·설명으로 모호하면 임의 결합하지 않고 코드만 붙여 넣도록 안내한다.
3. 기존 실행 전 검사로 구문·금지 기능·필수 메서드·샘플 실행을 확인하고 실패 원인과 가능한 코드 위치를 표시한다.
4. 통과한 코드에만 `편집기에 적용`을 활성화한다. 검사 후 입력이 바뀌면 이전 통과 상태를 해제한다.
5. 적용 전까지 기존 편집기·문서 이름·저장 원본을 유지한다. 모달 취소도 코드를 바꾸지 않는다.
6. 모달을 연 뒤 편집 문서가 변경됐다면 교체 확인을 거친다. 적용은 기존 undo로 되돌릴 수 있는 하나의 코드 교체로 처리한다.
7. 적용 후 기존 문서의 미저장 변경으로 처리한다. 원본에 덮어쓰기/새 이름 저장 흐름을 유지하고 임의 신규 문서로 바꾸지 않는다.

## 3. 공통 규약과 프롬프트 내용

현재 `src/ai/input.js`의 `buildGenerationInput`은 게임 API·규칙·예제와 전략 순위를 조합하지만 API 연결/모델을 요구하는 검증과 JSON 출력 지시가 함께 있다. 이 내용을 그대로 복사하지 않고 공통 규약·전략과 방식별 검증·출력 요구를 분리한다.

| 구성 | 공통 | 방식별 차이 |
| --- | --- | --- |
| 게임 규약 | 필수 함수·타일/아이템·방향·독립 턴·실행 제한·예제 | 없음 |
| 전략 | 템플릿·순서/가중치·요청·신규/수정 의도 | 수정 원문을 읽는 경로 |
| 출력 | 규약에 맞는 완성된 단일 파일 | API는 기존 JSON schema, 복사용은 JavaScript 코드 블록 하나 |
| 연결 | 없음 | API만 연결·모델·제공자·호출 한도 검증 |

복사용 프롬프트는 한국어로 게임 목적·규칙·필수 형식·전략·추가 요청·선택한 현재 코드를 구분한다. `module.exports` 클래스의 `initialize`, `getName`, `moveNext`와 실제 인자·방향 값·500ms 호출 제한·인스턴스 유지·금지 기능·맵 크기 전달·아이템 규칙을 포함한다. 런타임 정책과 문서를 대조하고 규약 사본을 여러 곳에 따로 관리하지 않는다.

외부 AI에는 여러 대안/설명 대신 완성된 JavaScript 코드 블록 하나를 요청한다. 외부 AI가 출력 형식이나 실행 규약을 항상 지킨다고 보장하지 않으며 실제 검사로 확인한다. 게임 규약과 충돌하는 전략은 규약을 우선하도록 지시한다.

사용자 코드·추가 요청은 공통 규약과 명확하게 구분한다. 원문에 구분 문자가 있어도 내용 손실이나 잘못된 경계 해석이 없도록 인용/직렬화한다. 계정 이메일·Google 신원·세션·연결 이름·API 키·내부 경로는 본문에 넣지 않는다.

## 4. 구현 구성과 데이터 경계

다음 파일·경로는 구현 시 확정할 후보이며 이미 존재하는 새 기능을 뜻하지 않는다.

| 영역 | 작업 |
| --- | --- |
| `src/ai/input.js`와 공통 규약 모듈 | 공통 규약·전략 분리, 기존 OpenAI 입력 호환 유지 |
| 인증된 규약 조회 | 예: `GET /api/algorithm-assistant/contract`. 작업실 인증에서 제공하고 AI 활성화·연결 정책과 분리 |
| `public/prompt-assistant.js` | 전략·요청·코드 스냅샷으로 프롬프트 구성·미리보기·복사 |
| `public/editor.html`, `editor.css` | 공통 사이드바·탭·프롬프트 액션·가져오기 모달 |
| `public/editor.js` | 편집 상태·검사·후보·undo·문서 전환 통합 |
| `public/ai-scripting.js`, `ai-connections.js` | 기존 API 기능 유지, 탭 전환과 초기화 시점 조정 |
| 테스트·문서 | 규약 일치·복사 대체·가져오기·기존 API 회귀 검증 |

규약은 서버에서 관리하고 같은 출처로 로드한다. 사용자 전략·요청·코드를 포함하는 실제 프롬프트는 브라우저에서 조합한다. 프롬프트 원문·사용자 코드·외부 AI 결과를 DB·로그·localStorage에 새로 보관하지 않는다. 임시 상태는 문서 전환·모달 취소·로그아웃 등 정리 계기를 정의한다.

코드 검사는 `/api/algorithms/validate`와 기존 파일 업로드/실행 검증을 재사용한다. 검사 임시 파일은 기존 수명과 정리 규칙을 따르고 최종 저장은 기존 코드 파일 저장소를 쓴다. 새 제품 차원의 코드 크기 제한은 도입하지 않는다. 샘플 검사 통과가 모든 맵·모든 턴의 성공을 보장하지는 않는다.

## 5. 상태·실패·경합 처리

- 탭 변경으로 전략·요청·코드·선택한 API 연결을 초기화하지 않는다.
- 프롬프트 탭 진입으로 모델 조회나 AI 생성이 자동 시작되지 않도록 초기화 시점을 분리한다.
- API 생성 중 탭을 바꿔도 취소/재요청하지 않는다. 진행 작업이 있음을 표시하고 해당 탭으로 돌아갈 수 있게 한다.
- API 후보와 붙여 넣은 후보의 출처·검사 대상·문서 기준을 구분한다. 다른 후보에 통과 결과를 재사용하거나 잘못된 API 요청을 폐기하지 않는다.
- 검사 취소·모달 닫기·문서 교체·로그아웃 뒤 늦은 결과는 폐기한다. 검사 중 입력 변경은 차단하거나 요청 순번으로 이전 검사를 무효화한다.
- 복사는 클릭 시점의 최신 입력으로 본문을 재구성한다. 이전 미리보기/복사 결과를 최신으로 오인하지 않도록 한다.
- Clipboard API가 제한되는 사내 HTTP·권한 거부 환경에서는 읽기 전용 본문을 선택해 직접 복사하도록 한다. 실제 복사 실패를 성공으로 표시하지 않는다.
- 규약 로딩 실패·세션 만료·검사 실패 시 기존 코드를 유지하고 이유·재시도 경로를 제공한다.
- 개인정보 운영 준비는 배포 전 마지막 필수 단계로 유지한다. 지금은 원문 추가 저장 없이 안내·삭제 정책을 연결할 경계를 지킨다.

## 6. 단계별 구현 순서

| 단계 | 작업 | 완료 기준 |
| --- | --- | --- |
| 1 완료 | 공통 규약·전략 입력 분리 | 기존 API 입력 호환, 복사용 출력 분리, 로그인 전용 규약 조회, 외부 호출 0회 |
| 2 완료 | 사이드바 UI·상태 분리 | 기본 프롬프트 탭, 공통 전략/요청 유지, API 진행/선택과 그립·접기·최대화 보존 |
| 3 완료 | 생성·미리보기·복사 | 신규/수정 본문, 코드 포함 스위치, 최신 입력 반영, 복사 실패·수동 대체 |
| 4 완료 | 코드 가져오기·검사·적용 | 단일 코드 처리, 실행 검사, 변경 후 재검사, 명시적 적용·undo·원본 유지 |
| 5 완료 | 통합 검증·리뷰·문서 | 실제 테스트 경기 종료·저장·재조회·수정/덮어쓰기와 회귀 검증. 외부 AI 응답/클립보드는 대체 |

각 단계 구현 후 관련 검증·리뷰를 하고 변경 내용과 남은 항목을 설명한다. 커밋은 사용자 요청에 따라 진행한다. 유료 API·외부 계정 준비를 구현의 선행 조건으로 요구하지 않는다.

## 7. 검증과 완료 기준

1. AI 비활성·키/연결 없음에서도 로그인 후 생성/복사/가져오기가 가능하다. 게스트·타인 데이터 접근은 차단한다.
2. 신규/수정·전략 순서 5/3/1·아이템 충돌·코드 포함/제외·문서/입력 변경을 실제 복사 본문에서 확인한다.
3. API와 복사용 프롬프트가 동일한 규약을 쓰고 필수 함수·제한·예제를 누락하지 않는다. API JSON 출력 지시는 복사용에 섞이지 않는다.
4. 프롬프트 탭 진입·복사·탭 전환만으로 외부 AI 요청이 발생하지 않는다. 복사 권한 거부 시 수동 복사가 가능하다.
5. 유효 코드·한글 미선언 이름·구문 오류·함수 누락·금지 API·무한 루프를 기존 검사로 구분한다. 여러 코드 블록을 임의 결합하지 않는다.
6. 검사 후 입력 변경·취소·세션 만료·늦은 결과·적용 전 문서 변경에서 기존 코드를 보존한다. 적용 전 자동 변경/저장이 없고 적용 후 undo·덮어쓰기/새 이름 저장이 가능하다.
7. 기존 API 연결·모델 기억·생성/수정·진행/취소·후보 복원과 템플릿 코드 생성·파일·저장·테스트 플레이를 회귀 검증한다.
8. 데스크톱·모바일에서 탭·키보드·복사·모달·그립·접기·최대화가 동작한다.

`npm run test:prompt-workflow`를 추가해 AI 비활성·키 없음 상태에서 전략 선택→실제 본문 복사→반환 코드 붙여 넣기→실제 실행 검사→명시적 적용→테스트 경기→계정 저장→페이지 재진입을 연결해 검증했다. 임시 대칭 4×4 맵에서 실제 QuickJS 알고리즘이 코인 4개를 모두 수집해 40점으로 정상 종료하고 패널티·예외·시간 초과가 없음을 확인한다. 검사/적용/경기만으로 계정 코드가 저장되지 않는 것도 확인한다.

저장된 코드의 수정 프롬프트에는 원문이 정확히 포함된다. 수정 코드 적용·undo/redo·원본 덮어쓰기·리비전 증가·모바일의 같은 계정 재로그인/재조회와 다른 계정 조회 차단까지 검증한다. 테스트 서버·계정·맵·업로드는 임시 영역에 두고 종료 시 정리한다. 외부 AI 요청 0회와 업로드 정리를 확인하며 사용자 서버나 OS 클립보드를 변경하지 않는다. 외부 AI 응답은 샘플 기반 코드, 클립보드는 메모리 대체물이다.

기존 단위/HTTP·프롬프트·가져오기·AI 연결·작업실 회귀 검사와 코드 리뷰를 수행했다. 범위 내에서 추가 수정이 필요한 높음/중간 결함은 발견하지 않았다. 사용 안내의 예전 로컬 템플릿 전용 설명은 현재 프롬프트/AI 연결/템플릿 흐름으로 갱신했다. 상세 명령·검사 항목·실사용 미검증 범위는 [검증 기록](prompt-assistant-verification.md)을 따른다. 실제 외부 AI 생성 품질·회사 네트워크·개인정보 운영 준비는 이번 로컬 검증으로 완료 처리하지 않는다.
