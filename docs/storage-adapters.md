# 계정 데이터 저장 어댑터

현재 한 컨테이너에서 운영할 수 있도록 계정·알고리즘·완료 경기 기록의 **메타데이터**는 파일 어댑터로 저장한다. 알고리즘 원문과 경기 당시 코드 사본은 별도 `.js` 파일로 보관한다. HTTP API와 경기 서버는 `AccountRepository`의 작업 단위 메서드만 사용한다. 기본 생성 위치는 `src/persistence/account-repository.js`이고 현재 메타데이터 구현은 `src/persistence/file-account-repository.js`, 코드 파일 구현은 `src/persistence/file-source-store.js`다. `ACCOUNT_STORE_ADAPTER`의 유효 값은 아직 `file`뿐이다. DB 어댑터는 구현되지 않았다.

메타데이터 파일은 `ACCOUNTS_FILE`로 지정하며 기본값은 `data/accounts/store.json`이다. 코드 파일 디렉터리는 `ALGORITHM_SOURCE_DIR`로 지정할 수 있으며 기본값은 메타데이터 파일 옆의 `sources/`다. 컨테이너 재생성 후에도 데이터를 유지하려면 **메타데이터 파일과 코드 파일 디렉터리를 함께** 영구 볼륨에 연결해야 한다. 기본 경로에서는 `data/accounts` 전체를 마운트하면 된다. 파일 저장은 단일 서버 프로세스에서 갱신을 직렬화하고 임시 파일로 교체한다. 여러 컨테이너가 같은 파일을 동시에 수정하는 구성은 지원하지 않는다. 백업·복원은 서버를 멈춘 상태에서 두 저장 영역을 함께 복사한다.

메타데이터에는 코드 원문 대신 서버가 발급한 `sourceKey`만 저장한다. 새 코드 파일을 기록한 다음 메타데이터 참조를 갱신하며, 기존 코드 갱신이 성공하면 이전 파일을 제거한다. 경기 기록의 코드 파일은 과거 경기 재대결을 위해 그대로 보존한다. 메타데이터 기록에 실패하면 새로 쓴 코드 파일을 정리한다. 기존 `store.json`에 `source` 문자열이 있으면 첫 접근 시 코드 파일로 옮긴 후 JSON을 교체한다. 파일과 메타데이터는 서로 다른 저장 영역이므로 갑작스러운 프로세스 종료 후 참조되지 않는 코드 파일이 남을 수 있다. 배포 전에는 백업·복구와 미참조 파일 정리 정책을 확정해야 한다.

## 어댑터 계약

| 영역 | 메서드 | 보장할 동작 |
| --- | --- | --- |
| 계정 | `login`, `user`, `listUsers`, `updateUser` | 첫 로그인 생성, 활성 상태와 역할 관리, 마지막 활성 관리자 보호 |
| 알고리즘 | `list`, `get`, `save` | 소유자별 조회·수정, 목록에서 코드·파일 참조 제외, 수정 버전 충돌 검사 |
| 경기 기록 | `history`, `historyEntry`, `recordMatch` | 종료 결과와 당시 코드 파일 참조 저장, 목록에서 코드·파일 참조 제외, 소유자별 코드 조회 |

API가 저장 파일의 전체 JSON이나 코드 파일 경로를 직접 읽거나 수정하지 않도록 한다. 어댑터는 위 메서드의 반환 형식과 오류 상태(특히 403·404·409)를 유지해야 한다. `save`, `updateUser`, `recordMatch`, 첫 로그인은 메타데이터 관점에서 원자적으로 완료되어야 한다. `adminEmail`은 초기 관리자 목업 로그인 선택지에 사용한다. 새 DB 어댑터는 메타데이터만 DB에 기록하고 같은 코드 파일 저장소를 사용하도록 이 계약을 구현한다. DB 이전 시에는 `sourceKey` 참조와 코드 파일을 함께 검증해야 한다.

제품 차원의 코드 파일 크기 제한은 없다. 다만 업로드와 실행 시 코드가 메모리에 적재되고 QuickJS 실행 인스턴스의 메모리 제한은 별개로 적용된다. 큰 코드의 실제 실행 가능 크기는 컨테이너 자원과 런타임에서 검증해야 한다.

현재 로그인 세션과 진행 중 경기는 서버 메모리에 있으며 이 어댑터에 포함하지 않는다. 서버 재시작 시 재로그인과 진행 중 경기 종료를 허용하는 단일 컨테이너 구성이다. 맵은 별도 `MapRepository`가 샘플·관리자 버전별 JSON 파일을 관리한다. 관리자 맵을 유지하려면 `data/maps`도 영구 볼륨에 연결한다. 맵까지 여러 컨테이너에서 편집할 단계에 DB 이전 여부를 결정한다.
