# JavaScript 코드 검사 확장 v2

2026-11-16. 공통 명세 커밋 `9a06e5e` 이후 J1의 검사 확장 구현. 저장 시 검사/상태 연결(J2)은 아직 구현하지 않았다.

## 구현 범위

- 실제 preflight에서 사용자 try/catch/finally를 실행 전에 AR011로 거부한다. 원본 offset·행/열과 `javascript-preflight-v2` profile을 진단에 포함한다. 문자열/주석의 키워드는 거부하지 않는다.
- AST와 eslint-scope의 lexical binding을 이용해 확인 가능한 함수/const 함수·동일 클래스 this 메서드 호출 그래프의 직접/상호 순환을 AR009로 거부한다. arrow의 lexical this와 별도 함수의 this를 구분하고, 큰 그래프는 iterative DFS로 처리한다.
- 기존 async/generator/import/class static 거부에도 원본 위치와 규칙 코드를 추가했다. timeout AR012, 잘못된 반환 AR013, 사용자 예외 AX002에는 측정 실행 시간·500ms 한도를 제공한다.
- 기본 2맵×4참가자×3호출(24회)에 목표 없음·도달 불가 목표·최대 크기 희소/밀집 코인 4개 시나리오×1참가자×3호출을 추가해 총 36회 검사한다. 시나리오별 새 객체, 시나리오 내 같은 객체/필드를 유지한다. 최초 실패 시 중단한다.
- 성공 결과에 profileVersion과 fixtureVersion `2.0.0`, 실패 context에 시나리오 이름을 포함한다. 기존 debug/취소·전체 검사 기한·현재 어댑터의 실제 중단 경로를 사용한다.
- 복사용 전체/후속 프롬프트의 규칙에도 사용자 try문·재귀 금지와 반복형 탐색 안내를 반영했다. 닷넷 제공용 generated game-content도 재생성했다. 직접 AI API 기능을 새로 활성화하지 않았다.

## 제한과 후속

이 구현은 공통 작성 규약 v1 전체의 준수 검사기가 아니다. 임의 alias·동적 computed call·bind/call/apply·반환 함수·상속/필드 함수·getter/setter·prototype 갱신의 호출 순환과 전체 상태 소유권은 아직 증명하지 않는다. 미해석 호출을 AP001로 일괄 거부하는 완전한 승인 API 프로필은 후속이다. 현재는 확인된 순환만 거부하고 나머지는 기존 제한/QuickJS 실행 예산을 적용한다. 이 차이를 숨기지 않고 전체 정책 status는 specified-not-activated로 유지한다.

실제 게임 내부 runtime은 중단/예외 방어 시험을 위해 try/루프를 실행할 수 있다. 새 규칙은 코드 검사 진입점에서 적용한다. 직접 게임 시작 API의 전체 사전 검사 강제·기존 코드 마이그레이션·저장 상태와의 연결은 J2다. 따라서 현재 새 검사 경로가 곧 모든 실행 진입점의 규약 강제 완료를 의미하지 않는다.

깊은 재귀가 정적으로 확인되는 경우 preflight는 이제 로드/실행 전에 거부한다. 4단계에서 발견한 낮은 수준 runtime의 깊은 재귀 오류 분류 자체를 수정한 것은 아니므로 우회 호출/내부 fixture의 장애 방어는 후속이다. 중단 예외를 받았다는 이유만으로 일반 VM 상태 안전성 전체를 보증하지 않는다.

무한 루프를 정적으로 증명해 차단하지 않는다. 실제 호출 timeout으로 실패시키며 유한 계산도 500ms 초과 시 같은 판정이다. 테스트 통과는 모든 입력/게임 턴의 성공 보장이 아니다. 저장 기능은 기존 방식이며 검사 실패 원문을 새로 차단하지 않는다.

## 검증

정적 try·순환 거부/원본 위치, 정상 스코프 구분, 최대 맵·목표 없음·도달 불가 fixture, 실제 preflight의 선실행 거부·큰 입력 전용 실패·실행 시간 진단을 검증한다. 기존 runtime/runner-contract/javascript-runner와 preflight 회귀를 포함한다. 생성 프롬프트/기본 skeleton의 실제 검사도 회귀 대상이다.

첫 전체 회귀에서 기존 제거 상태 AI 모듈의 실제 검사 완료 대기 테스트가 4초를 초과했다. 실제 검사 테스트 한 곳의 대기를 15초로 조정했으며 제품 500ms·검사 전체 기한을 늘리지 않았다. AI 테스트는 합성 응답이며 유료/외부 AI 호출은 하지 않는다.

최종 검증: 신규 검사/기존 실행기 집중 회귀 54건 통과, Node 전체 289건 통과(`--test-concurrency=2`), 변경 파일 형식·diff 검사 통과. 기본 동시 실행 전체 회귀 중 기존 계정 파일 잠금 테스트의 Windows EPERM이 1회 발생했고, 동시 수를 제한한 전체 재실행에서 통과했다. 해당 간헐 파일 잠금 문제를 이번 작업으로 수정했다고 판단하지 않는다.

실행 중인 사용자 서버는 재시작하지 않았다. Node 검사 프로세스/닷넷 콘텐츠가 변경됐으므로 운영 반영 시 정상 재시작이 필요하다.
