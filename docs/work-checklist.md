- [ ] 규칙: 경계·벽·패널티·모든 액션 시간·아이템 획득 및 교체·효과 차감.
- [ ] 동시성: 같은 코인·아이템·벽 처리 중복 방지, 종료 직전 응답.
- [ ] 랜덤점프: 사용자 호출 없음, 금지 위치 회피, 목적지 없음 연출.
- [ ] 맵: 대칭·중앙축·import/export 왕복·도달 가능성·테두리.
- [ ] 권한: 타인 코드 접근 차단, 게스트 기능 제한, 관리자 전용 API.
- [ ] 저장: 재로그인·다른 PC·경기 중 원본 수정·새 이름 저장.
- [ ] 통신: 순번 누락·재연결 상태 복원·지연 이벤트.
- [ ] UI: 업로드부터 결과까지, 편집·AI 생성부터 테스트·저장까지.
- [ ] 운영: 동시 경기 부하·메모리·종료 정리·백업 복원.

시간·난수에 의존하는 규칙 테스트에는 제어 가능한 시각·난수 입력을 사용한다. 실제 운영의 알고리즘 실행 시간이 매번 같거나 모든 경기가 결정적이라고 가정하지 않는다.

## 12. 배포와 운영 준비

- [ ] 실제 접근 경로·VPN·DNS·TLS·허용 포트 확인.
- [ ] 서버 OS·런타임·실행 계정·프로세스 실행 권한 구성.
- [ ] DB 연결·마이그레이션·영구 데이터 볼륨 설정.
- [ ] AI 중계 연결과 인증 확인.
- [ ] 비밀 설정 주입·로그 내 자격 증명 제외.
- [ ] 동시 경기·메모리·출력·업로드 크기 한도 적용.
- [ ] 서비스 상태·경기 수·실행 오류·시간 초과·자원 사용 관측.
- [ ] 서버 재시작·배포 중 경기 처리·임시 파일 정리.
- [ ] 백업·복원·배포 되돌리기 절차 검증.
- [ ] 사내 실제 브라우저에서 전체 흐름 확인.
- [ ] 배포 결과·운영 절차·남은 한계 기록.

## 13. 권장 진행 순서

1. 상세 규칙·API 초안과 실행 환경 검증을 먼저 진행한다.
2. 동시에 사내망·Azure·AI 중계의 가능한 경로를 조사한다.
3. 검증 결과로 기술을 고정하고 개발 환경을 만든다.
4. 파일 업로드 → JS 실행 → 기본 맵 경기 → 결과까지 먼저 완성한다.
5. 아이템·기믹·연출을 추가한다.
6. 계정·영구 저장·관리자 맵을 연결한다.
7. 에디터·디버그·테스트 플레이를 연결한다.
8. 실제 AI 연결과 코드 작성 흐름을 완성한다.
9. 통합·부하·사내 연결 검증 후 배포한다.

기술·배포 세부 사항을 모두 미리 확정할 필요는 없다. 다만 각 단계의 선행 조건을 충족하기 전에 해당 조건을 이미 해결한 것으로 가정하여 구현하지 않는다.
