# AI 연결 및 스크립팅 작업 계획

- 작성일: 2026-10-11
- 상태: 계획 수립. 실제 AI 연결은 아직 구현하지 않았다.
- 1단계 진행: 공통 계약·메타데이터 입력/공개 필드 검증·정책 설정 해석을 구현했다. 상세 계약·초기 한도·검증 범위는 [AI 공통 계약](ai-contracts.md)을 따른다. 저장소·HTTP·외부 호출은 후속 단계다.
- 2단계 진행: 연결 메타데이터 파일 어댑터·임시/암호화 자격 증명 저장·키 교체 조율·세션 정리를 구현했다. [저장 및 운영 경계](ai-storage.md)를 따른다. 제공자 확인·모델 조회·사용자 UI는 아직 연결하지 않았다.
- 기준: 회사·개인 유형을 강제 구분하지 않고 모든 연결에 제공자 선택 → 자격 증명 설정 → 연결 확인 → 모델 선택 흐름을 적용한다.
- 관련 문서: [작성 페이지 초기 계획](algorithm-authoring-plan.md), [현재 작업실](local-authoring.md), [저장 어댑터](storage-adapters.md), [알고리즘 규약](algorithm-api.md), [게임 규칙](game-rules.md).
- AI 연결·모델 선택·요청 관리에 대해서는 이 문서가 이전 계획보다 우선한다. 기존 게임·코드 저장·독립 턴 규칙은 유지한다.

## 1. 목표와 범위

로그인 사용자가 Claude, OpenAI, Gemini 연결을 등록하고 모델을 선택하여 자연어와 전략 템플릿으로 JavaScript 알고리즘을 생성·수정한다. 같은 제공자에 여러 연결을 등록할 수 있다. 업무용·개인용 등의 이름은 사용자가 지정하며 회사·개인 유형 필드는 만들지 않는다.

게임 로그인과 AI 제공자 인증은 별개다. Google 로그인은 게임 계정을 확인하고 AI 연결 자격 증명은 외부 API 사용 권한을 확인한다. 첫 구현은 제공자별 API 키 방식으로 시작한다. 제공자 웹 서비스 로그인이나 구독을 자동으로 API 자격 증명으로 취급하지 않는다. 별도 OAuth·조직 인증 방식은 공식 지원 여부를 확인한 뒤 확장한다.

이번 범위는 연결 등록·확인·교체·삭제, 모델 선택, 생성·수정·취소, 공통 실행 검사, 후보 표시·적용, 계정별 선택 기억이다. 게스트 AI 기능, 코드 변경 이력, 자동 저장, 무인 반복 생성·실행, 사용자 PC 연결 도구는 포함하지 않는다.

## 2. 현재 구현과 변경 경계

현재 `public/editor.js`는 `public/strategy-templates.js`로 로컬 코드를 생성한다. 자유 입력은 반영되지 않으며 외부 AI를 호출하지 않는다. 서버의 공통 실행 검사, 후보 코드 표시, 명시적 적용, undo, 요청 중 편집 변경 확인과 취소 후 늦은 결과 무시는 재사용한다.

생성 부분을 서버 AI 요청으로 교체하고 기존 로컬 템플릿 생성은 별도 기능으로 남긴다. 실제 AI와 혼동되지 않도록 이름과 상태를 구분한다. AI 연결이 없어도 직접 편집·파일 불러오기·코드 검사·테스트 플레이는 사용할 수 있다.

## 3. 사용자 화면과 흐름

### 작업실 사이드바

상단에 연결 드롭다운, 연결 관리 아이콘, 모델 드롭다운, 간단한 연결 상태를 배치한다. 아래에는 기존 전략 템플릿·자연어 요청·생성 및 수정 액션을 둔다. 생성은 신규 코드를 만들고 수정은 현재 편집 코드 사본을 함께 전달한다.

- 연결: 사용자 지정 이름과 제공자 표시. 끝에 연결 추가 액션 제공.
- 모델: 선택한 연결에서 조회되고 서버 정책으로 허용된 모델 표시. 모델 ID와 표시 이름을 구분한다.
- 안내: 설명이 검증된 모델만 속도·용도 설명을 제공한다. 모델 이름만 보고 비용·성능을 단정하지 않는다.
- 상태: 미등록, 확인 중, 사용 가능, 자격 증명 오류, 네트워크 오류, 모델 사용 불가를 구분한다.
- 선택 기억: 마지막 연결·모델을 계정별로 저장한다. 임시 연결이 사라지거나 모델이 중단되면 명시적으로 재선택한다.
- 연결이나 모델이 없으면 생성 액션을 비활성화하고 이유와 연결 관리 진입 액션을 표시한다.

### 연결 추가·관리 모달

1. Claude / OpenAI / Gemini 제공자를 선택한다.
2. 제공자별 API 키 발급 안내와 비밀번호형 입력란을 표시한다. 키 전달·보관 위치를 설명한다.
3. 사용자가 연결 이름과 자격 증명 보관 방식을 선택한다.
4. 연결 확인을 호출한다. 성공·실패 사유를 표시하고 실패 시 입력을 다시 수정할 수 있다.
5. 조회 가능한 모델 목록과 연결 상태를 표시한다. 모델 조회 가능과 실제 생성 가능은 구분한다.
6. 기본 모델을 선택하고 완료한다. 해당 연결을 사이드바에서 바로 선택한다.

관리 모달에서 이름 변경, 키 교체, 재확인, 모델 목록 새로고침, 기본 모델 변경, 연결 삭제를 제공한다. 저장된 키 원문을 재조회하는 API는 만들지 않는다. 키 교체는 새 키 확인에 실패하면 이전 연결을 유지하며 연결 수정은 리비전으로 충돌을 검사한다.

보관 방식의 초기 제안은 이번 로그인 동안 사용과 계정에 암호화 저장 두 가지다. 기본은 이번 로그인 동안 사용으로 둔다. 두 방식 모두 서버에 키가 전달된다. 계정에 저장할 때는 암호화 설정이 준비돼야 하며, 준비되지 않은 개발 환경에서는 해당 선택을 이유와 함께 비활성화한다.

## 4. 서버 구성과 네트워크

`작업실 → AI API → 요청 서비스 → 제공자 어댑터 → 외부 AI → 공통 실행 검사 → 후보 파일` 흐름을 사용한다. 코드 생성은 게임 경기 프로세스에서 실행하지 않는다.

| 구성 | 책임 |
| --- | --- |
| AI 연결 저장소 | 소유자, 이름, 제공자, 기본 모델, 리비전, 확인 상태와 시각 |
| 자격 증명 저장소 | 임시 키 수명, 저장 키 암복호화, 교체·삭제, 외부 응답에서 키 제거 |
| 제공자 어댑터 | 연결 확인, 모델 조회, 생성·수정, 사용량 해석, 취소 |
| 규약 입력 구성기 | 게임 규칙·API·코드 제한·템플릿 순서·자연어·수정 코드 조합 |
| 요청 서비스 | 소유권·세션, 동시 요청 제한, 상태·SSE, 취소·만료·파일 정리 |
| 공통 실행 검사 | 기존 구문·금지 기능·필수 함수·QuickJS 실행 검사 재사용 |

어댑터 계약은 `checkConnection`, `listModels`, `generate`로 구성한다. 제공자별 요청·응답 형식 차이는 어댑터 내부에서 처리한다. 구체 SDK·API·지원 모델은 각 어댑터 구현 시 공식 문서와 현재 Node 환경에서 확인한다. 한 모델 조회 실패가 다른 제공자의 연결 목록을 막지 않도록 한다.

로컬에서는 서버 직접 호출을 먼저 검증한다. 배포 시 승인된 중계를 사용할 수 있도록 호출 경로는 서버 설정으로 분리한다. 사용자가 임의 API 주소를 입력하도록 하지 않는다. 개인 키도 서버의 외부 접속 제한이나 코드 외부 전송 정책을 우회하지 못한다. 서버가 중계에도 접근할 수 없으면 실제 AI 사용은 불가능하며 템플릿 생성·직접 편집을 유지한다.

회사·개인 분류 대신 서버 정책으로 허용 제공자·모델·전송 경로·요청 한도를 적용한다. 모델이나 연결 실패 시 다른 연결·제공자로 자동 전환하지 않는다.

## 5. 데이터와 자격 증명

새 AI 기능은 [개인정보 운영 준비 계획](privacy-operations-plan.md)의 개발 설계 조건을 따른다. 연결·키·요청·후보를 계정 및 필요한 세션으로 추적하고 보유 기간·전송 정책을 구현 코드와 분리한다. 저장소 계약에 소유자별 삭제·진행 요청 취소 경계를 준비하며 삭제 이후 늦은 결과의 재저장을 막는다. 서비스 계정 개인정보·OAuth 신원은 AI 입력에서 제외한다. 개인정보 운영 정책·최종 안내·계정 전체 삭제 조율은 배포 전 마지막 필수 단계에서 구현한다.

연결 메타데이터는 `id`, `ownerId`, `name`, `provider`, `credentialMode`, `credentialRef`, `defaultModelId`, `revision`, `createdAt`, `updatedAt`, 확인 결과·시각으로 구성한다. 목록 API는 비밀 참조·키 원문을 제외한다. 키가 달라지면 이전 확인 상태와 모델 캐시를 무효화한다.

메타데이터는 별도 `AiConnectionRepository` 계약과 파일 어댑터로 구현하고 이후 DB로 교체할 수 있게 한다. 기존 파일 잠금·원자적 교체·리비전 충돌 원칙을 재사용한다. 마지막 선택은 사용자 설정 메타데이터로 보관한다.

자격 증명은 `CredentialStore`로 분리한다. 영구 키는 인증된 암호화 방식으로 보관하며 암호화 키는 저장 데이터와 별도의 로컬 비밀 설정 또는 배포 비밀 주입으로 제공한다. 암호화 자료에는 형식 버전과 키 식별자를 기록한다. 키 교체·백업 복원 절차를 문서화하며 암호화 키가 없거나 다른 경우 자동으로 새 키를 만들어 기존 데이터를 덮어쓰지 않는다. 키·비밀 설정·실제 사용자 데이터는 Git과 로그에서 제외한다.

임시 키는 사용자와 로그인 세션에 연결해 서버 메모리에만 둔다. 해당 세션 로그아웃·만료·서버 재시작 시 제거하며 다른 로그인 세션으로 공유하지 않는다. 이용 중지는 해당 사용자의 모든 임시 키와 AI 요청을 무효화한다. 영구 키는 일반 로그아웃으로 삭제하지 않으며 계정 소유권 검사 후 새 로그인에서 사용할 수 있다.

입력 코드 사본과 생성 후보는 별도 임시 파일로 보관한다. DB·계정 JSON에 코드 원문이나 AI 응답 전체를 저장하지 않는다. 요청 메타데이터에는 상태·사용량·검사 결과·내부 파일 참조만 보관하며 최초 버전은 서버 메모리에 둔다. 서버 재시작 시 진행 요청 복구는 제공하지 않는다. 후보 파일 조회는 소유자와 요청 수명을 검사한다.

## 6. AI 입력과 코드 검사

서버가 관리하는 공통 규약에 필수 클래스·함수, 맵·아이템 표현, 방향 반환값, 동기 함수 및 사용 제한, 호출별 500ms, 메모리 제한과 예제를 포함한다. AI 입력의 규약과 실제 런타임 정책을 대조하는 검사를 둔다.

템플릿은 최대 3개, 순서별 가중치 5·3·1을 유지한다. 생성 버튼은 템플릿 또는 자연어 요청 중 하나 이상 있으면 사용할 수 있게 한다. 순위는 AI에 전략 지침으로 전달하며 생성 코드가 실제 점수 평가에서 이를 적용했는지 사용자가 검사·테스트할 수 있게 설명을 표시한다. 자연어 요청과 템플릿이 충돌하면 임의로 한쪽을 무시하지 않고 충돌을 표시하여 수정하도록 한다.

수정 요청에는 요청 시작 시점의 코드 파일 사본을 사용한다. 디버그 출력은 사용자가 선택한 내용만 포함한다. 코드·요청문은 외부 전송 대상임을 연결 등록과 생성 화면에서 설명한다.

응답은 코드·전략 설명·사용량·완료 사유로 정규화한다. 제공자 응답의 잘림·거부·형식 오류를 성공으로 처리하지 않는다. 구조화된 응답 지원 여부는 어댑터에서 처리하고 추출된 코드는 반드시 기존 실행 검사에 통과시킨다. 검사 실패 코드도 현재 편집기를 덮어쓰지 않고 실패 후보와 진단을 표시한다. 초기에는 사용자가 진단을 포함해 다시 수정 요청하며 자동 반복 수정은 하지 않는다.

알고리즘 파일의 제품 차원 크기 제한은 추가하지 않는다. 다만 모델별 입력·출력 한도는 별도로 검사한다. 입력 초과 시 코드를 조용히 잘라 보내지 않고 해당 모델로 처리할 수 없음을 안내한다. 초기에는 전체 코드 생성·수정을 제공하며 큰 코드의 부분 수정은 후속 범위다. 모델 한도를 확인할 수 없으면 서버 정책 상한과 제공자 오류를 명시적으로 처리한다.

## 7. API와 요청 수명

| API 초안 | 동작 |
| --- | --- |
| `GET /api/ai/providers` | 서버에서 허용한 제공자·기능 목록 |
| `GET /api/ai/connections` | 현재 사용자·세션에서 이용 가능한 연결 목록 |
| `POST /api/ai/connections` | 자격 증명·보관 방식·이름으로 연결 등록 |
| `PATCH /api/ai/connections/:id` | 리비전 확인 후 이름·기본 모델·키 교체 |
| `DELETE /api/ai/connections/:id` | 연결·자격 증명·관련 선택 제거, 해당 진행 요청 취소 |
| `POST /api/ai/connections/:id/check` | 자격 증명 재확인 |
| `GET /api/ai/connections/:id/models` | 캐시된 모델 목록·조회 시각·상태 |
| `POST /api/ai/connections/:id/models/refresh` | 제공자 모델 목록 갱신 |
| `PUT /api/ai/preferences` | 마지막 연결·모델 선택 기록 |
| `POST /api/ai/requests` | 연결·모델·생성/수정 의도로 요청 예약 |
| `PUT /api/ai/requests/:id/source` | 수정용 편집 코드 사본을 파일로 업로드 |
| `POST /api/ai/requests/:id/start` | 입력 준비 확인 후 생성 시작 |
| `GET /api/ai/requests/:id/events` | 상태·진단·사용량을 SSE로 전달 |
| `GET /api/ai/requests/:id/source` | 완성된 후보 코드 파일 조회 |
| `DELETE /api/ai/requests/:id` | 요청 취소·후보 폐기 |

코드 업로드는 기존 파일 스트리밍 경로를 재사용하고 작은 JSON 요청과 분리한다. 초기 상태는 `prepared → queued → generating → validating → completed/validation_failed`이며 실패·취소·만료는 별도 종료 상태다. 입력 준비 중 요청에도 짧은 만료와 슬롯 제한을 적용한다.

동시 요청 수·대기 수·시간 제한·후보 보관 수명은 서버 설정으로 둔다. 연결 확인·모델 새로고침도 외부 호출이므로 별도 요청 제한과 시간 제한을 적용한다. 취소·만료는 제공자 요청과 실행 검사를 중단하도록 전달하고 늦은 결과를 폐기한다. 취소를 요청했더라도 실제 미완료 작업은 끝날 때까지 실행 슬롯에 포함한다. 취소가 이미 발생한 제공자 비용을 되돌린다고 안내하지 않는다.

로그아웃은 현재 로그인 세션의 AI 요청을 취소한다. 이용 중지는 계정 전체 요청을 취소한다. 연결 삭제·키 교체는 해당 연결의 진행 요청을 취소하고 새 요청은 새 리비전을 사용한다. 완료·실패·취소 시 임시 파일과 비밀 참조를 정리하며 완료 후보는 설정한 수명 또는 사용자의 폐기까지 보관한다. 이탈 후 재접속은 같은 유효 세션과 보관 수명 안에서만 요청 상태를 복원한다.

SSE 순번과 상태 조회에 필요한 초기 스냅샷을 제공한다. 재연결·상태 조회 때도 계정·세션·요청 소유권을 검사한다. 모델 목록·연결 확인·생성의 지연 응답은 요청 순번 및 연결 리비전으로 검사하여 새 선택이나 상태를 덮어쓰지 못하게 한다.

## 8. 구현 순서와 완료 기준

| 순서 | 작업 | 완료 기준 |
| --- | --- | --- |
| 1 | 연결·자격 증명·제공자·모델·요청 계약과 설정 정의 | 회사·개인 유형 없이 소유권·보관·호출 경로·오류·수명을 문서화 |
| 2 | 연결 메타데이터 파일 어댑터와 임시/암호화 자격 증명 저장소 | 소유권·리비전·키 교체 실패 보존·로그아웃 정리·재시작 복원 검사 |
| 3 | 제공자별 연결 확인과 모델 목록 어댑터 | 내부 어댑터·카탈로그 구현. [상세 범위](ai-providers.md); 실제 키 호출은 후속 검증 |
| 4 | 연결 관리 모달·사이드바 모델 선택·선택 기억 | HTTP·브라우저 흐름 구현. [사용 흐름·설정](ai-connections-ui.md); 실제 호출은 후속 검증 |
| 5 | 공통 규약 입력과 생성 요청 서비스 | 파일 입력, 큐·SSE·취소·슬롯·파일 정리, 실패 후 기존 코드 보존 검사 |
| 6 | 첫 제공자의 실제 생성·수정과 공통 실행 검사 연결 | 실제 API로 생성 → 검사 → 후보 적용 → 테스트 → 저장 성공 |
| 7 | 나머지 두 제공자의 생성·수정 어댑터 | 공통 UI에서 제공자·모델을 바꾸어 같은 흐름 성공 |
| 8 | 통합·경합·보안·배포 문서 검증 | 아래 필수 검사와 실제 연결 범위·남은 운영 조건 기록 |

생성·수정 검증의 첫 제공자는 실제 사용할 자격 증명이 준비된 제공자로 정한다. 제공자 없는 개발 환경에서는 대체 응답으로 UI·경합 검사를 진행할 수 있지만 실제 AI 완료로 표시하지 않는다. 외부 API를 사용하는 연결 확인·생성 검증은 사용자가 등록한 연결과 명시적 액션으로 수행한다. 키를 채팅에 요청하지 않는다.

## 9. 필수 검증

- 다른 사용자·게스트의 연결·키·모델·요청·후보 조회 및 수정 차단.
- API·SSE·오류·로그에 키 원문이나 내부 비밀 참조가 포함되지 않음.
- 임시 키의 세션 격리·로그아웃·만료·이용 중지·재시작 정리.
- 저장 키의 재로그인·재시작 복원, 잘못된 암호화 키·키 누락 시 데이터 보존.
- 키 교체·삭제·동시 수정·확인 중 새 연결 선택의 경합 처리.
- 모델 페이지네이션·중단·접근 거부·캐시 만료·갱신 순서 역전 처리.
- 코드 업로드 실패·모델 입력 초과·응답 잘림·검사 실패에서 편집 코드 보존.
- 생성 중 편집·문서 변경·적용 undo·취소 뒤 늦은 응답·세션 만료 처리.
- 실제 미완료 요청 슬롯 유지, 여러 계정의 공정한 실행, 대기·실행 시간 제한.
- 검사 프로세스·임시 파일·SSE 정리와 서버 재시작 후 남은 파일 회수.
- 기존 템플릿·직접 편집·저장·게임 플레이·OAuth·관리자 브라우저 회귀 검사.
- 각 제공자의 실제 API 생성·수정 검증과 네트워크 접근 불가 안내.

## 10. 실제 연결 전 필요한 운영 정보

개발 계약과 UI는 먼저 구현할 수 있다. 실제 호출 전에는 제공자별 API 자격 증명, 사용할 모델, 외부 코드 전송 허용 범위, 호출 경로, 이용량 한도를 정한다. 영구 키 저장을 사용하려면 암호화 키와 백업·복구 설정이 필요하다. 가격·모델 가용성·API 지원 범위는 연결 시 공식 자료로 확인하고 확정되지 않은 값을 UI에 고정하지 않는다.

첫 배포는 단일 서버/컨테이너, 메타데이터 파일 어댑터, 코드 파일, 메모리 요청·세션 구조를 유지한다. DB 전환은 메타데이터 저장소 교체로 별도 수행하며 실제 AI 연결 구현의 선행 조건으로 삼지 않는다.
