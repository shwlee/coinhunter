# C++ 제한 규약 실행기 작업 계획

- 상태: 계획 작성, 구현 미착수. [공통 규약·검사/저장·복구 계획](restricted-language-runners-plan.md)을 따른다.
- 2026-11-16 리뷰 반영: guest 외 host 강제 자원 한도, 시간/예외 해제 실패 판정, 실패 코드 보관과 실행 허가 분리. JS J 작업의 공통 경로를 재사용한다.
- 후보: Clang 분석·변환 + WASI/Wasmtime. 정규 예외 해제로 중단하는 경로를 우선 시험하고, Wasm epoch/trap은 최후 제한 장치로 분리한다.
- 기존 결과: raw trap 시 스택 문제와 RAII 자원 누적 확인. trap 뒤 스택 포인터 복원만으로 일반적인 재사용 안전성을 인정하지 않는다.

## X1. 구문·참조·컴파일 규약

1. 단일 사용자 소스, 승인된 표준 헤더와 서버 지정 compiler/linker 옵션만 허용한다. 외부 헤더/라이브러리·사용자 추가 파일·절대 경로 include를 거부한다.
2. 사용자 try/catch(함수 try 블록 포함), goto/비표준 점프, 직접/상호 재귀, 비동기/스레드/대기/소켓·시스템 호출을 거부한다. setjmp/longjmp·inline assembly 등 예외 해제 우회도 검사한다.
3. 사용자 전역/정적 가변 상태와 static 지역 상태를 제한하고 Player 인스턴스 필드에 상태를 둔다. host가 보유하는 인스턴스 참조와 구분한다.
4. 매크로 확장·템플릿 인스턴스·연산자/변환 함수·함수 포인터/virtual·콜백을 포함해 호출 경로를 검사한다. 분석 불가 경로의 지원 범위를 명시한다.
5. noexcept·소멸자·정리 코드, 컬렉션의 비교 함수·allocator 등 암묵적 호출에 중단 예외가 들어갈 때의 결과를 검증한다. 검사 위치를 단순 텍스트 치환으로 만들지 않는다.

산출물: 표준 헤더/API allowlist, Clang 의미 분석·원본 진단, 부정 fixture. 컴파일러의 파일/네트워크 접근과 CPU·메모리·템플릿 확장·출력/임시 디스크 한도는 별도 준비 샌드박스로 적용한다.

## X2. 정상 예외 해제 기반 자동 중단

1. 허용된 루프/함수 경로에 예산 확인을 삽입한다. Wasm 내부의 읽기 전용 호스트 기한 조회/취소 플래그 등 후보를 비교하고 blocking host import는 허용하지 않는다.
2. 기한 초과 시 host 소유 호출별 마감 상태를 고정한 뒤 생성된 중단 예외를 발생시킨다. 생성 래퍼/부모는 마감 상태·종료 기록·정리 여부로 판정하고 예외 타입만으로 timeout 처리하지 않는다. 사용자 try/catch 금지와 표준 라이브러리 내부 예외 처리 검증을 구분한다. Wasm guest가 host의 기한 상태를 수정할 수 없게 한다.
3. 정규 C++ 예외 해제로 소멸자가 실행되는지 확인한다. 1차 실험의 1MiB RAII·6회 중단 사례를 재현하고 live allocation·선형 메모리·정상 재호출을 비교한다. allocator의 확보 메모리와 실제 살아 있는 할당을 구분한다.
4. noexcept/소멸자·표준 라이브러리 내부 등 예외를 안전하게 던질 수 없는 위치를 구분한다. 안전 지점 간 실행 시간이 너무 길면 추가 제한/별도 API 후보를 보고한다.
5. 정리 유예 내 종료하지 못하면 epoch trap/프로세스 종료 경로로 이동한다. trap 발생 인스턴스는 정상 예외 해제 성공과 구분해 폐기/교체 대상으로 시험한다.

필수 부정 시험: noexcept 함수에서 중단 예외 발생, 예외 해제 중 소멸자의 추가 예외/terminate, 표준 콜백 경로의 예외 변형, 강제 epoch와 정상 해제 경합, 마감 뒤 정상 방향 반환. terminate/trap/정리 미완료는 실행기 장애 및 인스턴스 폐기로 분류한다. 앞서 확정된 턴 timeout은 유지하되 정상 재사용으로 표시하지 않는다. 초기 프로필은 안전한 예외 전파를 입증하지 못한 경로를 거부한다.

통과 기준: 정상 예외 timeout 후 같은 Player/필드 유지·재호출·소멸자 정리, 반복 중단에도 자원/힙 상태 안정성. 예외를 던지는 것만으로 보장됐다고 하지 않는다.

## X3. 메모리·호스트·복구 정책

선형 메모리/스택/table 한도, 허용 import, 파일/환경/네트워크 비상속, 컴파일된 std::thread의 실제 런타임 거부와 오류 분류를 검증한다. 호스트 RSS와 선형 메모리 한도를 구분한다.

공통 R0 OS 강제 한도를 Wasm 모듈 로드/JIT·초기화 전에 적용한다. Wasmtime/Python 또는 선정 host 런타임의 메모리·native 스택/할당·IPC를 포함하며 컴파일/검사/예비 호스트와 전체 예약을 조율한다. guest 한도만으로 서버 보호가 완료됐다고 하지 않는다. 공통 R2 시간 계약의 시작/완료 기록·시계 매핑·마감 상태를 host에 두고 부모 감시가 독립 집행한다.

사전 할당 중심 프로필을 대안으로 측정하되 턴 중 동적 할당 금지를 이미 합의된 규칙으로 도입하지 않는다. 영속/임시 allocator 후보는 임시 포인터가 필드에 남는 문제와 중단 중 구조 갱신까지 검증한다.

준비된 Wasm 재사용·모듈 JIT·인스턴스 초기화 비용과 예비 호스트 비용을 분리 측정한다. 강제 교체 시 raw 메모리를 복사하면 C++ 포인터/allocator/호스트 참조가 유효하다고 가정하지 않는다. 상태 복원 정책은 공통 R2에서 결정한다.

## X4. 검사·저장 연결

WASI 산출물 검사와 imports/exports·메모리 선언·compiler/runtime/변환 버전 검증을 준비 단계에 포함한다. 업로드된 임의 Wasm 대신 서버에서 승인 옵션으로 준비한 산출물만 사용한다.

동일 실행 프로필로 공통 preflight의 맵/아이템/연속 호출을 실행하고 500ms 초과·예외·규약 위반 시 검사 실패·실행 불허를 표시한다. 실패 코드도 파일로 보관하며 JS J 작업의 저장/검사 상태·hash/revision/profile 계약을 재사용한다. 컴파일 오류를 사용자 원본 위치로 매핑하고 생성 래퍼/시스템 경로를 숨긴다. 소스 파일 보관과 metadata 참조를 분리한다.

## X5. 완료 판정

- 승인 프로필에서 BFS/반복형 DFS·기본 컬렉션·Player 필드 유지.
- try/catch·재귀·goto·매크로/템플릿/간접 호출 우회와 외부 참조 거부.
- 정규 timeout 후 소멸자·메모리 안정성, 강제 trap의 폐기/교체, 늦은 응답 미적용 확인.
- 컴파일 격리·악성 입력/부하·메모리 고갈·중단/종료 경합과 검사/저장 정합성 통과.
- 실제 host OS 한도·전체 admission·프로세스 트리 회수와 noexcept/이중 예외/terminate·마감 상태 및 시간 통보 경합 검증.
- 일반 네이티브 C++ 전체 지원으로 표시하지 않고 실제 허용한 WASI 프로필과 한계를 명시.

참고: [WASI C++ 예외 옵션](https://github.com/WebAssembly/wasi-sdk/blob/main/CppExceptions.md), [Wasmtime interruption](https://docs.wasmtime.dev/examples-interrupting-wasm.html). 정규 예외 해제와 강제 Wasm trap을 같은 결과로 처리하지 않는다.
