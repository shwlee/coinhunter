# 관리자 맵 관리 작업 계획

- 작성일: 2026-10-06
- 상태: 1~6단계 구현 완료. 별도 관리 목록·게시·노출 API·편집기 연결을 제공한다. 자동 테스트 70개 및 관리·편집 브라우저 검증 통과.
- 관련 문서: [관리자 전체 계획](admin-page-plan.md), [맵 편집기](map-editor-plan.md), [파일 기반 맵 관리](map-files.md).

## 1. 화면 구성과 범위

맵 관리는 `/admin/maps`, 제작·편집은 기존 `/admin/maps/editor`에 배치한다. 관리자 페이지의 게임맵 메뉴는 관리 목록으로 연결한다. 목록의 **새 맵 만들기** 또는 각 맵의 **편집**으로 제작 화면에 진입한다. 편집 화면에는 **맵 관리로 돌아가기**와 현재 맵의 게시 상태를 제공한다. 저장 후에는 편집 화면에 머무른다.

이번 단계는 목록·검색·상태 필터, 작은 미리보기, 게시·게시 버전 갱신·숨기기·다시 노출, 특정 맵 편집 연결이다. 게임 시간·아이템·기믹 설정, 표시 순서 변경, 복사·삭제는 후속 단계다. 맵별 게임 옵션 화면을 구현할 때 목록의 해당 맵에서 바로 열 수 있도록 연결한다. 현재 단계에서 동작하지 않는 옵션 버튼을 먼저 노출하지 않는다.

관리자 제작 맵은 모든 관리자가 공동 관리한다. 기존 저장소의 기본 샘플은 별도 표시하되 이번 단계에서는 읽기 전용이다. 샘플 원본 수정·노출 변경은 제공하지 않으며, 향후 샘플 복사 및 운영 데이터의 노출 설정으로 확장한다. 읽기 전용인 이유를 표시하고 일반 관리 맵의 조작 버튼과 혼동하지 않게 한다.

## 2. 관리 목록 UI

- 목록 상단: **새 맵 만들기**, 이름 검색, 상태 필터, 새로고침.
- 각 항목: 작은 게임판 미리보기, 이름·크기, 코인 수·총점·벽 수, 최신 저장 버전·게시 버전, 노출 상태.
- 미리보기와 통계는 최신 초안을 기준으로 한다. 초안과 게시 버전이 다르면 **수정본 미게시** 표시를 함께 붙여 서비스 중인 맵과 같다고 오해하지 않게 한다. 샘플은 게시 원본 기준이다.
- 필터: 전체 / 미게시 / 노출 중 / 비노출 / 수정본 미게시. 수정본 미게시 상태는 노출 중·비노출 모두와 겹칠 수 있다.
- 항목의 주 동작은 편집이며 게시 상태에 맞는 관리 버튼만 제공한다. 게시 갱신 등 중요한 동작은 맵 이름·대상 버전·노출 결과를 확인하고 수행한다.
- 목록이 비어 있을 때 새 맵 만들기로 안내하고, 검색 결과 없음과 조회 실패를 구분한다. 처리 중 중복 클릭을 막고 성공·실패를 표시한다.
- 작은 화면에서는 항목을 세로로 배치한다. 미리보기는 정적인 바닥·벽·코인만 표시하고 캐릭터나 애니메이션은 포함하지 않는다.

## 3. 상태와 동작

초안 버전, 게시 버전, 노출 여부를 분리한다. 편집 저장은 게시·노출 상태를 변경하지 않는다.

| 상태 | 표시 | 제공할 관리 동작 |
| --- | --- | --- |
| 게시 버전 없음 | 미게시 | 게시 |
| 게시 버전 있음, enabled=true | 노출 중 | 숨기기 |
| 게시 버전 있음, enabled=false | 비노출 | 다시 노출 |
| 최신 초안과 게시 버전이 다름 | 위 상태 + 수정본 미게시 | 게시 버전 갱신 |

- **첫 게시:** 최신 저장 초안을 검사하고 게시 버전으로 확정하며 노출한다. 저장되지 않은 편집 내용은 대상이 아니다.
- **게시 버전 갱신:** 최신 저장 초안을 새 게시 버전으로 지정한다. 기존 노출 여부는 유지한다. 숨겨 둔 맵을 갱신하는 것만으로 자동 노출하지 않는다.
- **숨기기:** 사용자 선택 목록에서 제외한다. 초안·게시 원본·버전 파일은 보존한다.
- **다시 노출:** 기존 게시 버전을 다시 노출한다. 최신 수정본을 자동 게시하지 않는다. 수정본이 있으면 기존 게시 버전을 노출한다는 사실을 확인 화면에 표시한다.
- 미게시 맵에는 숨기기·다시 노출을 제공하지 않는다. 이미 노출 중인 버전과 같은 버전을 다시 게시하는 버튼도 제공하지 않는다.

게시 검사는 기존 규칙을 유지한다. 크기·타일 값·네 모서리 시작점·설정값, 상하좌우 대칭, 코인 존재, 모든 이동 가능 공간의 연결성을 서버에서 검사한다. 실패하면 이유를 표시하며 기존 게시 버전과 노출 상태를 유지한다. 초안은 그대로 편집할 수 있다.

## 4. 편집 화면 연결

- 목록의 편집 버튼은 `/admin/maps/editor?mapId=<id>`로 이동하고 해당 맵의 최신 초안을 자동으로 불러온다. 기존 불러오기 모달도 유지한다.
- 잘못된 ID·없는 맵·조회 실패는 오류와 관리 목록으로 돌아갈 경로를 제공한다. 오류를 빈 새 맵으로 조용히 대체하지 않는다.
- 편집 헤더에 이름·초안 버전·게시 버전·노출 상태를 표시한다. 저장 후 게시 버전과 다르면 수정본 미게시로 갱신한다.
- 맵 관리로 돌아가기, 다른 맵 불러오기, 화면 이탈의 미저장 확인은 기존 실제 변경 감지 규칙을 재사용한다.
- 관리 목록은 진입 시 최신 상태를 조회한다. 게시·노출 조작 성공 후에도 자동 갱신한다. 다른 관리자의 변경은 새로고침으로 확인하며, 오래된 상태로 쓰는 요청은 서버에서 충돌을 거부한다.

## 5. 저장소와 API 변경

기존 `MapRepository`와 `data/maps` 파일 구조를 유지한다. 게시·노출 변경은 등록 정보만 원자적으로 갱신하고 맵 원본은 덮어쓰지 않는다. 서버 재시작 없이 이후 목록 조회·경기 생성에 반영한다. 이미 시작된 경기는 시작 시 복사한 맵·설정을 유지한다.

기존 `publish`는 언제나 enabled=true로 바꾸므로, 첫 게시와 재게시를 구분해 재게시 시 기존 노출 여부를 보존하도록 수정한다. CLI도 같은 규칙을 사용하고 문서를 갱신한다.

구현 API는 다음과 같다. 세부 요청·응답은 [API 문서](data-and-api.md)에 기록한다.

| API | 역할 |
| --- | --- |
| `GET /api/admin/maps` | 기존 초안 목록 계약을 유지하고 통계·상태 정보를 추가. 샘플은 명시적인 조회 옵션으로 포함하여 기존 편집 모달과 구분 |
| `GET /api/admin/maps/:id/preview` | 지정 저장 버전의 미리보기 데이터. 샘플도 읽기 가능 |
| `POST /api/admin/maps/:id/publish` | 조회한 최신 초안 버전을 검증하고 첫 게시 또는 게시 갱신 |
| `PUT /api/admin/maps/:id/visibility` | 게시 버전의 노출·비노출 변경 |

관리 페이지·API 모두 활성 관리자만 접근하도록 서버에서 검사한다. 요청에는 목록에서 읽은 초안 버전·게시 버전·노출 여부를 이전 상태로 전달한다. 저장소의 직렬화된 변경 구간 안에서 이 값들을 비교하여 상태가 달라졌으면 409를 반환한다. 단순히 API에서 확인한 뒤 별도로 쓰는 방식은 사용하지 않는다. 충돌 후 목록을 갱신하되 요청을 자동 재시도하지 않는다.

미리보기는 목록 조회에 모든 맵 원문을 한꺼번에 싣지 않고 필요한 항목만 불러온다. 미리보기 데이터에는 버전 식별자를 포함해 다른 버전의 통계·상태와 혼합하지 않는다. 샘플 파일은 읽기 전용으로 유지한다.

## 6. 구현 순서

1. **상태·저장소 규칙:** 게시 갱신 시 노출 유지, 이전 상태 비교, 오류 구분을 저장소에서 구현하고 테스트한다. 기존 CLI·초안 저장 계약을 보존한다.
2. **관리 API:** 목록 통계·샘플 구분·미리보기, 게시·노출 API와 관리자 권한 검사를 연결한다.
3. **관리 목록 화면:** `/admin/maps` 및 관리자 메뉴 연결, 미리보기·검색·필터·빈 목록·오류·새로고침을 구현한다.
4. **게시·노출 UI:** 상태별 버튼, 확인 화면, 처리 중 표시, 검사 실패 안내, 성공·충돌 후 자동 목록 갱신을 구현한다.
5. **편집기 연결:** 목록에서 특정 맵 자동 불러오기, 관리로 돌아가기, 헤더 상태 및 저장 후 수정본 미게시 표시를 연결한다.
6. **통합 검증·문서:** 새 맵 생성 → 저장 → 첫 게시 → 사용자 선택 → 초안 수정 → 게시 갱신 → 숨기기 → 다시 노출을 브라우저에서 검증한다. 재시작 복원과 진행 중 경기 독립성을 확인하고 관련 문서를 갱신한다.

## 7. 완료 기준

- 일반 사용자·게스트는 관리 페이지와 관리 API에 접근할 수 없다.
- 첫 게시 전에는 사용자 목록에 없고, 게시 후에는 나타나며 숨기기·다시 노출이 정확하게 반영된다.
- 수정본 저장만으로 게시 버전이 바뀌지 않는다. 게시 갱신은 기존 노출 여부를 유지하고 다시 노출은 기존 게시 버전만 사용한다.
- 잘못된 맵의 게시 및 오래된 관리 상태로 수행한 변경은 거부되며 기존 데이터는 보존된다.
- 편집 진입 시 선택한 맵을 바로 불러오고, 저장 및 목록 복귀에서 미저장 변경 안내가 정확하게 동작한다.
- 샘플은 읽기 전용으로 구분되고 기존 편집기의 저장·불러오기 모달은 정상 동작한다.
- 저장·게시·노출 상태가 재시작 후 복원되고 이미 시작된 경기에는 영향을 주지 않는다.
- 자동 테스트와 데스크톱·모바일 브라우저에서 주요 흐름을 검증한다.
