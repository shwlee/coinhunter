# AI 연결 관리·모델 선택 — 4단계

## 사용자 흐름

알고리즘 작업실 AI 사이드바 위쪽에 연결 선택·관리 아이콘·모델 선택·목록 새로고침을 배치했다. 관리 아이콘을 누르면 모달에서 새 연결 또는 기존 연결을 편집한다.

1. Claude·OpenAI·Gemini 제공자를 선택하고 다음으로 이동한다. 새 연결은 `제공자 → 키 발급 → 연결 확인 → 모델 선택`의 4단계로 안내한다.
2. 선택한 제공자만의 준비 사항·번호별 발급 절차·키 발급 화면 버튼·결제/한도 링크·막혔을 때의 안내를 읽는다. `키를 준비했어요`로 다음 화면에 진입한다. 공식 문서 확인일은 2026-10-11이며 콘솔 메뉴는 계정/언어에 따라 달라질 수 있음을 표시한다.
3. 이름·보관 방식·API 키를 입력하고 `확인 후 추가`를 누른다. 기본은 이번 로그인 동안 사용이다. 암호화 설정이 없으면 계정 저장을 비활성화한다. 서버가 모델을 조회한 뒤 연결을 저장하며 실패하면 해당 단계에서 오류별 다음 행동을 표시한다. 요청 시작·완료·실패·이전 단계 이동·종료 시 키를 비운다.
4. 모달 안에서 모델을 선택하고 완료한다. 실제 목록과 서버 허용 정책의 교집합에서만 선택을 기억한다. 이 단계에서는 연결은 이미 저장됐음을 명시하며, 선택 전 닫아도 저장된 연결은 남는다. 목록을 다시 확인할 수 있고 실제 생성 지원 검증은 후속 단계다.
5. 기존 연결에는 이름 저장·확인 후 키 교체·재확인·삭제가 있다. 제공자/보관 방식을 바꾸려면 새 연결을 추가한다. 교체 실패는 기존 키와 모델을 보존하고 성공하면 이전 기본 모델·선택·캐시를 무효화한다.

임시 연결과 선택은 해당 로그인에서만 제공한다. 암호화 저장한 연결·선택은 다른 PC나 새 로그인에서도 제공한다. 모델 캐시는 세션별 메모리이며, 모델 목록 로딩·선택 저장·생성 시 목록이 없거나 만료되면 서버가 자동으로 다시 조회한다. 연결과 선택 모델은 유지하며 자동 조회로 연결 리비전을 변경하지 않는다. 연결 목록 조회 자체는 외부 호출하지 않는다. 연결 관리로 편집 코드를 바꾸거나 저장하지 않는다.

## 로컬 설정

`.env`에서 `AI_ENABLED=true`로 활성화하고 서버를 재시작한다. 기본은 비활성이다. 활성화만으로 외부 호출하지 않는다. 임시 키는 마스터 키가 필요 없다. 영구 저장은 [저장 문서](ai-storage.md)의 마스터 키·키 식별자와 `AI_ALLOW_STORED_CREDENTIALS=true`가 필요하다. 실제 API 키는 웹 모달에서 입력하며 채팅·Git에 넣지 않는다. 이번 작업은 사용자의 로컬 비밀 설정을 변경하지 않았다.

`AI_MAX_CONNECTIONS_PER_USER`는 기본 20개다. 확인·등록·교체·갱신은 공통 조회 한도와 시작 간격을 공유하며 시간 초과 뒤 실제 전송이 끝나기 전까지 슬롯을 유지한다. OpenAI 생성·수정은 [생성 서비스](ai-generation.md)로 연결했고 템플릿 생성도 그대로 사용할 수 있다. Claude·Gemini 생성은 후속이다.

## 서버 경계

### 모델 선택 목록 간소화

전체 API 모델 목록 대신 코드 작성에 사용할 대표 계열만 표시한다. OpenAI는 기본(Sol 포함)·Pro/Astra·Mini/Luna 계열별 최신 모델로 최대 3개, Claude는 Sonnet·Opus·Haiku·Fable별 최신 모델로 최대 4개, Gemini는 Pro·Flash·Flash-Lite별 최신 모델로 최대 3개다. 실제 연결에서 조회되지 않은 모델 ID는 만들지 않는다.

같은 계열의 과거 버전과 날짜별 스냅샷은 하나로 합친다. 같은 버전에서는 날짜 없는 ID를 우선하고, 날짜별 ID만 제공되는 경우 실제 조회된 최신 ID를 사용하되 화면에는 날짜를 숨긴다. 음성·이미지·임베딩·검색 등 전용 모델은 제외한다. Gemini의 대표 Preview 모델은 이름에 Preview를 명시한다. 모델 이름만 표시하며 내부 API ID는 선택 값으로 유지한다.

서버 카탈로그와 선택 검증에 같은 정책을 적용한다. 관리자 허용 모델 설정은 이 목록을 추가로 제한한다. 맞는 모델이 없으면 빈 목록을 표시하고 전체 목록으로 되돌아가지 않는다. 소비자용 웹 서비스의 모델 목록과 동일한 사용 권한을 보장하는 기능은 아니다. 변경 적용 후 서버를 재시작하고 모델 목록을 새로고침한다.

모델 계열 확인 근거: [OpenAI 모델 목록](https://developers.openai.com/api/docs/models/all), [Claude 모델 개요](https://platform.claude.com/docs/en/models/overview), [Gemini 모델 목록](https://ai.google.dev/gemini-api/docs/models). 숫자 버전 비교와 계열 규칙은 `src/ai/model-selection.js`에서 관리한다. 새 계열이 출시되면 규칙 검토가 필요하다.

- 로그인 사용자만 `/api/ai/*`를 사용할 수 있다. 변경 요청은 현재 로컬 서비스의 동일 Origin을 요구한다. 기존 서버 주소 검증과 함께 적용하며 HTTPS·중계 배포 시 Origin 정책을 배포 설정에 맞추어야 한다.
- `GET providers`는 활성 여부·허용 제공자·암호화 저장 가능 여부를 반환한다. `GET connections`는 공개 메타데이터와 마지막 선택만 반환한다.
- 등록/교체 확인은 저장 수정 큐 진입 전에 수행하고, 커밋 시 세션·리비전을 다시 검사한다. 조회 중 다른 편집을 막지 않는다. 이름/모델 변경과 키 교체는 별도 PATCH이며 DELETE는 리비전과 소유권을 검사한다.
- 재확인·갱신 POST는 확인 상태·시각을 새 리비전에 기록한다. 모델 선택 PUT은 필요시 목록을 자동 갱신한 뒤 모델을 검사하고 저장 트랜잭션에서도 리비전을 확인한다. 다른 사용자·다른 임시 세션·누락 Origin·잘못된 필드를 차단한다.
- 자동 갱신은 동일 사용자·세션·연결·리비전의 동시 요청끼리 공유하고 기존 조회 한도·시간 제한을 적용한다. 유효한 캐시는 재사용한다. 실제 목록에서 선택 모델이 제거됐으면 거부하며 다른 모델을 자동 선택하지 않는다. 조회 실패는 실제 제공자 오류로 표시하고 만료된 목록으로 생성하지 않는다.
- 모델 GET의 `cacheOnly=1`은 외부 호출 없이 캐시 상태만 반환한다. UI는 재확인·갱신 실패 후 이 경로로 상태를 확인하여 실패한 외부 조회를 즉시 반복하지 않는다.
- UI는 조회 순번으로 늦은 결과를 폐기하고 선택 저장을 순서대로 처리한다. 갱신 실패 뒤 오래된 모델을 활성 상태로 유지하지 않는다. 모달 처리 중 중복 요청·닫기를 제한한다.

공개 응답에 원본 키·비밀 참조·내부 로그인 식별자를 포함하지 않는다. 개인정보 운영 준비는 배포 전 마지막 필수 단계로 유지한다.

## 검증·다음 단계

`test/ai-api.test.js`는 실제 HTTP·파일·세션에서 관리 API·권한·Origin·실패 보존·조회 중 편집·로그아웃 경합·연결 수 한도를 검증한다. `npm run test:ai-connections`는 데스크톱/모바일 UI·선택 기억·키 입력 초기화·기존 코드 보존·영구/임시 세션 구분을 검증하며 CSP를 유지한다. 제공자 HTTP 응답만 대체했으며 실제 API 키 호출은 아직 검증하지 않았다.

5단계 공통 게임 규약 입력·코드 파일 사본·생성 요청 큐·SSE·취소·후보 수명과 OpenAI 생성 연결을 구현했다. 실제 키 검증 결과와 후속 제공자 진행은 생성 문서를 따른다.

## 발급 안내 유지보수

2026-10-14 OpenAI 안내 보완: 모달의 스크롤 본문 밖 상단에 `ChatGPT 구독과 별도 과금`을 강조하고 OpenAI API 키로 연결한다는 설명을 고정했다. 제공자 선택·준비·키 입력·모델 선택 및 기존 연결 관리에서 확인할 수 있으며 다른 제공자를 선택하면 숨긴다. 준비 본문은 `1 API 결제 준비`와 `2 API 키 발급` 카드로 나눈다. 결제 설정 링크를 먼저 배치하고 결제 플랜 시작·카드 등록·크레딧 구매, 기존 API 잔액이 있으면 진행 가능함을 짧게 안내한다. 모델 조회 성공이 유료 생성 가능을 보장하지 않는다는 설명을 결제 액션 바로 아래에 둔다.

키 발급 문장을 줄이고 다음 단계 버튼을 `API 키 입력으로`, 입력 라벨을 `OpenAI API 키`로 표시한다. 입력란 바로 아래에서 ChatGPT 비밀번호나 OAuth 값이 아닌 비밀 키 전체를 입력하도록 안내한다. 불필요한 공통 링크/설명을 준비 단계에서 숨겨 중복을 줄였다. 확인 체크박스나 결제를 강제하는 별도 승인 절차는 추가하지 않는다. 실제 결제 상태를 API 키 조회만으로 확인했다고 표시하지 않는다.

브라우저 검증에는 데스크톱/모바일 고정 요금 안내, 결제→키 링크 순서, 모바일 첫 화면 결제 버튼 가시성, 스크롤 후 안내 유지, 키 입력 문구, 다른 제공자 전환 시 숨김을 포함한다. 사용자 서버는 재시작하지 않았으며 화면 새로고침으로 적용한다.

제공자별 설명·링크·실패 시 안내는 `public/ai-provider-guides.js`로 분리했다. 모바일에서 긴 안내는 본문 안에서 스크롤하고 단계 이동 버튼은 계속 표시한다. 외부 사이트를 자동 조작하거나 대신 계정·결제를 설정하지 않는다. 브라우저 검증에는 세 제공자 안내 전환·오류 안내·모달 안의 선택 완료·이전 단계 이동 시 키 초기화·모바일 이동 버튼 가시성을 포함한다.

공식 근거: [OpenAI API 시작 안내](https://developers.openai.com/api/docs/quickstart), [Claude 키 발급 절차](https://platform.claude.com/docs/en/get-api-key), [Gemini 키·프로젝트 준비](https://ai.google.dev/gemini-api/docs/api-key). 화면 캡처를 발급 콘솔의 실제 화면처럼 만들어 사용하지 않았다.
