# 작성용 규약·두 모드 프롬프트 계약

- 구현일: 2026-11-14
- 범위: 작성용 전체 규약·후속 요약·선택적 최소 골격·내용 버전과 두 모드의 복사용 본문 구성.
- 상태: 1~3단계 완료. 기본값은 새 대화이며 UI에서 후속 요청을 선택할 수 있다. 규약 확인과 내용 버전·문서 수명을 연결했다.
- 관련: [작업 계획](prompt-context-reduction-plan.md), [작성 규약 원본](algorithm-authoring-rules.md), [현재 사용법](local-authoring.md).

## 응답과 호환성

로그인 전용 `GET /api/algorithm-assistant/contract`에 다음 필드를 추가한다. 외부 AI·API 키·DB·새 사용자 저장소가 필요하지 않으며 기존 인증·Host/Origin·no-store 정책을 유지한다.

| 필드                              | 내용                                                                                   |
| --------------------------------- | -------------------------------------------------------------------------------------- |
| `schemaVersion`                   | 기존 1 유지. 현재 변경은 필드 추가이며 기존 클라이언트의 구조 검사를 깨지 않음         |
| `contentVersion`                  | `sha256:` 뒤에 64자리 16진수. 새 작성용 규약 내용과 관련 정책의 식별자                 |
| `promptContext.fullRules`         | 새 대화에 사용할 작성용 전체 규약. 전략이 구현된 완성 예제는 포함하지 않음             |
| `promptContext.continuationRules` | 앞선 규약 유지 지시, 메서드·방향·위치 계약과 실행 제한·금지 기능의 짧은 요약           |
| `promptContext.starterSource`     | initialize/getName/moveNext가 있는 실행 가능한 최소 골격. 전략은 구현하지 않고 -1 반환 |
| `outputInstructions.prompt`       | 기존 단일 JavaScript 코드 블록 출력 지시. 본문과 별도로 유지                           |

기존 `instructions`와 `outputInstructions.api`는 서버의 호환용으로 유지한다. 2단계부터 `public/prompt-builder.js`는 새 `promptContext`, `contentVersion`, 복사용 출력 지시만 사용한다. 새 필드가 없는 오래된 응답은 재조회 오류로 처리하며 과거 긴 본문으로 조용히 대체하지 않는다. 보관한 직접 API 서버 기능은 재활성화하지 않는다.

`schemaVersion`은 응답 구조의 버전이고 `contentVersion`은 작성용 내용의 버전이다. 같은 구조 안의 규칙·제한이 바뀌면 내용 버전만 달라질 수 있다. 새 필드 검증은 2단계, 규약 확인 시 변경 감지·전체 모드 복귀는 3단계에 연결했다.

## 복사용 생성 함수 — 2단계

`buildCopyablePrompt(contract, strategy, source?, options?)`에서 네 번째 인자의 `conversationMode`를 `new` 또는 `continue`로 지정한다. 생략하면 항상 `new`이며 생성 횟수·이전 호출에 따라 바꾸지 않는다. 모드를 전략 객체 안에 넣어 기존 검증을 완화하지 않는다.

| 조건                          | 생성 내용                                                            |
| ----------------------------- | -------------------------------------------------------------------- |
| new + generate                | 전체 규약·최소 골격·전략/요청·출력 지시. 원문은 포함하지 않음        |
| new + modify                  | 전체 규약·명시한 원문·변경 요청·출력 지시. 원문 필수, 골격 제외      |
| continue + generate           | 짧은 규약 요약·이번 새 전략/요청·출력 지시. 전체 규약/골격/원문 제외 |
| continue + modify + 원문      | 짧은 요약·현재 원문 기준 수정 요청·출력 지시. 전체 규약/골격 제외    |
| continue + modify + 원문 생략 | 이전 대화에서 작성한 코드 기준 수정 요청·짧은 요약·출력 지시         |

후속 요청의 원문 생략은 `undefined`로 표현한다. 명시적으로 넘긴 null·숫자·공백 문자열을 정상 원문으로 받지 않는다. 원문이 있는 수정은 이전 대화의 코드보다 첨부한 현재 원문을 기준으로 한다. 생성 목적에 넘긴 원문은 기존처럼 무시해 선택하지 않은 코드를 붙이지 않는다. 요청은 기존 전략 검증·우선순위와 JSON 직렬화를 사용해 코드·구분자·한글을 보존한다.

결과는 기존 text·intent·includesSource·length에 conversationMode·contentVersion·includesFullRules·includesExample을 추가한다. includesExample은 완성된 샘플 알고리즘이 아니라 최소 골격을 포함했는지를 뜻한다. conversationMode·contentVersion은 내부 상태 비교에 사용하며 복사용 본문에는 대화 방식 표시나 규약 해시를 넣지 않는다. 본문은 짧은 게임/작성 제목·규약 우선 지시, 전체 규약 또는 후속 유지 요약, 조건별 골격, 이번 작업, 요청 데이터, 출력 형식으로 구성한다. 두 모드 모두 동일한 단일 파일/코드 블록 출력 지시로 끝난다. length는 실제 생성 문자열 길이이며 토큰·비용 추정값이 아니다.

## 모드 선택과 문서 수명 — 3단계

작성 도우미 상단에 `새 알고리즘 작성 / 기존 코드 수정` 목적 선택을, 프롬프트 생성 버튼 바로 위에 새 AI 대화/같은 AI 대화 라디오와 규약 변경 안내를 제공한다. 초기 목적은 generate, 대화 방식은 new다. 대화 방식의 수동 전환·규약 변경에 따른 new 복귀·생성·복사 횟수로 작업 목적을 바꾸지 않는다. continue에서도 새 알고리즘을 만들 수 있다. 현재 코드 포함은 modify에서만 선택하며 new+modify에서 원문이 없으면 생성/복사를 막고 대상 코드 포함을 안내한다. 기존 AI 대화의 코드를 수정하는 continue+modify는 원문을 생략할 수 있다.

새 문서·저장 코드/PC 파일 불러오기는 기존 editor reset 경계를 이용해 목적을 generate, 모드를 new로 돌리고 미리보기·코드 포함을 비운다. 같은 문서의 붙여 넣기·편집·저장은 목적과 모드를 유지한다. 포함하지 않은 코드는 편집해도 생성 본문을 바꾸지 않으며 최신 코드가 AI 대화와 다르면 포함하도록 짧게 안내한다. 선택하지 않은 원문을 자동 첨부하지 않는다.

명시적 생성에서만 본문을 만들고 모드·내용 버전을 입력 스냅샷에 포함한다. 미리보기 요약은 선택 UI 자체가 아니라 실제 생성 본문의 모드·규약 종류·원문/골격 포함·글자 수를 표시한다. 현재 입력과 다르면 본문을 유지하며 재생성 전 복사/전체 선택 액션을 비활성화한다. 복사 대기 중 모드·문서·입력이 바뀌면 늦은 성공 안내를 폐기한다.

`규약 확인`은 같은 인증 API를 수동으로 다시 조회한다. 같은 내용 버전이면 모드와 생성 본문을 유지한다. 변경을 확인하면 new로 복귀하고 전체 규약 재전달을 안내하며 이전 본문은 재생성 필요 상태가 된다. 실패·401·오래된 응답 형식은 복사/생성을 막고 원문을 보존한다. 외부 AI 대화의 규약을 자동 확인했다고 표시하지 않으며 주기적 폴링·새 사용자 데이터 저장을 추가하지 않는다.

전략 ID·표시 순서·이름·설명·순위 가중치·입력 제한은 본문 생성과 화면에서 브라우저 모듈의 공통 값을 사용한다. 조회한 규약의 값이 이 모듈과 다르면 새로운 내용 버전과 이전 전략 값을 섞어 생성하지 않는다. 규약 조회와 생성 함수 모두 불일치를 검사하고 생성/복사/전체 선택을 차단한다. 편집 코드·기존 미리보기는 유지하며 먼저 저장/내보내기 후 화면 새로고침을 안내한다. 규칙 본문만 바뀐 경우에는 새로고침을 강제하지 않고 기존 버전 전환 정책을 따른다.

## 내용 버전의 범위

서버의 `promptContentVersion()`은 아래 항목을 고정된 구조로 직렬화한 후 SHA-256을 계산한다.

- 언어, 호출 시간·guest heap 제한.
- 전략 입력 길이·선택 수, 전략 ID·표시 이름·설명, 순위 가중치.
- 전체 규약·후속 요약·최소 골격.
- 복사용 출력 지시.

줄바꿈을 LF로 통일하고 본문 양 끝 공백을 정리하므로 Windows/Linux 체크아웃에서 같은 규약의 내용 버전이 같다. 사용자·세션·시각·요청 문장·코드·연결 정보는 넣지 않는다. 과거 문서 원문을 결합한 `instructions`와 종료한 API의 출력 포맷은 새 내용 버전에서 제외한다.

해시는 변경 식별용이며 인증 서명이나 AI의 규약 수신 증명이 아니다. 생성/복사만으로 외부 대화에 규약이 전달됐다고 판단하지 않는다. 반환 객체 변경이 다음 조회에 영향을 주지 않도록 매번 분리된 값을 반환한다.

## 규약과 구현 대응

새 규약은 과거 설명 문서 전체를 단순 잘라낸 것이 아니다. 아래 실제 구현을 확인한 별도 작성용 원본이다. 게임 규칙을 변경할 때 해당 원본·대응 검사를 함께 갱신한다.

| 규약 항목                                         | 구현 근거·검증                                                                                                 |
| ------------------------------------------------- | -------------------------------------------------------------------------------------------------------------- |
| 단일 파일·필수 메서드·문자열 이름·방향 반환       | `src/runtime/sandbox.js`, `src/runtime/preflight-worker.js`. 최소 골격을 실제 preflight에서 24회 호출          |
| 500ms·32MiB                                       | `src/runtime/policy.js`의 상수로 원본 자리표시자와 후속 요약을 구성. 상수 값 변경을 중복 하드코딩하지 않음     |
| 시작 위치·행 우선 인덱스·벽/코인·방향·아이템 순서 | `src/game/maps.js`, `state.js`, `match.js`. 실제 GameState의 이웃 위치·허용 타일·아이템 획득 결과 대조         |
| 동기 실행·금지 구문·호스트 기능 제한              | `src/runtime/policy.js`, `sandbox.js`, `preflight-worker.js`. 기존 런타임·검사 테스트로 회귀 검증              |
| 독립 턴·현재 턴 패널티·동일 인스턴스 유지         | `src/game/match.js`, `src/runtime/`. 기존 무한 루프→다음 호출·독립 프로세스 검사 유지                          |
| 액션 완료 시 획득·신발/망치/x2/점프·효과 교체     | `src/game/state.js`, `match.js`와 기존 게임 테스트. 지속량을 7로 바꾼 맵에서도 획득 효과에 반영되는지 대조     |
| 아이템/점프 배치 제한·Hurry Up·기믹               | `src/game/state.js`와 게임 테스트. 출현/소멸/액션 시간을 특정 맵의 값으로 고정하지 않음                        |
| 이름·debug.print 표시 한도                        | `src/runtime/sandbox.js`의 현재 동작을 문서화. 시간/메모리 외 상수 추출을 위해 실행기를 별도 리팩터링하지 않음 |

원본의 `{{TURN_LIMIT_MS}}`, `{{MEMORY_LIMIT_MIB}}`는 API 응답 생성 때 실제 정책 값으로 채운다. 알고리즘에 제공되지 않는 상대 위치·본인 효과 잔량·경기 남은 시간을 별도 API가 있는 것처럼 안내하지 않는다.

## 측정과 확인 범위

2026-11-14 규약 조각 글자 수: 기존 호환 규약 6,332자, 작성용 전체 규약 3,192자, 후속 요약 312자, 최소 골격 290자. 1단계까지는 실제 생성 본문이 기존과 같은 6,797자였다. 2단계의 근처 코인 단일 전략·신규 작성·코드 제외 조건에서 실제 생성 본문은 새 대화 4,091자, 후속 요청 896자다. 다른 원문·전략·작업 목적에서는 길이가 달라지며 이 수치는 토큰·비용·AI 품질을 뜻하지 않는다.

`test/prompt-contract.test.js`는 정책·규약 대응, 줄바꿈/조회 안정성, 규약·요약·골격·출력·정책별 변경 감지, 반환 객체 분리, 실제 골격 검사, 기존 생성 본문의 호환성을 검증한다. 기존 HTTP 검사가 새 필드를 포함한 인증·미인증·이용 중지·외부 호출 없음과 종료한 AI 경로를 확인한다.

2단계 검사는 두 모드와 작업 목적/코드 포함의 조합, 원문 없는 후속 수정, 명시한 최신 원문 보존, 호출 간 상태 미공유, 규약/모드 오류와 요청·출력 형식 보존을 추가했다. 기존 화면의 생성·복사·코드 가져오기·실제 경기·저장 흐름도 확인한다. 실제 외부 AI의 작성 결과·규약 기억 능력은 아직 검증하지 않았고 모드를 자동 선택하지 않는다.

3단계 브라우저 검사는 라디오 키보드 조작, 코드 없는 후속 수정, 모드/규약 변경 중 복사 경합, 같은 버전 재확인, 401·형식 오류 복구, 제외한 코드 편집 시 본문 유지, 새 문서/저장 코드/PC 파일 초기화, 적용·저장 중 모드 유지와 모바일 배치를 확인한다. 규약 변경·실패 응답과 클립보드는 테스트 대체물이며 실제 서버의 코드 검사·경기·저장을 사용한다.

1~3단계 적대적 리뷰 후에는 수동/규약 변경 시 수정 목적 유지와 원문 없는 새 대화 차단, 후속 신규 작성, 전략 설명·이름·ID·가중치·입력 제한 불일치 시 생성/복사 차단과 원문 보존을 회귀 검사에 추가했다. 순서·전략 수 변경은 단위 검사에서 확인한다. 4단계 전체 조합 확장은 별도 남은 범위다.
