# 작성용 규약 계약 — 분량 축소 1단계

- 구현일: 2026-11-14
- 범위: 작성용 전체 규약·후속 요약·선택적 최소 골격 분리, 결정적 내용 버전 추가.
- 상태: 서버 계약 준비 완료. 두 모드의 본문 구성은 2단계, 모드 선택 UI는 3단계에서 연결한다.
- 관련: [작업 계획](prompt-context-reduction-plan.md), [작성 규약 원본](algorithm-authoring-rules.md), [현재 사용법](local-authoring.md).

## 응답과 호환성

로그인 전용 `GET /api/algorithm-assistant/contract`에 다음 필드를 추가한다. 외부 AI·API 키·DB·새 사용자 저장소가 필요하지 않으며 기존 인증·Host/Origin·no-store 정책을 유지한다.

| 필드                              | 내용                                                                                   |
| --------------------------------- | -------------------------------------------------------------------------------------- |
| `schemaVersion`                   | 기존 1 유지. 현재 변경은 필드 추가이며 기존 클라이언트의 구조 검사를 깨지 않음         |
| `contentVersion`                  | `sha256:` 뒤에 64자리 16진수. 새 작성용 규약 내용과 관련 정책의 식별자                 |
| `promptContext.fullRules`         | 새 대화에 사용할 작성용 전체 규약. 전략이 구현된 완성 예제는 포함하지 않음             |
| `promptContext.continuationRules` | 앞선 규약 유지 지시, 메서드·방향·위치 계약과 실행 제한·금지 기능의 짧은 요약           |
| `promptContext.starterSource`     | initialize/getName/moveNext가 있는 실행 가능한 최소 골격. 전략은 구현하지 않고 -1 반환 |
| `outputInstructions.prompt`       | 기존 단일 JavaScript 코드 블록 출력 지시. 본문과 별도로 유지                           |

기존 `instructions`와 `outputInstructions.api`는 호환용으로 유지한다. 현재 `public/prompt-builder.js`는 아직 `instructions`를 사용하므로 1단계만 적용한 화면의 생성·복사 본문은 달라지지 않는다. 보관한 직접 API 서버 기능은 재활성화하지 않는다.

`schemaVersion`은 응답 구조의 버전이고 `contentVersion`은 작성용 내용의 버전이다. 같은 구조 안의 규칙·제한이 바뀌면 내용 버전만 달라질 수 있다. 2단계 이후 새 필드를 사용하는 클라이언트 검증과 3단계의 규약 변경 시 전체 모드 복귀에 연결한다.

## 내용 버전의 범위

서버의 `promptContentVersion()`은 아래 항목을 고정된 구조로 직렬화한 후 SHA-256을 계산한다.

- 언어, 호출 시간·guest heap 제한.
- 전략 입력 길이·선택 수, 전략 ID·표시 이름·설명, 순위 가중치.
- 전체 규약·후속 요약·최소 골격.
- 복사용 출력 지시.

줄바꿈을 LF로 통일하고 본문 양 끝 공백을 정리하므로 Windows/Linux 체크아웃에서 같은 규약의 내용 버전이 같다. 사용자·세션·시각·요청 문장·코드·연결 정보는 넣지 않는다. 과거 문서 원문을 결합한 `instructions`와 종료한 API의 출력 포맷은 새 내용 버전에서 제외한다.

해시는 변경 식별용이며 인증 서명이나 AI의 규약 수신 증명이 아니다. 생성/복사만으로 외부 대화에 규약이 전달됐다고 판단하지 않는다. 반환 객체 변경이 다음 조회에 영향을 주지 않도록 매번 분리된 값을 반환한다.

## 규약과 구현 대응

새 규약은 과거 설명 문서 전체를 단순 잘라낸 것이 아니다. 아래 실제 구현을 확인한 별도 작성용 원본이다. 게임 규칙을 변경할 때 해당 원본·대응 검사를 함께 갱신한다.

| 규약 항목                                         | 구현 근거·검증                                                                                                 |
| ------------------------------------------------- | -------------------------------------------------------------------------------------------------------------- |
| 단일 파일·필수 메서드·문자열 이름·방향 반환       | `src/runtime/sandbox.js`, `src/runtime/preflight-worker.js`. 최소 골격을 실제 preflight에서 24회 호출          |
| 500ms·32MiB                                       | `src/runtime/policy.js`의 상수로 원본 자리표시자와 후속 요약을 구성. 상수 값 변경을 중복 하드코딩하지 않음     |
| 시작 위치·행 우선 인덱스·벽/코인·방향·아이템 순서 | `src/game/maps.js`, `state.js`, `match.js`. 실제 GameState의 이웃 위치·허용 타일·아이템 획득 결과 대조         |
| 동기 실행·금지 구문·호스트 기능 제한              | `src/runtime/policy.js`, `sandbox.js`, `preflight-worker.js`. 기존 런타임·검사 테스트로 회귀 검증              |
| 독립 턴·현재 턴 패널티·동일 인스턴스 유지         | `src/game/match.js`, `src/runtime/`. 기존 무한 루프→다음 호출·독립 프로세스 검사 유지                          |
| 액션 완료 시 획득·신발/망치/x2/점프·효과 교체     | `src/game/state.js`, `match.js`와 기존 게임 테스트. 지속량을 7로 바꾼 맵에서도 획득 효과에 반영되는지 대조     |
| 아이템/점프 배치 제한·Hurry Up·기믹               | `src/game/state.js`와 게임 테스트. 출현/소멸/액션 시간을 특정 맵의 값으로 고정하지 않음                        |
| 이름·debug.print 표시 한도                        | `src/runtime/sandbox.js`의 현재 동작을 문서화. 시간/메모리 외 상수 추출을 위해 실행기를 별도 리팩터링하지 않음 |

원본의 `{{TURN_LIMIT_MS}}`, `{{MEMORY_LIMIT_MIB}}`는 API 응답 생성 때 실제 정책 값으로 채운다. 알고리즘에 제공되지 않는 상대 위치·본인 효과 잔량·경기 남은 시간을 별도 API가 있는 것처럼 안내하지 않는다.

## 측정과 확인 범위

2026-11-14 로컬 글자 수: 기존 호환 규약 6,332자, 작성용 전체 규약 3,192자, 후속 요약 312자, 최소 골격 290자. 이는 규약 조각의 길이이며 최종 프롬프트 전체 길이·토큰 수·비용·AI 품질을 뜻하지 않는다. 현재 근처 코인 단일 전략의 실제 생성 본문은 기존과 같은 6,797자다.

`test/prompt-contract.test.js`는 정책·규약 대응, 줄바꿈/조회 안정성, 규약·요약·골격·출력·정책별 변경 감지, 반환 객체 분리, 실제 골격 검사, 기존 생성 본문의 호환성을 검증한다. 기존 HTTP 검사가 새 필드를 포함한 인증·미인증·이용 중지·외부 호출 없음과 종료한 AI 경로를 확인한다.

실제 외부 AI의 작성 결과·규약 기억 능력은 아직 검증하지 않았다. 이 단계에서 후속 모드를 자동 선택하거나 기존 규약을 생략하지 않는다.
