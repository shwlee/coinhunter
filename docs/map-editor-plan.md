# 관리자 게임맵 제작·편집 작업 계획

- 작성일: 2026-10-06
- 상태: 1~6단계 구현 완료. 별도 제작 화면과 관리자 초안 조회·저장 API를 연결했다. 후속 맵 관리의 publish/hide 및 특정 맵 자동 불러오기도 구현했으며 경기 설정은 후속 작업이다.
- 우선순위: 사용자 관리 다음으로 맵 제작·편집을 먼저 구현하고 게임 옵션 관리는 이후 진행한다.
- 관련 문서: [관리자 전체 계획](admin-page-plan.md), [파일 기반 맵 관리](map-files.md).

2026-10-06 후속 계획 변경: 게시·숨기기·다시 노출과 운영 목록은 게임 옵션 메뉴 대신 별도 `/admin/maps`에서 제공한다. 편집 화면과 직접 연결하고 경기 옵션 편집은 이후 구현한다. 아래 최초 구현 범위의 후속 메뉴 배치는 [맵 관리 계획](map-management-plan.md)을 따른다.

## 1. 이번 구현 범위와 화면 흐름

관리자 페이지의 게임맵 메뉴에서 별도 제작 화면 `/admin/maps/editor`로 진입한다. 사용자 관리 화면 아래에 편집기를 붙이지 않고 제작에 필요한 공간을 확보한다. 관리자 공통 헤더와 돌아가기 기능을 유지한다.

기본 흐름은 **열·행 입력 → 빈 게임판 생성 → 도구 선택 → 바닥 클릭으로 배치 → 맵 저장 → 저장 목록에서 불러오기**다. 이번 단계는 맵의 모양과 타일을 작성·저장하는 기능이다.

| 이번 단계 | 이후 게임 옵션 메뉴 | 추가 후속 기능 |
| --- | --- | --- |
| 빈 맵 생성, 코인·벽·지우기 도구, 대칭 배치, 저장·불러오기 | 맵 목록의 노출/비노출 관리, publish/hide, 맵별 경기·아이템·기믹 설정, 표시 순서 | 샘플 복사, 랜덤 생성, int[]·JSON import/export |

제작 화면의 저장 목록은 편집할 맵을 고르는 용도다. 게임 옵션 메뉴의 목록은 사용자에게 제공할 맵과 경기 설정을 관리하는 용도다. 제작 화면에서 저장했다고 사용자 맵 선택 목록에 자동으로 노출하지 않는다.

## 2. 빈 게임판 생성

- 열(`col`, 저장 형식은 `columns`)과 행(`row`, 저장 형식은 `rows`)을 입력하고 생성 버튼을 누른다. 현재 게임의 허용 범위인 열 4~40, 행 4~30을 유지한다.
- 생성 시 `columns × rows` 길이의 `tiles`를 모두 `0`으로 초기화한다. 바닥과 격자만 표시하고 코인·벽·아이템·플레이어는 배치하지 않는다.
- 네 모서리 시작 칸은 표시하고 항상 빈칸으로 보호한다. 맵 밖 경계는 게임 규칙에서 처리하므로 테두리 전체를 벽으로 채우지 않는다.
- 생성 전에는 타일 도구를 비활성화한다. 생성 후 도구와 저장 기능을 사용할 수 있다.
- 기존 맵의 크기를 바꾸고 다시 생성하면 배치가 초기화된다. 실제 미저장 변경이 있을 때만 초기화 확인을 받는다. 자동으로 자르거나 늘리지 않는다.

## 3. 편집 UI/UX

- 상단에 새 맵, 저장된 맵 불러오기, 저장을 배치한다. 작은 도구 영역과 넓은 게임판 영역으로 구성한다.
- 배치 도구는 코인·벽을 선택하는 토글과 지우개로 구성한다. 현재 도구를 명확히 강조하고, 코인 도구에는 10/30/100/200/500 점수 선택을 제공한다.
- 게임판의 칸을 클릭하면 선택한 에셋을 배치한다. 기존 타일이 있으면 선택한 값으로 교체한다. 지우개를 클릭한 칸은 빈 바닥으로 되돌린다. 같은 칸을 다시 클릭해도 예기치 않게 지워지지 않는다.
- 코인은 현재 게임의 점수별 코인 이미지, 벽은 기존 게임 자산을 재사용한다. 플레이용 움직임·효과는 편집 화면에서 재생하지 않는다.
- 배치 전 포인터 위치에 적용 칸을 미리 강조한다. 시작점은 배치 불가 표시와 이유를 제공한다.
- 큰 맵은 전체 보기 배율과 확대·축소를 제공해 전체 형태 확인과 정확한 타일 클릭을 모두 지원한다. 확대된 게임판의 스크롤은 편집 영역 안에서 처리한다.
- 편집 실행 취소·다시 실행을 제공한다. 대칭 배치 한 번은 하나의 변경으로 취급한다. 서버의 저장 리비전은 편집 실행 취소 이력과 별개다.
- 맵 크기, 코인 수·총점, 벽 수, 미저장 여부를 간단히 표시한다. 오류는 편집 내용을 지우지 않고 화면에 표시한다.

## 4. 상하좌우 대칭 옵션

- 기본값은 켜짐으로 한다. 끄면 클릭한 칸만 변경할 수 있다.
- `(x, y)` 클릭 시 `(x, y)`, `(columns - 1 - x, y)`, `(x, rows - 1 - y)`, `(columns - 1 - x, rows - 1 - y)`를 함께 변경한다.
- 홀수 크기의 중앙 행·열에서 겹치는 위치는 한 번만 처리한다. 코인 점수 교체와 지우기에도 같은 규칙을 적용한다.
- 대칭을 켜는 것만으로 기존 배치를 자동 변환하지 않는다. 켠 이후의 편집에 적용하며, 기존 비대칭 상태는 검사 결과로 알려준다.
- 대칭 옵션은 편집 도구 설정이며 경기 옵션이 아니다. 비대칭·고립 구역·코인 없는 맵도 작업 중 초안으로 저장할 수 있다.
- 게시 가능한 맵은 기존 규칙대로 상하좌우 대칭, 코인 존재, 네 시작점과 모든 이동 가능 공간의 연결성을 만족해야 한다. 제작 화면에서 문제 위치와 이유를 표시하되 초안 저장은 막지 않는다.

## 5. 저장·불러오기

- 신규 저장 시 모달에서 맵 이름과 선택적인 설명을 받는다. 맵 ID는 서버가 안전한 값으로 생성하고 사용자가 파일 경로를 입력하지 않게 한다.
- 이미 불러온 맵은 같은 ID로 새 리비전을 저장한다. 이름 변경도 해당 맵의 새 리비전으로 처리한다.
- 저장된 맵 불러오기는 별도 모달 목록으로 제공한다. 이름 검색, 크기, 최신 초안 리비전, 게시/노출 상태를 표시하되 여기에서 상태를 변경하지 않는다.
- 목록에서 선택한 맵의 최신 초안을 불러오고 크기·타일·이름·설명을 복원한다. 초안이 없는 기본 샘플은 이번 편집 목록에서 제외하고 샘플 복사를 후속 기능으로 둔다.
- 새 맵 생성, 다른 맵 불러오기, 화면 이탈 시 저장 이후 실제 변경이 있을 때만 확인한다. 저장 성공 또는 불러오기 완료 시 변경 기준을 갱신한다.
- 저장 실패나 다른 관리자와의 리비전 충돌 시 현재 편집 내용을 유지한다. 충돌은 최신 맵을 다시 불러오도록 안내하며 조용히 덮어쓰지 않는다.
- 신규 맵에는 서버의 공통 기본 `settings`를 부여한다. 기존 맵 편집 저장은 저장된 `settings`를 보존한다. 클라이언트가 숨은 설정값을 임의로 변경할 수 없게 한다.

## 6. 데이터와 API

기존 `MapRepository`의 `registry`, `getDraft`, `saveDraft`를 재사용한다. 맵 원본은 `data/maps/<id>/<revision>.json`, 초안·게시·활성 상태는 `data/maps/registry.json`에 저장하며 Git에서 제외한다. 서버 재시작 후에도 복원한다. 기존 샘플 원본은 변경하지 않는다.

아래 API를 구현했으며 세부 응답 형식은 [API 문서](data-and-api.md)에 기록한다.

| API | 역할 |
| --- | --- |
| `GET /api/admin/maps` | 관리자 저장 맵 목록·크기·리비전·상태 조회 |
| `GET /api/admin/maps/:id/draft` | 편집할 최신 초안 조회 |
| `POST /api/admin/maps` | 서버 ID·기본 옵션을 적용한 신규 초안 저장 |
| `PUT /api/admin/maps/:id/draft` | `expectedRevision`을 검사하고 새 초안 리비전 저장 |

페이지와 API 모두 서버에서 활성 관리자 권한을 검사한다. 요청은 허용 필드만 받아 크기, 배열 길이, 타일 값, 이름, 시작점 보호를 검증한다. 잘못된 입력은 400, 없는 맵은 404, 저장 충돌은 409로 구분한다. 동시 쓰기는 기존 저장소 직렬화와 원자적 등록 파일 교체를 유지한다.

후속 게임 옵션 메뉴에서 `publish(id, revision)`과 `setEnabled(id, enabled)`를 관리자 API로 연결한다. publish는 저장된 최신 초안을 검증한 후 게시·노출한다. hide는 노출만 해제하고 초안·게시 버전은 보존한다. 숨긴 게시 버전을 다시 노출하는 기능과 새 초안 게시를 구분한다. 옵션 수정 역시 새 리비전으로 저장한다.

게시된 맵을 편집·저장해도 기존 게시 버전은 유지하며 사용자는 새 초안을 볼 수 없다. 이미 시작된 경기는 시작 시 복사한 맵과 설정을 끝까지 사용한다.

## 7. 구현 순서

1. 관리자 메뉴에서 제작 화면으로 진입하는 경로와 서버 권한 검사를 연결한다. 화면 골격, 열·행 입력, 빈 게임판 생성을 구현한다.
2. 타일 편집 상태와 렌더링을 분리하고 코인 점수·벽·지우개 도구, 시작점 보호, 미리보기, 확대·축소를 구현한다.
3. 대칭 위치 계산, 중앙축 중복 방지, 실행 취소·다시 실행, 미저장 변경 감지를 연결한다.
4. 신규·수정 저장 API를 구현한다. 공통 기본 옵션과 기존 설정 보존을 보장하고 서버 입력 검증·리비전 충돌을 처리한다.
5. 저장 모달과 저장된 맵 목록·불러오기를 연결한다. 저장·불러오기 결과 및 실패 이유를 표시한다.
6. 대칭·연결성·코인 존재 검사를 제작 화면에서 안내하고 아래 완료 기준을 검증한다. 작업 문서와 API 명세를 갱신한다.
7. 별도 후속 작업으로 게임 옵션 메뉴의 맵 목록, publish/hide, 노출 순서, 맵별 옵션 편집을 구현한다.

## 8. 이번 단계 완료 기준

- 관리자만 제작 화면·조회·저장 API에 접근할 수 있다.
- 지정 크기의 빈 게임판이 생성되고 코인·벽 배치, 교체, 삭제가 화면과 저장 데이터에 일치한다.
- 대칭 켜짐/꺼짐, 홀수 중앙축, 시작점 보호, 실행 취소가 올바르게 동작한다.
- 미완성 맵도 초안으로 저장·다시 불러올 수 있으며 서버 재시작 후 동일한 데이터가 복원된다.
- 미저장 변경 확인은 실제 변경이 있을 때만 발생한다. 저장 실패·충돌은 편집 내용을 잃게 하지 않는다.
- 기존 맵 설정과 게시 버전이 편집 저장으로 변경되지 않는다. 신규 저장 맵은 일반 사용자 목록에 나타나지 않는다.
- 자동 테스트로 권한·유효성·충돌·설정 보존·저장 복원을 검증하고, 브라우저에서 생성 → 대칭 배치 → 저장 → 불러오기 전체 흐름과 큰 맵 편집을 확인한다.
