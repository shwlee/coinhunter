## 1. 적용 범위와 검사 단계

사용자가 제출하는 한 개 파일에 적용한다. 사용자 helper 클래스/함수와 간접 호출도 같은 규칙을 따른다. 서버가 생성하는 래퍼, 고정된 실행기 SDK, 승인된 표준 라이브러리 구현은 사용자 소스가 아니다. 예를 들어 사용자 try문은 금지하지만 호스트의 timeout 처리 catch까지 금지하지 않는다.

정적 분석, 준비/참조 검사, 격리 환경, 호출별 실제 실행 검사는 서로 대체하지 않는다. 코드 검사 버튼뿐 아니라 서버의 업로드·저장·게임 진입이 같은 활성 규약/프로필을 사용해야 한다. 검사 실패 원문은 보관할 수 있으나 유효한 통과 기록 없이 실행하지 않는다. 현재 저장 API에는 이 새 동작이 아직 구현되지 않았다.

단일 코드가 여러 규칙을 위반할 수 있다. 정적 진단은 원본 위치 순서로 제공하고 같은 규칙/위치 중복은 제거한다. 구문 오류가 있으면 먼저 AX001을 표시하고 의미/실행 검사는 미수행으로 기록한다. 정적 규약 위반이 있으면 실행하지 않는다. timeout은 무한 루프의 증명이 아니므로 “무한 루프 확정”이라고 표시하지 않는다.

AP001은 해당 프로필에서 지원하지 않거나 호출 대상을 해석할 수 없는 구문이다. AP001을 AR009(재귀가 확인됨)으로 바꿔 표시하지 않는다. AX002는 사용자 실행 예외, AX003은 증거가 확인된 자원 한도 초과, AX004는 검사 환경/인프라 실패다. 예외 메시지 문자열로 원인을 추정하지 않는다.

## 3. 허용 범위와 언어별 차이

다음은 기본 알고리즘에 필요한 범위다. 초기 언어 프로필은 정확한 버전·API/overload·인자/콜백 조건으로 이를 구체화해야 하며, 단순 이름 목록으로 모든 호출을 허용하지 않는다.

| 기능                                                       | 공통 판정                         | 프로필 명세가 필요한 예                                                                                                               |
| ---------------------------------------------------------- | --------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------- |
| 지역 변수·인스턴스 필드·숫자/불리언·배열·분기              | 허용 목표                         | 큰 정수/배열 할당의 시간·메모리 제한은 별도 적용                                                                                      |
| for/while·일반 break/continue/return                       | 허용                              | 반복 검사 삽입/런타임 실제 중단으로 시간 제한                                                                                         |
| helper 함수·타입·변경 불가 값 상수                         | 순환/공유 상태가 없으면 허용 목표 | Python helper 선언 자체를 모듈 가변 상태로 오판하지 않음                                                                              |
| 큐·집합·사전·우선순위 큐                                   | 필요한 기본 기능                  | C# Queue/HashSet/Dictionary/PriorityQueue, Python collections/heapq, C++ queue/unordered_set/vector 등은 API별 중단/콜백 검증 후 승인 |
| 표준 수학 함수                                             | 승인 API 허용                     | 외부 패키지 금지와 C# Math 정적 메서드 호출 금지를 혼동하지 않음                                                                      |
| debug 출력                                                 | 호스트 제공 제한 API만 허용       | stdout/file/network logger를 임의 연결하지 않음                                                                                       |
| 정렬·comparer·generator/iterator·동적 속성·연산자 오버로드 | 프로필 검증 전 미승인             | 내부 재귀, 숨은 callback, 긴 builtin 호출, 중단 예외 변형 가능성                                                                      |
| using/with/소멸자·noexcept                                 | 프로필 검증 전 미승인             | 명시적 사용자 try문 금지를 우회하는 예외 억제·정리 경로 검증                                                                          |

언어별 기준:

- **JavaScript:** 현재 module.exports로 Player 클래스 하나를 내보내는 형식을 유지한다. module.exports 자체를 전역 가변 상태 위반으로 오판하지 않는다. class static 멤버는 금지, 프로토타입/모듈 수준의 사용자 공유 가변 상태는 새 분석 대상이다. goto 문법은 없고 labelled break/continue의 지원 범위는 JS 프로필에서 명시한다. 현재 generator 금지는 유지한다.
- **C#:** 사용자 static 선언은 상태 유무와 관계없이 기존 규칙대로 거부한다. const 값은 허용하며 static readonly 선언은 static 규칙에 따라 거부한다. 정적 플랫폼 메서드 호출은 승인 API 여부로 판정한다. helper 클래스·인스턴스 메서드는 허용 후보이며 파일 하나에 포함해야 한다.
- **Python:** 외부 패키지 import는 거부하지만 승인된 표준 모듈 import까지 일괄 금지하지 않는다. 클래스/함수 선언과 변경 불가 값 상수는 구분하고 클래스/모듈의 가변 컬렉션, global/nonlocal 상태 변경은 거부 대상으로 정의한다. bool은 int의 하위 타입이어도 이동 방향 반환으로 허용하지 않는다.
- **C++:** 승인 표준 헤더 include는 허용, 사용자/외부/절대 경로 헤더는 거부한다. Player 필드의 상태는 허용하고 사용자 전역/정적 가변 상태는 거부한다. constexpr 값 상수와 공유 가변 객체를 구분한다. 매크로 확장·템플릿 인스턴스·함수 try 블록도 검사한다.

표준 라이브러리 내부가 재귀를 사용한다는 이유만으로 사용자 재귀 규칙을 위반했다고 표시하지 않는다. 그 API의 중단/자원 안전성은 별도로 검증한다. 사용자 콜백으로 다시 사용자 함수가 호출되어 순환이 생기면 AR009 대상이다. 분석 불가능한 동적 dispatch는 AP001로 거부한다.

## 4. 입력·상태·호출 규약

초기화는 식별 번호·columns·rows, 이동은 평탄한 정수 map·정수 위치 myPosition·items[4]를 받는다. 방향은 왼쪽 0 / 위 1 / 오른쪽 2 / 아래 3 / 제자리 -1이다. 지도 값과 아이템 위치(-1은 없음)는 기존 실행 계약을 따른다. 비JS 메서드 철자/서명·문자열 형식은 언어 어댑터 계약에서 확정하며 이 명세가 새 API를 배포하지 않는다.

Player 필드는 같은 실행 인스턴스의 다음 호출에 유지한다. 입력은 호출 스냅샷이며 엔진 상태를 직접 수정할 수 없다. -1 정상 반환이나 벽 방향 선택을 코드 검사 실패로 처리하지 않는다. 랜덤점프 중 알고리즘 미호출 같은 게임 규칙을 검사기에서 임의로 변경하지 않는다.

한정된 테스트로 모든 입력/턴의 종료를 증명할 수 없다. 500ms 마감, 실제 중단 여부, 정리 완료/인스턴스 재사용은 각각 판정한다. 현재 JS는 기존 실제 중단 계약을 유지한다. 다국어의 정리 유예·교체 후 상태 복원은 공통 계획의 미확정 정책이며 이 규약으로 승인하지 않는다.

## 5. 진단과 저장/실행 상태 계약

기계 명세의 진단에는 code/stage/language/policyVersion/profileVersion/sourceHash/message/location/scenario/callId가 있다. location은 원본 기준 1부터 시작하는 행/열이고 끝 좌표는 반열린 범위다. 실행 오류처럼 위치를 모르면 null을 사용한다. 시나리오/호출 번호도 해당 없는 경우 null이다. 내부 경로·생성 래퍼 위치·원문 코드 전체를 메시지에 노출하지 않는다.

검사 통과는 소유자, source hash/revision, 언어, 규약/프로필/분석기/런타임/fixture/자원 프로필 버전에 묶는다. 변경되면 stale이다. 검사 버튼을 누른 뒤 코드가 바뀌거나 새 revision을 저장했으면 이전 검사 통과를 새 코드에 적용하지 않는다.

| 상태       | 원문 보관 | 실행                                                 |
| ---------- | --------- | ---------------------------------------------------- |
| pending    | 허용      | 검사 완료 대기                                       |
| passed     | 허용      | 현재 소스/프로필과 일치하는 경우 허용                |
| failed     | 허용      | 수정·재검사 필요                                     |
| unverified | 허용      | 검사 취소/포화/서비스 오류 등을 표시하고 재검사 필요 |
| stale      | 허용      | 버전/소스 변경 안내·재검사 필요                      |

권한·revision 충돌·저장소 오류는 원문 보관 실패다. 검사 실패와 혼동하지 않는다. 잘못된 사용자 코드의 규약 위반/예외/timeout은 failed, 검사 인프라 장애는 unverified다. 아직 지원하지 않는 언어는 실행 불가이며 저장 성공으로 지원 capability가 생기지 않는다.

## 7. 인수 사례의 사용과 완료 기준

cases.json은 코드 조각 또는 입력 조건과 기대 판정의 집합이다. sourceUnit/context를 보고 테스트 harness가 전체 Player로 조립해야 하며 조각을 그대로 제품에 업로드하지 않는다. 지정된 진단 코드는 포함돼야 할 항목이고 다른 정적 위반이 함께 검출될 수 있다. manifest/환경/실행 사례도 구문 분석 결과와 구분한다.

- accept는 해당 규칙을 위반하지 않는 예시이며 완성된 알고리즘의 실행 안전성 통과가 아니다.
- reject-static은 실행 전에 거부해야 한다. skip-runtime을 결과에 표시한다.
- reject-runtime은 신뢰된 내부 fixture로 실행 예산/반환 검사를 시험하는 사례다. 일반 사용자 사전 검사에서는 실패 코드로 기록한다.
- profile-dependent는 지원 여부/진단이 아직 결정되지 않은 프로필 승인 대상이다. 임의로 통과시키지 않는다.

후속 J0/J1 또는 언어별 분석기 구현 시 이 인수 사례를 실제 검사기로 실행하고 결과를 별도 보관한다. 명세 JSON의 정합성 확인만으로 규약 집행 검증을 통과했다고 하지 않는다.
