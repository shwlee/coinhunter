# 프롬프트 작업 마감 이후 남은 작업

- 정리일: 2026-11-15
- 기준: 사용자 결정으로 프롬프트 수정은 현재 구현까지 마감한다. 이 문서는 남은 범위 정리이며 새 기능 구현을 시작한 것은 아니다.
- 현재 구현: 게임 플레이·결과 분석·본인 이전 경기 알고리즘 대결, 계정·Google OAuth, 코드 편집/검사 진단/테스트/파일 저장, 관리자 사용자 관리·맵 제작/게시/옵션·전송/복제/표시 순서·대칭 랜덤 생성.
- 우선 적용: 과거 체크리스트에 이미 구현한 항목이나 제거한 직접 AI 연결이 미완료로 남아 있어도 최신 진행 기록과 이 범위 결정을 우선한다.
- 백엔드 기준: 엔진 실행 영역 외의 서비스 관리를 **게임 운영**이라고 부른다. 운영 NoSQL 후보와 언어 중립의 실행 데이터 수집/저장 영역을 분리해 선정·구현한다. [책임·연결 계약](game-backend-boundaries.md).
- 로그 수집 기준: 독립된 수집 모듈을 인터페이스로 주입하고 수집 정책과 실제 저장 어댑터를 분리한다. [모듈·추상화 계약](game-log-collection-modules.md)의 접수/내구 확인·장애/완결·교체 검증을 구현 기준으로 사용한다. 실제 로그 수집 구현은 아직 남아 있다.
- 운영 DB 추천안: [선정·개발·전환 계획](game-operations-database-plan.md)에 MongoDB 우선 후보와 단일 컨테이너 제약에 따른 SQLite 대안, 데이터 범위·일관성·원문 파일 정합성·단계별 이전을 정리했다. 제품/배포 확정과 구현은 아직 남아 있다.
- 2026-11-15 배포 범위 변경: FE/BE 서버 분리를 고도화 보류에서 배포 준비로 전환했다. [FE 요구사항](frontend-deployment-requirements.md)을 기준으로 독립 실행·정적 제공·API 중계·인증/주소·SSE/업로드·산출물·회귀 검증을 먼저 준비한다. 실제 분리 구현은 아직 남아 있다.
- 실행/렌더링 목표: [전체 흐름·차트](game-execution-rendering-flow.md)에 C# 운영 BE·상주 실행 관리자·게임별 Node.js 엔진과 화면/SSE·원본 로그·종료/복구 경로를 보관했다. 구체 포팅·서비스/프로세스 구현 계획은 이 목표에 맞춰 갱신하며 이번에는 문서화만 수행했다.
- 실행 공정성 기준: 실제 계산 속도가 승부에 반영되는 독립 턴을 유지한다. 계산 완료 즉시 액션·액션 완료 즉시 다음 계산으로 진행하며 공통 판단 지연/논리 시간 보정은 제외한다. 언어별 호출 인프라 편차는 실행기·입력 전달 설계와 측정으로 줄인다. [호출 비용 분석](algorithm-invocation-cost-analysis.md).
- 실행기 후속 작업: [구체 계획](algorithm-runner-independence-plan.md)에 계약 정의·기존 JS 어댑터 주입·독립 진행·호출 비용 분해/최적화·통합 검증을 추가했다. 문서화만 완료했으며 구현은 남아 있다. 다른 언어 런타임/후보 검증은 다국어 착수 때 수행한다.
- 관련: [진행 결과](progress.md), [저장 어댑터](storage-adapters.md), [관리자 계획](admin-page-plan.md), [개인정보 운영 준비](privacy-operations-plan.md), [고도화 보관 목록](enhancement-backlog.md).

## 1. 현재 범위에서 마감한 프롬프트 작업

작성용 규약·새 대화/후속·독립적인 작업 목적·코드 포함·생성/복사·검사 진단까지 현재 상태로 유지한다. 분량 축소 1~4단계는 완료했으며 다음 항목은 미완료인 채 보류한다. 완료로 간주하거나 다음 작업으로 자동 착수하지 않는다.

- 분량 축소 5단계의 실제 외부 AI 출력·문맥 유지 비교 평가.
- 검사 오류와 원문을 묶는 수정 프롬프트 액션.
- 테스트 결과를 연결하는 전략 개선 프롬프트.
- 기타 프롬프트 UI·전략 템플릿·출력 품질 고도화.

직접 AI API 연결, 별도 AI 응답 가져오기 모달, 로컬 템플릿 코드 생성은 제거 상태를 유지한다. 코드 편집기 직접 붙여 넣기·기존 검사·테스트·저장을 사용한다. 일반적인 계속 진행 요청으로 보류한 프롬프트 기능을 다시 시작하지 않는다.

## 2. 사내 서비스 배포를 위한 작업

| 권장 순서   | 작업                 | 구체 범위와 완료 기준                                                                                                                                                                                                                                                                                                                 |
| ----------- | -------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 선행/병행   | 전량 턴 로그 저장    | 매 턴 결과와 액션 완료·기믹·종료/취소를 기록할 이벤트 계약, JSONL/DB/Blob 저장소와 writer·내구성·조회/보관 정책을 확정하고 구현한다. 현재 최근 40건 로그는 전량 기록이 아니다. [저장소·모듈 분석](game-log-storage-analysis.md)을 기준으로 DB와 함께 설계한다.                                                                        |
| 1           | 운영 저장소 전환     | DB 종류와 메타데이터 전환 범위 확정. 계정/Google 신원·권한·알고리즘 메타데이터·경기 기록의 DB 어댑터와 이전 절차 구현. 유일 제약·원자적 갱신·충돌·소유권을 검증한다. 코드 원문/경기 코드 사본은 파일로 유지하고 DB 참조와 함께 이전·복구한다. 맵 저장소의 DB 전환 포함 여부도 확정하되 파일 기반 맵 관리 기능을 재구현할 필요는 없다. |
| 2           | 단일 컨테이너 패키징 | 현재 서비스와 실행기·에디터 빌드·정적 자산을 포함한 이미지/기동 절차. 환경변수·비밀 설정 주입, 코드/DB/맵의 영구 볼륨, 비관리자 실행, 기동 확인·정상 종료를 검증한다. 개발용 .env/계정 데이터/키를 이미지·저장소에 포함하지 않는다. FE/BE 분리는 선행 조건이 아니다.                                                                  |
| 3           | 실제 배포 연결       | 운영 주소·DNS·TLS·VPN·방화벽·포트·프록시와 Host/Origin 경계를 확정한다. Google OAuth의 운영 콜백·쿠키·서버의 Google 통신 경로, 회사 계정 가입 범위, 관리자 초기 등록을 실제 환경에서 검증한다. 이미 구현한 OAuth를 새로 만드는 작업은 아니다. 직접 AI 중계는 배포 요구에서 제외한다.                                                  |
| 4           | 통합·부하·장애 검증  | 사내 브라우저/다른 PC에서 로그인·저장/재조회·플레이·관리자 제작/게시 전체 흐름 확인. 동시 경기의 CPU/메모리/프로세스 수·500ms 제한·종료/업로드 정리와 계정/경기 격리를 검증한다. 운영 자원에 맞는 허용 동시 실행 수와 서버 재시작 시 진행 경기 처리 기준을 정한다.                                                                    |
| 5           | 운영·복구 준비       | 상태 확인·자원/오류/시간 초과 지표·로그 수명, 업데이트/종료/되돌리기 절차를 준비한다. DB 메타데이터와 코드·경기 사본·맵 파일의 일관된 백업/복원을 검증하고 미참조 파일·임시 파일 정리 정책을 확정한다. 자산·폰트 출처/사용 조건과 운영 매뉴얼을 점검한다.                                                                             |
| 마지막 필수 | 개인정보 운영 준비   | 기능·배포 구성을 검증한 뒤 실서비스 개시 전에 수행한다. OAuth·계정·코드·경기·접속/디버그 로그의 항목/목적·보유/삭제·사용자 안내·권리 요청·백업 만료를 정리하고 계정 전체 삭제와 연관 파일/세션/경기의 정리를 구현·검증한다. 기존 미연결 AI 데이터가 있다면 이전/제외/정리 정책을 확정한다.                                            |

정리한 순서는 권장 순서다. 컨테이너 골격과 배포 네트워크 확인은 DB 전환과 병행할 수 있다. 단일 컨테이너에서 DB까지 함께 실행할지 또는 별도 저장소를 사용할지도 DB 선택 시 확정하며, 현재 단계에서 특정 DB 제품이나 외부 서비스를 정하지 않는다.

## 4. 고도화 항목의 현재 범위

- [FE 웹서버·BE 서버 분리](frontend-backend-separation-plan.md): 2026-11-15 배포 준비 범위로 전환했다. 더 이상 보류 항목이 아니며 [FE 요구사항](frontend-deployment-requirements.md)에 따라 진행한다.
- [여러 언어 지원](enhancement-backlog.md#2-여러-알고리즘-언어-지원): C#·C++·JavaScript·Python 대상. 사전 준비/컴파일·경기별 인스턴스 유지, 턴별 500ms 중단 후 같은 인스턴스 재호출을 언어별로 검증한 뒤 지원 구조를 확정한다. 턴마다 컴파일하거나 시간 초과마다 프로세스를 재시작하는 방식으로 바꾸지 않는다.

향후 기능을 추가하더라도 원문 파일 저장·사용자 소유권·독립적인 경기 실행·삭제 가능한 저장 계약을 유지하며, 개인정보 운영 준비는 실서비스 전 마지막 필수 단계로 남긴다.
