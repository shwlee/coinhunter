# 턴 경계의 화면 끊김 수정

2026-11-15. 3단계 이후 플레이 피드백을 반영했다. 3단계 변경과 함께 보관하며, 실제 운영 서버는 중지하지 않았다.

## 원인과 수정

기존 전달 경로는 엔진의 20ms snapshot을 운영 API가 60ms 간격으로 조회했다. 화면은 이동이 끝나도 다음 액션을 받지 못하면 끝점에 머물렀다. 수신할 때마다 렌더링 시계를 초기화해 네트워크 지연 변화가 같은 이동의 진행률을 소폭 뒤로 움직이게 할 수도 있었다.

- [Match](../backend/node/src/game/match.js)는 알고리즘 결과로 액션을 시작하거나 랜덤점프를 시작하면 다음 tick을 기다리지 않고 snapshot을 발행한다. 독립 턴·액션 시간·500ms 예산은 유지한다.
- 실행 관리자의 [snapshot 대기](../backend/src/CoinHunter.Execution.Host/Services/ExecutionManager.cs)는 새 sequence 또는 종료를 감지하면 대기자를 깨운다. 확인/Task 캡처를 같은 lock에서 처리해 누락된 알림을 방지하고 구독 취소는 해당 대기자에만 적용한다.
- 내부 GET의 선택적 afterSequence로 최신 상태를 기다린다. idle 대기는 최대 1초로 제한해 운영 API의 세션/소유자 확인·heartbeat가 계속 가능하다. 기본 GET과 공개 SSE 형식은 유지한다.
- 운영 API의 60ms 고정 대기를 제거했다. 구독 대기용 HTTP 연결 풀을 시작/중지/검사 풀과 분리해 SSE가 제어 요청의 연결을 점유하지 않게 했다. 기존 인증·소유권·SSE 수락 한도와 쓰기 기한을 유지한다.
- [GamePresentation](../frontend/public/game-presentation.js)은 확인된 snapshot을 최대 64개 보관하고 **표시만 40ms 지연**시킨다. 단조 증가하는 렌더 시계로 snapshot 사이를 표시하며 늦거나 중복된 sequence는 거부한다. 새 게임에서 초기화하고 최종 결과는 즉시 확정한다.
- 표시 버퍼는 다음 방향을 예측하지 않는다. 실제 알고리즘 계산 대기·패널티·벽 충돌·점프 등의 상태를 유지하고 엔진의 진행 속도·점수·로그를 변경하지 않는다.

## 로컬 브라우저 측정

[원시 결과](benchmarks/game-motion-2026-11-15.json), `npm run backend:test:motion`으로 재현한다. 테스트 계정·별도 서비스·기본 샘플 2개·현재 코드의 실제 렌더링 sample을 사용한다. 12×10 변경 전 자료는 직전 로컬 진단의 화면 보간식 추적 결과다. 한 번의 로컬 비교이며 OS/네트워크/알고리즘에 대한 최대 지연 보장은 아니다.

| 항목                                   |   수정 전 12×10 |  수정 후 12×10 |  수정 후 20×16 |
| -------------------------------------- | --------------: | -------------: | -------------: |
| snapshot 수신 간격 중앙값              |          62.3ms |         30.8ms |         30.9ms |
| 새 이동 첫 snapshot의 경과 시간 중앙값 |          30.0ms |         0.52ms |         0.03ms |
| 턴 경계 정지 중앙값                    |  3프레임 ≈ 50ms | 1프레임 ≈ 17ms | 1프레임 ≈ 17ms |
| 턴 경계 정지 최대                      | 6프레임 ≈ 100ms | 2프레임 ≈ 33ms | 2프레임 ≈ 33ms |
| 같은 이동의 진행률 역행                |             6회 |            0회 |            0회 |

두 맵에서 화면 프레임 간격 중앙값은 약 16.7ms다. 진짜 계산 시간과 tick 감지 지연은 남아 있으며 이를 시각적으로 계속 이동하는 가짜 액션으로 대체하지 않는다.

## 검증과 적용

- 표시 시계/지터·확인된 액션·실제 thinking·초기화/최종 결과·메모리 상한 Node 검사 4건 추가. 엔진 시험에 액션 즉시 snapshot 발행 확인을 추가했다.
- Node 전체 **283건 통과**. 초회 병렬 실행에서 기존 레거시 파일 잠금 시험 1건에 Windows EPERM이 발생했으며, 해당 파일 단독과 전체 직렬 재검사는 통과했다. 이번 수정에서 그 레거시 잠금 코드는 변경하지 않았다.
- 닷넷 **48건**(계약 35/업무 13), 프로토콜 5건·분리 BE 통합 13그룹 통과. snapshot 대기자의 update/cancel/idle/terminal 동작을 검사했다.
- 실제 브라우저의 로그인→작업실/검사/저장→테스트 iframe→맵 제작/게시→게임/카운트다운/SSE/결과, 3개 화면 너비 검사 통과.
- 4게임·16실행기·동시 SSE/검사/업로드/맵 조회와 수락 한도, 엔진/실행 관리 장애·회수·partial 기록/복구 검사 통과.

실행 중인 개발 서버가 DLL을 사용하므로 검증은 별도 빌드 경로에서 수행했다. [빌드 도구](../scripts/backend-tools.js)의 선택적 COINHUNTER_BUILD_ROOT는 dotnet의 ArtifactsPath와 테스트 실행 DLL 경로를 함께 변경한다. 정상 실행의 기본 경로·데이터·설정은 유지한다.

```powershell
$env:COINHUNTER_BUILD_ROOT = 'artifacts/motion-fix-dotnet'
npm run backend:test
npm run backend:test:motion
$env:COINHUNTER_BUILD_ROOT = $null
```

실제 플레이 서버에 반영하려면 실행 중인 서버를 정상 종료한 뒤 `npm start`로 다시 빌드/시작한다. 이전 빌드로 구동 중인 BE에는 소스 수정만으로 반영되지 않는다. 이 작업에서 사용자의 서버를 종료하거나 실제 계정/코드·Google 설정을 변경하지 않았다.
