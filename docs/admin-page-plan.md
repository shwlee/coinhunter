# 관리자 페이지 작업 계획

- 상태: 관리자 진입·권한, 사용자 관리, 맵 제작·게시·노출·옵션, 샘플 복사·맵 복제·표시 순서·대칭 랜덤 생성·int[] 전송 구현. 전역 정책은 후속 작업이다.
- 범위: 최초 논의한 플레이어(사용자) 관리, 게임 옵션 관리, 게임맵 생성·편집·게시.
- 관련 문서: [전체 계획](implementation-plan.md), [파일 기반 맵 관리](map-files.md), [맵 제작·편집 계획](map-editor-plan.md), [맵 관리 계획](map-management-plan.md), [작업 체크리스트](work-checklist.md).

## 진입과 권한

로그인한 관리자에게 홈·게임 플레이·알고리즘 작업실의 공통 계정 헤더에 관리자 페이지 버튼을 표시하고 `/admin`에서 사용자·옵션·맵 관리 화면으로 이동한다. 로그인하지 않은 요청은 로그인으로 보내고 일반 사용자의 페이지 및 쓰기 API 접근은 서버에서 403으로 거부한다. 초기 관리자는 저장소에 이메일을 넣지 않고 로컬 부트스트랩 명령으로 계정 데이터에 등록한다. 실제 Google 인증 도입 시 인증된 계정 식별자와 저장된 관리자 권한의 연결을 검증한다. 화면에서 메뉴를 숨기는 것만으로 권한을 처리하지 않는다.

## 화면별 작업

### 1. 사용자 관리

- 계정 목록에서 이메일, 역할, 이용 상태를 확인하고 검색·필터링한다.
- 관리자가 이용 중지·해제와 사용자/관리자 역할 변경을 수행한다. 변경 즉시 서버의 권한 검사와 세션·진행 중 경기 처리에 반영한다.
- 자기 계정 또는 마지막 활성 관리자를 실수로 중지·강등해 관리 기능을 잃지 않도록 서버 규칙과 확인 화면을 둔다.
- 비밀번호나 Google 계정 자체는 이 화면에서 관리하지 않는다. 코드 원문과 개인 경기 기록을 관리자 목록에 노출하지 않는다.

### 2. 맵 관리에 통합한 게임 옵션

- 맵 관리 목록의 게임 옵션 모달에서 `settings`의 액션 시간, Hurry Up 전환 시간, 아이템 최초 출현·주기·효과 지속량, Hurry Up 코인 소멸 간격, BlackMatter·벽 파괴 주기를 편집한다. 단위·허용 범위·현재 값을 표시하며 기본 샘플은 조회만 허용한다. 아이템 지속량은 신발·점프의 턴 수, 망치의 벽 파괴 횟수, x2의 코인 횟수에 공통 적용한다. 독립 게임 옵션 진입 메뉴는 제거한다.
- 사용자가 경기 시작 화면에서 고를 수 있는 옵션과 관리자만 고정하는 옵션을 분리한다. 공통 허용 정책이나 기본값이 필요하면 별도 서버 설정 모델과 저장 API를 정의한 뒤 화면에 연결한다. 맵별 설정과 전역 설정을 암묵적으로 혼합하지 않는다.
- 옵션 저장은 유효성 검사를 거친 새 맵 초안/게시 버전 또는 별도 정책 버전으로 반영한다. 이미 진행 중인 경기는 시작 당시 옵션을 유지한다.

### 3. 게임맵 관리

- 별도 제작 화면에서 새 맵 생성, 편집, 미리보기, 초안 저장·불러오기를 제공한다. 맵 관리 목록에서 게시·비활성화·경기 옵션·표시 순서를 관리하고 선택한 맵의 편집기로 바로 이동한다. 샘플 복사와 최신 초안 복제는 새 ID의 미게시 초안을 만든다. JSON 가져오기·내보내기도 편집 화면에서 제공한다.
- 가로·세로 크기를 설정해 빈 맵을 만들고 벽과 코인을 배치·삭제한다. 대칭 옵션을 켜면 편집 한 번에 상하·좌우 대칭 위치를 함께 갱신하며 중앙축의 중복 위치는 한 번만 처리한다. 네 모서리 시작점을 보호하고 맵 밖 경계는 기존 게임 규칙을 유지한다.
- `int[]` 가져오기·내보내기를 제공한다. 열·행과 배열을 받아 길이·타일·시작점을 검사하고 기본 옵션의 미저장 새 맵으로 연다. 대칭·도달 가능성·코인 존재는 문제 위치로 안내하고 게시 시 강제한다. 숫자 배열·C# 배열 복사/다운로드를 제공하며 전체 맵 JSON은 이름·옵션까지 보존할 때 사용한다.
- 랜덤 생성은 대칭을 기본 규칙으로 하고 결과를 편집 가능한 초안으로 표시한다. 게시 전에 코인 존재, 시작점 공정성, 모든 필수 공간의 도달 가능성 등을 검증한다. 배치할 수 없으면 실패 이유를 보여주고 기존 초안은 보존한다.
- 저장은 현재 초안 리비전을 조건으로 수행해 다른 관리자 창의 수정 덮어쓰기를 막는다. 미게시 초안은 일반 사용자 맵 선택 목록에 나타나지 않고, 게시·비활성화는 진행 중인 경기에 영향을 주지 않는다.

## 구현 순서

1. **완료:** 관리자 진입·공통 레이아웃과 페이지/API 권한 검사를 연결한다. 기존 사용자 관리 API의 마지막 관리자 보호는 2단계에서 화면과 함께 재검증한다.
2. **완료:** 사용자 관리 화면의 검색·필터·이용 상태·역할 변경, 자기 계정·마지막 관리자 보호 및 세션 반영을 검증한다. 동시 수정은 이전 상태 비교로 충돌을 거부한다.
3. **완료:** [맵 제작·편집 계획](map-editor-plan.md)에 따라 별도 제작 화면에서 빈 게임판 생성, 코인·벽 배치, 선택적인 대칭 편집, 저장·불러오기를 구현했다. 초안 저장 API와 리비전 충돌도 이 단계에 포함한다.
4. **완료:** [맵 관리 계획](map-management-plan.md)에 따라 별도 목록, publish/hide, 게시 갱신, 특정 맵 편집 연결을 구현했다. 제작 화면에서도 저장된 초안의 게시·게시 갱신을 제공한다. 숨기기·다시 노출은 관리 목록에서 진행한다.
5. **맵별 옵션·복사·순서 완료:** 옵션 모달에서 새 초안으로 저장한다. 게시 갱신 후 새 경기에 적용하며 진행 중 경기는 보존한다. 샘플 복사·맵 복제와 전체 목록의 표시 순서 조정을 제공한다. 전역 정책은 후속 작업이다.
6. **JSON·int[] 전송·대칭 랜덤 생성 완료:** 편집 화면에서 크기·벽 밀도·코인 밀도·코인 점수를 설정해 연결된 대칭 초안을 생성한다. `int[]` 붙여넣기/파일 가져오기와 숫자·C# 배열 복사/다운로드를 제공한다.
7. 새 맵 생성 → 편집 → 저장 → 맵 관리에서 게시 → 사용자 선택 → 경기 시작을 브라우저에서 검증하고 권한·충돌·재시작 복원 테스트를 수행한다.

## 완료 기준

관리자가 브라우저에서 계정을 관리하고 게임 옵션을 설정하며 유효한 대칭 맵을 생성·게시할 수 있다. 일반 사용자는 관리자 데이터 수정 API에 접근할 수 없다. 게시된 맵과 설정은 서버 재시작 후에도 유지되고, 게시 전 초안이나 이후 수정은 이미 시작한 경기를 바꾸지 않는다.
