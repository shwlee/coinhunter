# 로컬 알고리즘 작업실

## 실행

`npm ci` 후 `npm start`로 실행하고 `http://127.0.0.1:3000/`을 연다. 진입 화면에서 알고리즘 작성 또는 게임 플레이를 선택한다. 시작 전에 CodeMirror 정적 자원을 자동 빌드한다. 실행 중 CDN이나 Google에 접속하지 않는다.

첫 진입 경로 `/`는 비로그인 사용자를 `/signin`으로 보내고, 로그인 후에는 홈 화면을 제공한다. 가입은 `/signup`, 게임은 `/game`, 작업실은 `/editor`다. 기본 로그인/가입 완료 후 홈으로 이동하며, 로그인 주소에 내부 목적지가 지정된 경우에는 해당 화면으로 돌아간다. 첫 로그인은 자동 가입으로 처리하며 별도 비밀번호 등록은 없다. 로그인 화면에서 게스트 게임으로 진입할 수 있다. 게스트가 `/editor`에 직접 접근하면 서버가 로그인 화면으로 이동시킨다. 목적지는 내부 경로만 허용한다.

목업 로그인에서 초기 관리자 또는 개발용 직원 계정을 선택한다. 최초 로그인 시 계정을 자동 생성하고, 계정·알고리즘·경기 기록 메타데이터는 `data/accounts/store.json`에, 코드 원문은 `data/accounts/sources/*.js`에 저장한다. 두 영역은 Git에서 제외된다. 브라우저가 달라도 같은 목업 계정을 선택하면 같은 코드를 열 수 있다.

현재 로그인은 실제 Google 계정 소유를 증명하지 않는 로컬 개발 전용이다. HTTP 서버와 목업 로그인 모두 루프백 환경에 한정한다. `NODE_ENV=production`에서는 기본적으로 목업이 꺼지며 목업을 강제로 켜면 서버 생성이 실패한다. 실제 Google 인증은 배포 전에 구현·검증해야 한다.

## 설정

`.env.example`은 설정 참고 파일이다. 현재 서버는 `.env` 파일을 자동 로딩하지 않으므로 PowerShell 환경 변수로 지정한다.

```powershell
$env:AUTH_MODE = 'mock'
$env:INITIAL_ADMIN_EMAIL = 'vactormanbear@gmail.com'
$env:MOCK_COMPANY_DOMAIN = 'company.test'
npm start
```

- `AUTH_MODE`: `mock` 또는 `disabled`. 생략하면 개발에서는 mock, production에서는 disabled.
- `INITIAL_ADMIN_EMAIL`: 초기 관리자 이메일. 기본 `vactormanbear@gmail.com`. 관리자 계정은 회사 도메인 예외다.
- `MOCK_COMPANY_DOMAIN`: 개발용 직원 두 계정의 도메인. 기본 `company.test`. 실제 Workspace 허용 도메인을 검증하는 설정은 아니다.
- `ACCOUNTS_FILE`: 사용자·알고리즘·경기 기록 메타데이터 파일 경로. 상대 경로는 실행 디렉터리 기준.
- `ACCOUNT_STORE_ADAPTER`: 현재는 `file`만 지원. 저장 경계와 DB 교체 조건은 [저장 어댑터](storage-adapters.md)를 참고.
- `ALGORITHM_SOURCE_DIR`: 코드 파일 저장 경로. 생략하면 `ACCOUNTS_FILE`과 같은 디렉터리의 `sources/`.
- `PORT`: 기본 3000.

초기 관리자 설정은 해당 이메일이 처음 가입하고 관리자 기록이 아직 없을 때만 적용된다. 설정 변경으로 기존 관리자 권한을 자동 회수하거나 기존 일반 사용자를 승격하지 않는다. 이후 변경은 작업실의 사용자 관리에서 처리한다. 개발용 로그인 선택지는 초기 관리자·developer·tester 세 계정이다.

## 작성과 테스트

- 작업실의 불러오기 버튼을 누르면 모달에서 계정에 저장된 코드 또는 로컬 `.js` 파일을 선택한다. 모달을 닫으면 편집 중인 코드가 유지되고, 코드를 열면 편집기에 반영된다. 코드 편집기 오른쪽의 AI 아이콘으로 사이드바를 접고 펼치며 동작은 툴팁으로 표시한다. 사이드바는 처음에 펼친 상태이며 데스크톱에서는 왼쪽 그립을 드래그하거나 방향키로 폭을 조절할 수 있다. 조절한 폭은 브라우저에 저장한다. 좁은 화면에서는 편집기 위에 배치하며 가로 크기 조절은 숨긴다. 편집기는 CodeMirror의 구문 강조·줄 번호·들여쓰기·괄호 처리·undo/redo와 검색을 제공한다.
- 코드 검사와 테스트 준비는 구문·금지 구문·선언되지 않은 이름을 분석한 뒤, 실제 게임과 같은 QuickJS 환경에서 생성자·필수 메서드·initialize·getName·moveNext를 실행한다. 구문 오류와 선언되지 않은 이름은 해당 줄을 강조하고 줄·열 위치를 표시한다. 실행 오류는 실패한 단계와 샘플 호출을 표시한다. 검사 중 코드가 변경되면 이전 검사 결과로 테스트를 시작하지 않는다.
- 실행 검사는 기본 12×10/20×16 샘플맵과 플레이어 번호 4개를 조합한 8개 인스턴스에서 각 3회 이동(총 24회)을 수행한다. 인스턴스 내 상태를 유지하며 아이템 유무와 코인이 없는 맵도 확인한다. `-1`은 유효한 반환값이며 예외·잘못된 반환값·호출별 500ms 초과는 검사 실패이다. 메모리 제한은 실제 게임과 같은 32 MiB이다. 모든 입력·분기·장시간 실행의 정상 동작을 보장하지 않으므로 테스트 플레이를 병행한다.
- 검사는 별도 임시 프로세스에서 수행하며 계정당 1건, 서버 전체 2건까지 허용한다. 전체 검사 대기는 30초로 제한하고 검사 프로세스를 정리한다. 실제 경기의 알고리즘 프로세스나 경기 기록에는 영향을 주지 않는다. 코드 파일의 크기 제한은 추가하지 않는다.
- 실행 로그에 출력 지우기와 자동 스크롤 켜기/끄기를 제공한다. 지운 이벤트는 같은 경기의 다음 상태 전송에서 다시 표시하지 않으며 새 경기에서는 다시 기록한다. 화면에는 최근 40개 이벤트를 표시한다.
- 테스트에 전달한 코드와 현재 편집 코드가 다르면 안내를 표시한다. 실행 중 코드 변경은 다음 테스트에 적용되며 현재 경기에는 반영되지 않는다.
- 작업실 첫 진입은 새 알고리즘 문서로 시작하며 `initialize`, `getName`, `moveNext`의 내용이 빈 템플릿을 넣는다. `새로 만들기`는 현재 코드와 저장 항목 연결을 비우고 같은 템플릿을 넣는다. 파일 가져오기는 새 미저장 문서를 만든다.
- 편집기 상단에 현재 코드가 새 문서·내 PC 파일·계정 저장 코드 중 어디에서 왔는지와 원본 이름을 표시한다. 저장 버튼은 코드 편집기 아래에 둔다. 저장 모달에서 현재 코드의 출처와 덮어쓸 원본 이름을 확인하고 기존 항목 덮어쓰기 또는 새 알고리즘으로 저장을 선택하며, 현재 편집 코드를 `.js` 파일로 내보낼 수도 있다. 파일 내보내기는 서버 저장을 수행하지 않는다. 새 문서와 로컬 파일은 새 항목 저장만 제공한다. 문법 오류가 있는 작업 중 코드도 보관할 수 있지만 실행 전에는 검증한다.
- 다른 창의 저장과 충돌하면 409 오류를 표시하고 편집 내용을 보존한다. 별도 코드 히스토리나 자동 저장은 없다.
- 편집기 도구 모음의 확대 버튼은 코드 영역을 화면 크기로 펼친다. 같은 버튼이나 Esc로 원래 배치로 돌아오며, 테스트 화면으로 전환할 때 확대 상태를 해제한다. 편집 중인 코드와 AI 사이드바 너비는 그대로 유지된다.
- 테스트 준비는 편집 코드를 같은 출처 테스트 패널에 전달한다. 맵과 시작 위치만 선택하며 혼자 실행한다. 캐릭터는 시작할 때마다 플레이 가능한 캐릭터 중 무작위로 배정한다. 이후 편집은 실행 코드에 영향을 주지 않는다.
- 작업실 테스트에서는 파일·저장 코드·더미·대결·기믹·캐릭터 선택과 카운트다운·순위·포디엄·결과 분석 화면을 표시하지 않는다. 실행·중단과 디버그 출력, 종료 점수만 제공한다. 아이템과 HurryUp은 선택한 맵의 기존 설정을 따른다. 이전 알고리즘 대결과 전체 결과 분석은 별도 게임 플레이 화면에서 이용한다.
- 테스트는 기존 게임 화면·서버 엔진·SSE·실행 프로세스를 그대로 사용한다. iframe과 부모는 출처·송신 창을 검사하여 코드 사본과 준비/경기 상태만 교환한다. 별도 축소 엔진은 없다.
- `debug.print` 출력은 테스트 패널에 표시된다. 종료하면 맵·위치 설정으로 바로 돌아가며 코드·설정은 유지된다. 테스트의 재연결 ID는 일반 게임과 별도로 저장한다.
- 편집기 하단의 플레이 아이콘으로 현재 코드 테스트에 진입하고 테스트 화면의 뒤로가기 아이콘으로 편집기에 돌아온다. 새로고침·이탈 시 저장된 알고리즘의 코드가 저장 시점과 달라졌으면 브라우저 경고를 제공한다. 새 문서는 저장 전까지 이 경고를 띄우지 않는다. 작업실 안에서 다른 코드를 열거나 새 문서를 만들 때는 현재 문서를 열거나 만든 뒤 코드가 실제로 변경된 경우에만 미저장 변경 확인을 띄운다. 이탈만으로 경기를 종료하지 않으며 기존 재연결 정책을 유지한다. 명시적 중단·로그아웃·이용 중지에서는 경기를 종료한다.

## AI 범위

AI 영역에서는 근처 코인·고액 코인·코인 밀집·아이템 4종 획득·아이템 4종 회피 중 최대 3개를 순서대로 선택한다. 템플릿 설명은 이름의 툴팁에 표시한다. 선택 후 드래그 또는 화살표로 우선순위를 바꿀 수 있으며, 1~3순위에 가중치 5·3·1이 자동 배정된다. 개별 가중치 입력은 없다. 회피 템플릿은 해당 아이템 칸을 경로에서 제외하고, 코인 밀집 템플릿은 도달 가능한 목표 코인의 주변 두 칸 안에 있는 코인 수를 평가한다. 현재는 이 순서와 가중치로 도달 가능한 코인과 아이템의 목표 점수를 계산하는 JavaScript 코드를 로컬에서 생성하고 서버의 실행 전 검사를 거친다. 자유 입력은 아직 해석하거나 외부 AI로 전송하지 않는다. 결과 적용은 명시적 버튼으로 수행하며 편집기의 한 번의 undo로 되돌릴 수 있다. 요청 후 편집이 변경되면 덮어쓰기를 확인한다. 취소한 요청의 늦은 결과는 무시한다.

실제 AI 제공자·중계·비밀키·네트워크 경로가 정해지지 않았으므로 자연어 생성·수정 완료로 간주하지 않는다.

## 계정·관리·저장

- 세션은 서버 메모리의 임의 토큰과 HttpOnly/SameSite 쿠키로 연결하며 유효 기간은 8시간이다. 서버 재시작 시 재로그인한다.
- 계정별 코드 조회·변경·저장된 코드 경기 실행을 검사한다. 로그인 사용자는 계정 단위로 동시 경기 한도를 적용한다.
- 관리자는 사용자 이용 중지/허용과 역할 변경을 수행한다. 마지막 활성 관리자는 해제할 수 없다.
- 이용 중지 시 해당 계정의 모든 세션을 폐기하고 경기를 중단하며 열린 SSE 연결을 닫는다. 해제 후 새 로그인이 필요하다.
- 로그아웃은 현재 세션을 폐기하고 해당 계정의 진행 중 경기를 종료한다.
- 파일 저장은 단일 서버 프로세스의 직렬 갱신·임시 파일 교체를 사용한다. 로그인 계정의 종료 경기와 당시 알고리즘 코드 사본은 메타데이터와 분리된 `.js` 파일로 기록한다. 계정 데이터 접근은 [저장 어댑터](storage-adapters.md)로 분리했다. 저장소를 여러 서버 프로세스가 동시에 공유하는 운영은 지원하지 않는다. 운영 배포 전에 DB 이전 여부를 결정한다.
- 백업은 서버를 종료한 후 메타데이터 파일과 코드 파일 디렉터리를 함께 복사한다. 복원도 서버 종료 상태에서 같은 경로에 배치한다. 유실된 관리자 복구가 필요하면 데이터 파일을 먼저 백업하고 오프라인 관리 절차로 처리한다.

## 검증

`npm test`: 기존 엔진과 함께 계정별 접근, 저장 충돌, 재로그인·파일 재로드 후 데이터 유지, 계정 단위 경기 한도, 이용 중지·세션 폐기, 마지막 관리자 보호를 검사한다.

`npm run test:authoring`: 목업 로그인→편집·저장→목업 생성 적용/undo→맵·위치 선택→단독 테스트→종료, 임의 캐릭터의 유효성, 작은 화면, 별도 브라우저 세션의 저장 목록을 검사한다.

`npm run test:browser`: 기존 게스트 플레이·이전 코드 대결 회귀 검사. 스크린샷은 `artifacts/`에 생성한다.

## 배포 전 남은 작업

실제 Google OIDC와 사용자 식별자 `sub` 연결, 회사 Workspace 제한과 관리자 예외 검증, OAuth 클라이언트·콜백·HTTPS·프록시 설정, 실제 AI 생성/수정 어댑터, 운영 DB·세션 저장소·백업 정책을 완료해야 한다. 목업 이메일을 실제 Google 신원으로 자동 신뢰하여 계정을 합치지 않는다.
