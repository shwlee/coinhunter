# 프롬프트 분량 축소 — 새 대화·후속 요청 작업 계획

- 작성일: 2026-11-14
- 상태: 1단계 규약 분리·내용 버전 구현 완료. 2~5단계는 미구현이며 프롬프트 생성 방식·UI는 아직 기존 동작이다. [구현 계약](prompt-contract.md).
- 목표: 처음에는 필요한 규약을 전달하고 같은 외부 AI 대화의 후속 요청에서는 중복 규칙·예제를 생략한다. 사용자가 선택한 원문과 요청은 임의로 줄이지 않는다.
- 관련: [전체 프롬프트 개선 계획](prompt-authoring-improvement-plan.md), [개선 아이디어](prompt-first-improvement-ideas.md), [현재 사용법](local-authoring.md).

## 1. 적용 원칙

복사·생성 횟수는 AI가 규약을 받았다는 증거가 아니다. 게임에서는 외부 대화의 실제 상태를 알 수 없으므로 자동으로 후속 요청으로 전환하지 않는다. 사용자가 `새 AI 대화에서 시작` 또는 `같은 AI 대화에서 계속`을 선택한다. 새 AI 대화·다른 서비스·불확실한 문맥에서는 전체 규약을 제공하는 모드를 사용한다.

대화 모드는 신규 작성/전략 개선/오류 수정이라는 작업 목적과 별개다. 같은 대화에서 새 전략을 만들 수도 있고, 새 대화에서 기존 코드를 수정할 수도 있다. 현재 `코드 포함` 여부로 신규/수정을 구분하는 로직이 후속 요청을 무조건 새 알고리즘으로 해석하지 않게 한다.

프롬프트 생성 버튼을 눌렀을 때만 본문을 만들고 미리보기는 항상 표시한다. 복사와 전체 선택은 생성된 본문을 사용한다. 모드·전략·추가 요청·포함 코드가 바뀌면 이전 본문은 보존하되 다시 생성하기 전 복사를 막는다.

## 2. UI와 포함 내용

전략 영역 위에 짧은 두 선택을 배치하고 기존 `현재 코드 포함` 선택은 유지한다. 개별 규칙·예제를 켜고 끄는 여러 체크박스, 제공자·모델·외부 대화 URL 입력은 추가하지 않는다.

```text
대화 방식  [새 AI 대화에서 시작] [같은 AI 대화에서 계속]
전략 선택 · 우선순위 · 추가 요청
현재 코드 포함 [선택]
[프롬프트 생성] [생성된 코드 가져오기]
미리보기 · 모드/포함 내용/글자 수 · 복사
```

| 포함 내용                                 | 새 AI 대화에서 시작                                               | 같은 AI 대화에서 계속     |
| ----------------------------------------- | ----------------------------------------------------------------- | ------------------------- |
| 작성용 전체 게임 규약                     | 포함                                                              | 생략                      |
| 규약 유지 지시·짧은 필수 제한 요약        | 전체 규약에 포함                                                  | 포함                      |
| 규약 내용 버전                            | 포함                                                              | 포함                      |
| 기준 예제                                 | 완성 전략 대신 필요 최소 골격을 검토. 코드 수정 시 중복 예제 제외 | 제외                      |
| 선택한 전략·우선순위·이번 추가 요청       | 포함                                                              | 포함                      |
| 현재 코드                                 | 사용자가 선택한 경우 포함                                         | 사용자가 선택한 경우 포함 |
| 완성된 단일 파일·단일 코드 블록 출력 지시 | 항상 포함                                                         | 항상 포함                 |

새 대화의 전체 규약은 문서 원문 전체를 뜻하지 않는다. 알고리즘이 올바르게 동작하는 데 필요한 API·게임 규칙·실행 제한을 빠짐없이 포함한 작성용 규약이다. 현재 전체 문서/완성 예제를 단순 절단하지 않고 중복·운영 설명을 정리한다.

후속 요청의 짧은 요약에는 현재 JavaScript·필수 메서드/방향 계약 유지, 동기 실행·호출별 제한·금지 호스트 기능 등 꼭 유지할 조건을 담는다. 값은 공통 정책에서 얻고 별도로 하드코딩하지 않는다. 전체 타일·아이템 설명과 기준 예제는 반복하지 않는다. 내용 버전 표시는 문맥 확인용이며 AI가 실제로 해당 규약을 기억한다는 보장이 아니다.

## 3. 코드 포함과 작업 목적

- 기본값은 기존처럼 코드 제외다. 빈 기본 골격만 있으면 코드 포함을 비활성화한다.
- 새 AI 대화에서 기존 코드 수정을 요청하려면 수정 대상 코드를 포함한다. 작성 목적 선택 기능과 연결할 때 원문 없는 새 대화의 수정 요청은 코드 선택을 안내한다.
- 같은 AI 대화에서 AI가 방금 작성한 코드에 변경을 요청할 때는 코드 없이 요청할 수 있다. 이때 본문은 이전 대화의 코드를 기준으로 요청하며 무조건 새 알고리즘을 만들라고 지시하지 않는다.
- 사용자가 게임에서 코드를 직접 수정했거나 다른 코드를 불러왔다면 최신 원문 포함이 필요함을 짧게 안내한다. 제외한 코드를 자동 첨부하거나 매 편집마다 확인 모달을 띄우지 않는다.
- 코드 제외 상태의 코드 편집은 기존처럼 본문을 재조합하지 않는다. 원문을 제외하는 선택의 의미를 설명하고 포함된 코드가 변경된 경우에만 해당 원문을 생성 입력 변경으로 취급한다.
- 향후 오류 수정·결과 개선에서는 대상 코드/진단/경기 스냅샷 일치 규칙을 먼저 적용한다. 후속 요청이라는 이유로 다른 원문이나 오래된 오류를 섞지 않는다.

## 4. 상태 전환과 규약 변경

| 상황                                            | 처리                                                                                      |
| ----------------------------------------------- | ----------------------------------------------------------------------------------------- |
| 작업실 최초 진입·새 문서·다른 알고리즘 불러오기 | 새 대화 모드로 초기화. 이전 미리보기·생성 스냅샷을 비움                                   |
| 생성·복사 성공                                  | 현재 모드 유지. AI가 읽었다고 표시하거나 자동 전환하지 않음                               |
| 사용자가 후속 요청 선택                         | 전체 규약 생략 안내. 기존 본문이 있으면 재생성 필요 상태로 전환                           |
| 후속에서 새 대화로 복귀                         | 전체 규약 포함 모드로 전환하고 재생성 요구. 원문·전략은 임의 초기화하지 않음              |
| 코드 가져오기·명시적 적용·같은 문서 저장        | 대화 모드를 자동 초기화하지 않음. 현재 코드 포함 여부와 실제 문서 변경에 따라 재생성 판단 |
| 규약 조회/재조회에서 내용 버전 변경 확인        | 새 대화/전체 규약 모드로 복귀하고 다시 전달하도록 안내. 편집 코드는 유지                  |
| 규약 조회 실패·세션 만료                        | 후속 모드로 우회하지 않고 오류·재시도 제공                                                |
| 복사 대기 중 모드·문서·입력 변경                | 이전 요청의 늦은 복사 성공 안내를 폐기. 새 본문 생성 후 다시 복사하도록 안내              |

규약의 내용 버전과 API 응답의 구조 버전(schemaVersion)을 구분한다. 규칙·제한·출력 계약 변경을 추적할 결정적 내용 버전을 서버에서 제공한다. 외부 대화의 규약 버전을 자동 조회하거나 대조했다고 주장하지 않는다. 첫 진입부터 사용자가 기존 외부 대화를 계속할 수는 있지만 현재 규약과 맞는 대화인지 스스로 확인하게 한다.

외부 AI가 문맥을 잃었거나 대화가 길어져 규칙을 따르지 못하면 사용자가 전체 규약 모드로 돌아갈 수 있다. 모드 선택과 상태는 현재 문서의 브라우저 메모리에 두고 대화 이력·사용자 코드·프롬프트 원문을 새로 DB/localStorage에 저장하지 않는다.

## 5. 단계별 구현 순서

### 1단계 — 작성용 규약 분리와 내용 버전: 완료

1. `src/algorithm-assistant/contract.js`에서 작성용 전체 규약·후속 요약·출력 지시·선택적 최소 골격을 구분한다. API·맵·아이템·제한과 공통 원본의 대응표를 정한다.
2. 실제 런타임 제한과 규약 내용을 대조하는 검사를 추가한다. 불필요한 중복을 줄여도 함수·방향·위치·아이템·제한·금지 API를 누락하지 않는다.
3. 내용 버전을 정의하고 기존 응답 구조와 클라이언트 검증의 호환/변경 방식을 정한다. 미연결 상태로 보관한 직접 API 모듈을 다시 활성화하지 않는다.

완료 기준: 전체 규약만으로 새 대화에서 요청을 이해할 수 있고, 후속 요약에 실제 정책과 다른 값이 없다. 규약 내용 변경이 감지되며 생성·조회에 외부 AI 호출이 없다.

### 2단계 — 두 모드의 프롬프트 구성

1. `public/prompt-builder.js`에 복사용 대화 모드를 추가한다. 전략 검증·순위·요청 원문 보존은 기존 공통 기능을 재사용한다.
2. 새 대화는 전체 규약, 후속 요청은 유지 지시·짧은 요약을 넣고 각 모드의 코드/예제 조건과 공통 출력 지시를 적용한다.
3. 코드 제외 후속 요청을 허용하고 의도 문장을 이전 대화의 코드에 맞춘다. 이 변경을 미연결 직접 API의 입력 검증 완화와 혼합하지 않는다.
4. 생성 결과에 모드·규약 버전·코드/예제 포함 여부·글자 수를 반환해 UI가 같은 결과를 표시하게 한다. 자동 절단·토큰 수 추정·비용 절감률 보장은 하지 않는다.

완료 기준: 동일 전략/추가 요청/코드 선택 조건에서 후속 본문이 전체 본문보다 짧고, 선택한 요청·원문은 그대로 보존된다. 출력 지시는 두 모드 모두 동일하다.

### 3단계 — 모드 선택 UI와 문서 수명 연결

1. `public/editor.html`, `editor.css`에 두 모드 선택과 짧은 설명을 추가한다. 선택은 키보드·보조 기술로 구분 가능하게 하고 좁은 화면에 맞춘다.
2. `public/prompt-assistant.js`의 생성 입력 비교와 스냅샷에 모드·규약 버전을 포함한다. 생성 횟수로 모드를 자동 변경하지 않는다.
3. `public/editor.js`의 새 문서·불러오기·코드 적용·저장 경계에 위 초기화 정책을 연결한다. 포함하지 않은 코드를 자동으로 복사하지 않는다.
4. 항상 보이는 미리보기에 현재 생성 본문의 모드·포함 내용·글자 수를 표시한다. 선택만 바꾼 상태와 실제 생성 결과를 혼동하지 않도록 재생성 안내를 제공한다.

완료 기준: 새 대화 → 복사 → 수동 후속 선택 → 재생성 → 복사 → 코드 가져오기·검사·테스트 흐름이 이어진다. 문서 전환·복사 실패·늦은 응답에서 이전 상태가 새 문서를 덮지 않는다.

### 4단계 — 전체/후속 전환·실패·회귀 검증

1. 신규/후속 × 코드 포함/제외 × 전략만/자연어만/둘 다를 조합해 본문 구성·요청 보존을 검사한다.
2. 전체 규약/예제의 후속 생략, 출력 형식 유지, 내용 버전 변경 시 전체 모드 복귀, 규약 오류·401·재시도와 복사 지연 경합을 검증한다.
3. 큰 원문·코드 블록 구분자·따옴표·한글을 잘라내지 않는지 확인한다. 코드 제외 후속 수정이 잘못된 신규 작성 지시로 바뀌지 않게 검사한다.
4. 기존 `prompt-assistant`, `code-import`, `prompt-workflow`, `authoring` 브라우저 검사를 확장한다. 실제 실행 검사·테스트 경기·저장·권한과 직접 API 종료 경로는 유지한다.

완료 기준: 새 대화와 후속 모두 복사→코드 가져오기→실행 검사→테스트가 동작하고 데스크톱·모바일에서 모드·입력·미리보기·액션이 구분된다. 대체 응답 검사와 실제 AI의 문맥 유지 검증은 별도로 기록한다.

### 5단계 — 실제 출력 평가와 사용법 정리

1. 동일 외부 대화에서 전체 규약 첫 요청 후 전략 변경·오류 수정의 짧은 요청을 사용하고 실제 AI 응답의 규칙·출력 준수를 확인한다. 사용자가 외부 AI를 조작하며 게임이 대신 로그인/유료 호출하지 않는다.
2. 새 대화에서 전체 규약으로 시작하는 경로와 문맥이 불확실할 때 전체 모드로 복귀하는 경로를 함께 평가한다.
3. 모드별 글자 수와 중복 내용 감소, 실행 검사·요청 반영을 기록한다. 외부 모델의 결과가 항상 같다고 가정하거나 짧아진 만큼 품질·비용이 보장된다고 표시하지 않는다.
4. `docs/local-authoring.md`와 검증 기록을 갱신한다. 실제 서비스 사용 조건·브라우저 복사 권한은 배포 환경에서 확인한다.

완료 기준: 처음/후속/규약 재전달의 선택 기준을 사용자가 이해하고 같은 요청에 불필요한 규칙·예제를 반복하지 않으면서 실행 가능한 결과를 얻을 수 있다.

## 6. 전체 계획과의 관계

이 문서는 [전체 개선 계획](prompt-authoring-improvement-plan.md)의 작성 흐름과 규약 정리 중 프롬프트 분량 축소를 구체화한 하위 계획이다. 구현 시 이 문서의 1~5단계를 하나의 선행 작업으로 진행하고, 전체 계획의 중복 작업은 다시 구현하지 않는다. 오류 수정 액션·결과 기반 개선·샘플 코드 UI 정리는 별도 남은 범위로 유지한다.

사용자 지시에 따라 1단계만 구현했다. 다음 단계는 별도 작업 지시 이후 진행하고, 기존 FE·BE 분리·다국어 보류와 개인정보 운영 준비의 마지막 필수 단계 원칙을 유지한다.
