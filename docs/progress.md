# 구현 진행 결과

## 2026-10-06 — 관리자 게임맵 제작 화면

게임 플레이의 내 저장 코드 드롭다운 옆에 편집 버튼을 추가했다. 선택한 알고리즘 ID를 `/editor?algorithmId=...`로 전달하고 작업실은 원문 파일과 메타데이터를 불러와 기존 저장 문서로 초기화한다. 이름·출처·저장 리비전을 복원하므로 덮어쓰기 저장이 가능하고 불러오기 직후에는 미저장 경고가 발생하지 않는다. PC 파일을 선택하면 저장 코드 선택을 해제해 다른 알고리즘을 편집하는 혼동을 막는다. 작업실 브라우저 검증으로 게임 선택 → 편집 진입 → 원문 일치·출처·덮어쓰기 상태를 확인했다.

게임 플레이의 파일 선택 후 다음 버튼에서 작업실과 동일한 실행 전 알고리즘 검사를 수행하도록 연결했다. 게스트·로그인 모두 사용하며 검사 중 중복 진행을 막는다. 실패하면 현재 단계에서 원인·가능한 오류 위치를 표시하고 다른 파일을 선택할 수 있다. 새 파일 선택 시 이전 검사 메시지를 초기화한다. 검사는 별도 검증 세션이며 실제 경기의 플레이어 인스턴스와 독립적이다.

후속 `/admin/maps` 관리 목록을 구현했다. 최신 초안 미리보기·통계, 이름 검색·상태 필터, 게시·게시 갱신·숨기기·다시 노출을 제공한다. 숨긴 맵의 게시 갱신은 비노출을 유지하고 다시 노출은 기존 게시 버전만 사용한다. 오래된 관리 상태로 요청하면 저장소에서 충돌을 거부한다. 목록의 편집 버튼은 선택한 맵을 바로 불러오며 편집 헤더에 게시 상태를 표시한다. 기본 샘플은 읽기 전용으로 구분한다.

자동 테스트 70개와 맵 관리·편집 브라우저 검증을 통과했다. 관리 검증 명령은 `npm run test:map-management`다. 맵별 경기 옵션·표시 순서와 샘플 복사는 후속 작업이다.

첫 에셋 배치 시 생성 안내가 비워지면서 페이지 높이와 하단 스크롤이 37px 줄어드는 현상을 수정했다. 안내·검사 영역의 높이를 확보해 짧아진 문구가 게임판 위치를 바꾸지 않게 했다. 브라우저 테스트에서 첫 코인·첫 벽·모바일 첫 배치 전후의 게임판 크기·위치·페이지 높이·스크롤이 동일함을 검증했다.

위 단계 이후 별도 게임맵 제작 화면 `/admin/maps/editor`를 구현했다. 관리자 페이지의 **맵 제작하기**로 진입하며 크기 입력·빈 게임판 생성, 점수별 코인·벽·지우개, 선택적인 상하좌우 대칭, 실행 취소·다시 실행, 확대·전체 보기, 초안 저장·목록 검색·불러오기를 제공한다.

맵 API는 서버에서 관리자 권한을 검사하며 신규 맵 기본 설정과 기존 맵 설정·게시 버전을 보존한다. 동시 수정 충돌은 409로 거부하고 화면의 편집 내용을 유지한다. 전체 자동 테스트 68개와 맵 제작 브라우저 테스트로 저장 복원·권한·충돌·40×30 맵·모바일을 확인했다. publish/hide와 맵별 옵션 화면은 후속 작업이다. 맵 브라우저 검증 명령은 `npm run test:maps`다.

## 2026-10-06 — 관리자 사용자 관리 화면

- `/admin`에 계정 목록·이메일 검색·권한/이용 상태 필터, 역할 변경·이용 중지/해제와 변경 결과 표시를 구현했다. 작업실의 임시 사용자 관리 영역은 제거했다.
- 본인 관리자 계정과 마지막 활성 관리자의 중지·강등을 보호한다. 여러 관리자의 계정 설정 변경이 겹치면 이전 상태 비교로 충돌을 거부한다.
- 이용 중지는 로그인 세션과 진행 중 경기를 종료한다. 역할 변경은 다음 요청의 서버 권한 검사에 반영된다.
- 전체 자동 테스트 65개와 작업실·관리자 브라우저 테스트 통과. 데스크톱·모바일 화면을 확인했다.

## 2026-10-06 — 초기 관리자 설정 분리

- 코드와 설정 예시에서 특정 관리자 이메일 및 로그인 시 자동 승격 규칙을 제거했다.
- 서버를 중지한 상태에서 `npm run admin:bootstrap -- <관리자 이메일>`을 한 번 실행해 관리자 역할을 로컬 계정 메타데이터에 기록한다. 기존 관리자 역할 데이터는 그대로 사용한다.
- 실제 배포에서는 같은 저장소 계약을 DB 어댑터로 구현하고, 목업 로그인 대신 인증된 계정 식별자로 역할을 조회해야 한다.

## 2026-09-27 — 첫 게스트 웹 경기

### 완료한 작업 단위

- 실행 환경 선정: Node.js 자식 프로세스 + QuickJS WASM. 호출별 500ms 중단과 동일 인스턴스 유지 검증.
- 기본 프로젝트: npm 실행·테스트 명령, 잠금 파일, CI 구성.
- 게임 엔진: 최대 4인 독립 턴, 방향·코인·점수·경기 종료, -1 현재 턴 패널티.
- 아이템: 신발·망치·x2·랜덤점프 기본 효과, 교체·횟수 차감·일괄 출현·배치 제외.
- 기믹: BlackMatter와 벽 파괴 옵션 분리, HurryUp과 아이템 독립 일정.
- 웹: 게스트 파일 업로드, 샘플 다운로드, 더미 선택, 맵, 점수판, 실행 출력, 종료 화면.
- 통신: 세션별 경기 접근, SSE 상태 전송, 새로고침 후 재연결, 종료 시 프로세스 정리.
- 문서: 실행 안내, 게임 규칙, API, 데이터·통신, 실행 검증 보고서.

### 검증

- `npm test`: 런타임·게임·서버 자동 테스트.
- `npm run verify:runtime`: 정상 → 500ms 무한 루프 중단 → 동일 PID·필드로 정상 복구.
- `npm run demo`: 4인 자동 경기에서 코인 소진으로 종료.
- `npm run test:browser`: 파일 업로드, 득점, 4인 표시, 재연결, 종료, 모바일 가로 넘침 없음, 시간 초과 후 복구 출력.
- 데스크톱·모바일 스크린샷을 실제로 확인. 생성 파일은 `artifacts/`이며 커밋에서 제외.
- 원격 CI는 구성만 추가했다. 실행 완료로 간주하지 않는다.
