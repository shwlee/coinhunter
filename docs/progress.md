## 2026-10-11 — 로그아웃 후 늦은 OAuth 인증의 재로그인 차단

재리뷰의 중간 1번을 수정했다. 로그아웃에서 브라우저의 OAuth 대기 state와 최신 인증 추적 정보를 먼저 무효화하고 세션을 폐기한다. 인증 대기·Google 코드 교환·계정 조회 중 어느 단계에서 로그아웃해도 이후 콜백의 최신 시도 검사가 실패하여 세션을 발급하지 못한다. OAuth 쿠키 경로를 `/api/auth`로 바꿔 로그아웃 요청에서도 브라우저 식별자가 전달되게 했고, 로그아웃 응답은 현재 경로와 이전 `/api/auth/google` 경로의 쿠키를 모두 삭제한다.

전체 자동 테스트 115개와 Google OAuth·관리자·로그아웃 브라우저 검증을 통과했다. 대기 중 콜백의 코드 교환 차단, 코드 교환 및 계정 조회 중 로그아웃, 다른 브라우저의 정상 완료, 로그아웃 뒤 새 로그인 보존, 늦은 응답의 쿠키 비변경과 기존 세션 무효화를 실제 HTTP 경합으로 검증했다. 브라우저에서도 현재·이전 경로 쿠키가 함께 제거되는 것을 확인했다. 외부 Google 응답은 대체했으며 실제 로컬 계정 데이터는 수정하지 않았다. 재리뷰의 중간 2번인 진행 중 요청 집계와 중간 3번인 알고리즘 목록 갱신 문제는 남아 있다.

## 2026-10-11 — OAuth 로그인 대기 슬롯 소진 방지

리뷰의 중간 3번을 수정했다. 로그인 시작을 직접 TCP 접속 IP별 1분 횟수와 미완료 인증 수로 제한한다. 기본 한도는 60회/분과 50개이며 환경변수 `GOOGLE_AUTH_STARTS_PER_MINUTE`, `GOOGLE_AUTH_FLOWS_PER_ADDRESS`로 조정한다. 쿠키 변경·전달 헤더 위조로 한도를 우회하지 못하며 IPv4-mapped IPv6는 같은 IPv4 주소로 처리한다. 대기 중과 소비 후 진행 중인 최신 인증을 함께 세고 완료·만료 시 슬롯을 회수한다. 인증 슬롯 전체 1000개와 요청 추적 주소 4096개 상한을 유지한다.

제한 초과 시 429와 `Retry-After`를 반환한다. 수용 여부를 검사한 뒤에만 기존 인증을 대체하므로 거절된 재시도는 이전 인증·세션을 유지한다. 승인된 콜백은 시작 횟수 제한과 별개로 완료할 수 있다. NAT·VPN·프록시에서 접속 IP를 공유하는 경우의 한도 조정과 신뢰 프록시의 원본 IP 처리 경계는 [Google 설정 안내](google-auth-setup.md)에 기록했다. 여러 IP의 분산 공격 방어는 운영 프록시 단계에서 별도로 다룬다.

전체 자동 테스트 111개, Google OAuth·관리자 브라우저 검증과 변경 코드 포맷 검사를 통과했다. 쿠키·전달 헤더 변경 반복 요청, 다른 접속 IP의 정상 시작, 거절된 재시도 뒤 기존 콜백 완료, 진행 중 인증의 슬롯 유지, 전체 슬롯 포화 중 기존 브라우저 재시도, 슬롯 회수·구간 만료, 실제 HTTP의 429 헤더, 추적 메모리 상한과 잘못된 설정 거부를 검증했다. 앞선 리뷰의 중간 1~3번은 수정 완료했으며 이후 재리뷰에서 발견한 알고리즘 불러오기 목록 갱신 문제는 남아 있다.

## 2026-10-11 — 관리자 등록 대상의 로그인 방식과 계정 ID 구분

리뷰의 중간 2번을 수정했다. `bootstrapAdmin`은 로그인 방식으로 대상을 구분하고, 같은 이메일의 다른 관리자를 대신 반환하지 않는다. 같은 방식의 중복 이메일도 자동 선택하지 않는다. `admin:bootstrap`은 Google 모드에서 기존 Google 신원 연결 계정만 선택하며 없는 계정을 목업 관리자로 생성하지 않는다. 기존 활성 관리자 보호는 유지한다.

관리자 접근 복구는 별도의 로컬 `admin:grant` 명령으로 처리한다. `--list --email`로 계정 ID·로그인 방식·역할·이용 상태를 확인하고 `--user-id`로 지정한 기존 활성 계정에 관리자 권한만 추가한다. 이용 중지 계정 활성화, 다른 관리자 강등, 이메일 기반 계정 병합은 수행하지 않는다. 공개 HTTP 권한 부여 경로는 추가하지 않았다. 관리자 사용자 목록과 변경 확인 창에도 로그인 방식과 계정 ID를 표시한다. Google subject·토큰은 표시하지 않는다. [사용 안내](local-authoring.md)에 명령과 복구 절차를 기록했다.

전체 자동 테스트 105개와 Google OAuth·관리자 목록 브라우저 검증을 통과했다. 같은 이메일의 목업 관리자와 Google 계정, 동일 제공자 내 중복 이메일, Google 계정 미등록, ID 지정 승격의 재실행, 잘못된 ID·없는 계정·이용 중지 계정 거부, 코드·경기 기록·기존 관리자 보존을 검증했다. 변경 코드 포맷과 diff 검사를 통과했으며 실제 로컬 계정 데이터는 변경하지 않았다. OAuth 요청 한도 소진과 알고리즘 불러오기 목록 갱신 문제는 남아 있다.

## 2026-10-11 — 이전 OAuth 콜백의 세션 덮어쓰기 방지

리뷰의 중간 1번을 수정했다. 같은 브라우저에서 새 로그인 시도를 시작하면 이전 대기·진행 중 시도를 대체하고, Google 검증 전후 및 세션 발급 직전에 최신 시도 여부를 검사한다. 새 시도의 취소·실패 이후에도 이전 인증 결과로 세션을 발급하지 않는다. 이전 콜백이 새 인증 쿠키를 지우지 않도록 OAuth 브라우저 쿠키는 최대 10분 유지한다. 완료된 시도의 서버 추적 정보는 정리하며 기존 state 일회성·nonce·PKCE·만료 검증은 유지한다. 상세 동작은 [Google 인증 전환](google-auth-plan.md)에 기록했다.

맵 API는 서버에서 관리자 권한을 검사하며 신규 맵 기본 설정과 기존 맵 설정·게시 버전을 보존한다. 동시 수정 충돌은 409로 거부하고 화면의 편집 내용을 유지한다. 전체 자동 테스트 68개와 맵 제작 브라우저 테스트로 저장 복원·권한·충돌·40×30 맵·모바일을 확인했다. publish/hide와 맵별 옵션 화면은 후속 작업이다. 맵 브라우저 검증 명령은 `npm run test:maps`다.
