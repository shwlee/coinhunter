# AI 공통 계약 — 1단계

- 상태: 공통 계약·입력/공개 데이터 검증·설정 해석 구현. 저장소·HTTP API·외부 제공자 호출은 아직 연결하지 않았다.
- 2단계 갱신: 저장 어댑터와 내부 세션 수명 연결을 추가했다. 설정은 작성 서비스에서 읽으며 `AI_ENABLED`일 때 내부 저장 계층을 준비한다. HTTP·외부 호출은 아직 없다. 아래 1단계 설명 중 미연결 상태는 작성 당시 기준이며 현재 저장 범위는 [AI 저장 문서](ai-storage.md)를 따른다.
- 소스: `src/ai/contracts.js`, `src/ai/config.js`.
- 기준: [AI 작업 계획](ai-scripting-plan.md), [개인정보 설계 조건](privacy-operations-plan.md).

## 연결과 소유권

화면 이름과 내부 제공자 ID는 Claude=`anthropic`, OpenAI=`openai`, Gemini=`gemini`다. 회사·개인 유형 필드는 없다. 연결 등록의 일반 메타데이터 입력은 `name`, `provider`, `credentialMode`, `defaultModelId`만 허용한다. 소유자·세션·키·비밀 참조·임의 API 주소는 해당 입력에 포함할 수 없다. API 등록 단계에서 별도로 받은 키는 자격 증명 저장소에만 전달한다.

`AiScope`는 인증 서비스가 검증한 내부 `ownerId`와 서버 내부 로그인 수명 식별자 `sessionId`다. 요청 본문의 소유자 값을 사용하지 않는다. `sessionId`는 브라우저 인증 쿠키 원문이 아닌 서버 내부 식별자를 사용하도록 2단계에서 인증 서비스 경계를 확장한다. 임시 연결은 같은 계정의 다른 로그인 세션에도 노출하지 않는다.

`AiConnectionRepository`는 소유자 범위의 목록·조회·등록·리비전 기반 수정·삭제, 내부 계정/세션 정리, 마지막 연결·모델 선택 보관을 제공한다. 영구 선택에 임시 세션 비밀을 저장하지 않는다. 조회 API는 `publicConnection`의 명시적 필드만 반환한다. 소유자·세션·자격 증명 참조·파일 경로와 향후 추가된 내부 필드는 자동으로 공개되지 않는다.

연결 상태 확인은 키 리비전과 함께 처리한다. 키를 교체하거나 삭제한 뒤 도착한 이전 결과는 연결을 갱신하지 않는다. 외부 확인 작업은 저장소 잠금 밖에서 수행하며, 확인된 새 키를 활성화하는 원자적 참조 변경이 실패하면 새 키만 정리하고 기존 연결을 유지한다. 삭제는 새 요청을 차단한 뒤 진행 요청 취소·참조 제거·자격 증명 정리를 조율한다.

## 자격 증명 저장소

`CredentialStore`는 `put`, `resolve`, `delete`, `deleteOwner`, `deleteSession`을 제공한다. `put`은 내부 비밀 참조를 반환한다. `resolve`는 소유자/세션을 확인한 서버의 외부 인증 경로에서만 사용하며 HTTP 조회 API로 노출하지 않는다.

`session` 모드는 임시 메모리 보관이며 기본값이다. `stored` 모드는 암호화된 영구 저장이다. 저장 허용 설정이 켜져 있어도 암호화 키와 저장소가 준비되지 않으면 제공하지 않는다. 키 교체·삭제·임시 만료 처리는 2단계 구현 대상이다. 이메일·Google 신원·API 키를 일반 연결 메타데이터에 복제하지 않는다.

## 제공자와 모델

`AiProvider`는 `checkConnection`, 커서 기반 `listModels`, `generate`를 구현한다. 모델 목록 조회와 해당 모델의 생성 권한은 별개다. 모델 선택은 연결에서 실제 조회한 목록과 서버 허용 정책을 모두 통과해야 한다. 목록 조회를 지원하지 않거나 일부 모델만 제공되는 경우의 처리는 3단계에서 제공자별로 확정하며 모델을 임의로 발명하지 않는다.

생성에는 모델, 서버 규약, 수정용 코드 사본 경로, 취소 신호, 출력 파일 경로를 전달한다. 모델 이름 문자열의 형식 검사만으로 실제 모델을 승인하지 않는다. 어댑터는 파일에 후보를 기록하고 설명·사용량·완료 사유를 반환한다. `truncated`와 `refused`를 성공 코드로 처리하지 않는다. 기존 게임 실행·계정 코드 저장을 어댑터가 직접 호출하지 않는다.

외부 SDK 오류는 인증 오류·모델 사용 불가·네트워크·한도·입력 초과·응답 오류 등 `AI_ERROR_CODES`로 정규화한다. 외부 오류 원문·헤더·요청·토큰을 사용자 응답이나 로그에 그대로 전달하지 않는다. 인증 확인도 외부 호출이므로 시간·동시성·시작 횟수 제한은 후속 서비스 계층에서 적용한다.

## 요청 수명과 파일

`AiRequestService`는 입력 예약·파일 첨부·시작·상태·SSE·후보 파일 열기·취소와 계정/세션/연결별 취소·서버 종료를 제공한다. 수정 코드는 기존 파일 업로드의 서버 소유 사본을 사용한다. 경로는 서버 내부 계약이며 HTTP 요청에서 지정하지 않는다.

상태는 `prepared → queued → generating → validating → completed/validation_failed`이며 실패·취소·만료를 별도로 표시한다. 준비 TTL은 생성 시점부터, 요청 제한 시간은 시작 승인부터 큐 대기·외부 생성·검사 전체에 적용한다. 후보 TTL은 후보 생성과 검사 완료부터 적용한다. 진단이 있는 검사 실패 후보도 같은 수명과 개수 한도로 보관한다.

공개 상태가 취소·만료됐어도 실제 외부 호출이나 검사 프로세스가 끝나기 전에는 실행 슬롯을 반환하지 않는다. 완료 직전에 세션·계정 상태·연결 리비전을 확인해 늦은 결과를 차단한다. `openCandidate`는 코드 파일의 사용 중 삭제를 조율하는 핸들과 release를 반환한다. 보안 접속기록과 후보 파일 수명은 구분한다.

현재 단계의 상태 목록은 계약 선언이다. 큐·SSE·취소·파일 정리 구현은 5단계다. 최종 개인정보 운영 준비에서 계정 전체 삭제를 연결할 수 있도록 내부 정리 메서드를 처음부터 계약에 포함한다.

## 설정과 기본 한도

`readAiConfig`는 환경변수를 검증해 불변 설정을 반환하며 실제 서버에는 아직 연결하지 않았다. `.env.example`은 설정 예시이며 변경만으로 AI API가 활성화되지는 않는다. 키·암호화 자료를 설정 반환값에 포함하지 않는다.

| 설정 | 기본값 | 의미 |
| --- | --- | --- |
| `AI_ENABLED` | false | 실제 AI 기능 활성화 허용 |
| `AI_ALLOW_STORED_CREDENTIALS` | false | 암호화 준비 후 영구 키 보관을 제공할 수 있는 정책 |
| `AI_ALLOWED_PROVIDERS` | 세 제공자 | 허용 제공자 ID; 빈 값은 지원하는 모든 제공자 |
| `AI_ANTHROPIC/OPENAI/GEMINI_ALLOWED_MODELS` | 빈 목록 | 각 제공자의 모델 허용 목록. 빈 목록은 연결에서 조회된 모델을 허용 |
| `AI_MAX_RUNNING` / `AI_MAX_RUNNING_PER_USER` | 2 / 1 | 실제 실행 전체/계정 한도 |
| `AI_MAX_QUEUED` / `AI_MAX_QUEUED_PER_USER` | 10 / 1 | 대기 전체/계정 한도 |
| `AI_MAX_PREPARED` / `AI_MAX_PREPARED_PER_USER` | 20 / 2 | 입력 준비 전체/계정 한도 |
| `AI_MAX_CANDIDATES_PER_USER` | 3 | 보관 후보 계정 한도 |
| `AI_CONNECTION_TIMEOUT_MS` | 10000 | 연결 확인·모델 조회 시간 제한 |
| `AI_REQUEST_TIMEOUT_MS` | 120000 | 시작 승인 후 요청 전체 제한 |
| `AI_PREPARED_TTL_MS` | 120000 | 입력 준비 수명 |
| `AI_CANDIDATE_TTL_MS` | 900000 | 완료·검사 실패 후보 수명 |

계정 한도는 해당 전체 한도보다 클 수 없다. 모든 수치는 운영 정책의 초기값이며 실제 제공자·부하 검증 후 변경한다. 코드 파일의 제품 차원 크기 제한과 모델 입력 한도는 별개다. 직접 외부 연결을 먼저 구현하며 중계 주소·인증은 실제 배포 경로 확정 후 서버 설정으로 추가한다.

## 단계 리뷰와 검증

1단계 리뷰에서 입력 대기 슬롯도 계정별 한도가 필요함을 확인해 준비·큐 한도를 보완했다. 일반 메타데이터에 비밀/소유권 필드를 받거나, 공개 조회에서 새 내부 필드가 노출되거나, 오류 메시지에서 잘못 입력한 값을 노출하는 경로를 검사했다. 해당 범위에서 추가 높은/중간 문제는 확인하지 못했다.

`node --test test/ai-contracts.test.js`는 비밀 없는 불변 설정, 잘못된 설정·한도 관계 거부, 연결 메타데이터의 소유권·키 차단, 공개 연결 필드의 비밀 제외를 검사한다. 실제 자격 증명 저장·취소·외부 API 통신은 아직 구현되지 않아 해당 동작이 검증됐다고 간주하지 않는다.
