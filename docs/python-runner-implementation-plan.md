# Python 제한 규약 실행기 작업 계획

- 상태: 계획 작성, 구현 미착수. [공통 규약·검사/저장·복구 계획](restricted-language-runners-plan.md)을 따른다.
- 2026-11-16 리뷰 반영: 실제 게임 강제 자원 한도, 독립 시간 감시·예외 억제 판정, 실패 코드 보관과 실행 허가 분리. JS J 작업의 공통 경로를 재사용한다.
- 후보: Python AST 분석·변환 + 제한된 CPython 호스트. 기존 sys.settrace 단독 방식을 제품으로 채택하지 않는다. 후보가 요구를 충족하지 못하면 제어 가능한 VM으로 재선정한다.

## P1. 허용 문법과 참조 범위

실제 게임·검사 프로세스에 공통 R0 강제 자원 한도를 코드 compile/exec·클래스 정의·생성자 전에 적용한다. Python 객체 메모리만 아니라 C 내장 모듈·스택·인터프리터와 IPC 버퍼를 포함한다. 부모가 OS 한도 적용·admission·프로세스 트리 회수를 소유하고, 확인된 자원 초과와 원인 불명 exit를 구분한다.

1. 단일 소스·Player 필수 메서드를 검사한다. 사용자 try/except/except*/finally, async/await, 임의 동적 실행·import 로더, 스레드/프로세스/대기/파일/소켓 기능을 거부한다.
2. 외부 패키지를 금지하고 math/heapq 등 표준 기능은 실제 필요한 API별로 검토한다. builtins 전체와 표준 라이브러리 전체를 자동 허용하지 않는다.
3. 클래스/모듈 가변 상태·global/nonlocal 등 공유 상태 경로를 정의한다. 호스트가 유지하는 인스턴스 상태와 소스의 선언용 이름 바인딩을 구분한다.
4. 직접/상호 재귀와 별칭·콜백·특수 메서드의 호출 경로를 분석한다. monkey patching·getattr 등 분석 불가능한 호출은 지원 범위를 제한한다. introspection을 통한 호스트 객체 접근도 부정 테스트한다.
5. comprehension/generator·with/컨텍스트 관리자·사용자 소멸자·연산자 오버로드는 숨은 반복/정리 경로를 평가해 허용 여부를 명시한다. 키워드 블랙리스트만으로 안전하다고 하지 않는다.

산출물: 사용자용 문법/표준 API 목록과 진단·우회 fixture. Python에 존재하지 않는 goto 문법 검사 대신 실제 동적 제어 우회 경로에 집중한다.

## P2. AST 자동 검사 삽입

1. 허용 루프·함수 진입과 comprehension 등 허용한 반복 구문에 호스트 예산 검사를 삽입한다. 원본 행/열 대응을 유지한다.
2. host의 호출별 마감 상태를 고정한 뒤 중단 예외로 호출을 빠져나온다. 최외곽은 마감 상태·종료 시간·정리 여부를 기준으로 판정하며 예외 타입이나 정상 반환값만 신뢰하지 않는다. 사용자 try문 금지와 내부 예산/예외에 접근할 수 없는 심볼 경계를 함께 검사한다.
3. 변환 코드 compile/exec와 객체 생성은 준비 때 1회, 턴마다 같은 메서드를 호출한다. 검사는 매 턴 재컴파일하지 않는다.
4. 긴 C 내장 함수·정규식·정렬/comparer·큰 정수 연산·할당/GC는 삽입 지점 밖에서 오래 실행할 수 있으므로 별도 측정한다. 제어 불가능한 API는 제한 후보로 보고한다.

필수 부정 시험: with의 __exit__가 예외를 억제하는 경로, 승인 표준 함수가 콜백 예외를 처리하는 경로, 정리 중 다른 예외, 기한 뒤 정상 반환, 내부 guard 바인딩 변조 시도. 초기 허용 프로필에서는 중단 신호 억제 경로가 검증되지 않은 context manager/API를 거부한다. 마감 상태는 지우지 않으며 억제 뒤 계속 실행하면 부모 감시가 유예 종료를 집행한다. 정리 완료/객체 유효성 미확인은 재사용하지 않는다.

통과 기준: 허용된 유한 계산에서 시간 초과 후 실제 호출 종료·같은 객체 정상 호출, 검사 무력화 거부, 중첩 호출/특수 메서드에서도 누락 없음. AST 변환은 보안 샌드박스 자체가 아니므로 OS 격리를 병행한다.

## P3. 독립 실행과 복구

플레이어별 프로세스를 사용하고 같은 프로세스에서 한 번에 하나의 호출만 수행한다. 긴 native 연산으로 Python 내부 관리 스레드/GIL에 의존한 감시가 지연될 수 있으므로 부모 감시자가 기한·강제 종료를 관리한다.

공통 R2의 시작 통보·host 단조 시계 duration·부모 시간 매핑을 필수 검증한다. 통보/결과 IPC의 지연과 실제 실행 시간을 구분하고, 시작 미확인·전송 미응답을 사용자 timeout으로 추정하지 않는다. OS 한도는 유예와 무관하게 계속 집행한다.

유예 중 late return·정리 실패·프로세스 종료 후 교체, 게임 종료/취소 경합을 검증한다. 예비 인터프리터·준비된 코드의 시작 비용을 측정하고 사용자 객체를 공유하지 않는다. 상태 보관 후보는 명시적 제한 데이터이며 임의 pickle 입력을 복원 경로로 허용하지 않는다.

## P4. 검사·저장 통합

동일 호스트 프로필로 공통 preflight 시나리오를 수행한다. 입력 배열·정수/문자열 변환, Python bool 등 반환 타입의 오판, 예외 원본 위치 진단을 검증한다. 검사 실패 코드도 보관하되 실행은 허용하지 않는다. 먼저 완료한 JS J 작업의 저장 성공/검사 상태 분리·동일 hash/revision 결과 갱신·stale 처리 계약에 연결한다.

준비/검사 세션 CPU·메모리/출력/전체 기한, interpreter 종료와 임시 파일 정리를 구현한다. 외부 패키지 다운로드나 시스템 Python 환경 변경을 요구하지 않는 배포 산출물을 정의한다.

## P5. 완료 판정

- BFS/반복형 DFS·허용 컬렉션·영속 인스턴스 필드 동작.
- try/except/finally·직접/상호 재귀·동적 호출/호스트 접근·비동기/병렬 우회 거부.
- 큰 입력·긴 내장 함수·메모리 사용과 반복 timeout/복구 결과 보관.
- 실제 게임 프로세스의 OS 강제 한도·전체 예약·동시 과할당·제한 설정 실패·고아 회수 검증. 예외 억제/변형·기한 경합 및 GIL과 독립적인 부모 감시 통과.
- 독립 진행/비중첩/late return·검사/저장 정합성 통과.
- 허용 프로필에서 통과하지 못하면 CPython 후보 보류. Python을 Wasm에 넣는 것만으로 인터프리터 상태 복구가 해결된 것으로 처리하지 않음.

참고: [Python 추적 함수와 제한](https://docs.python.org/3.12/library/sys.html#sys.settrace). 본 계획의 AST 변환은 기존 trace 실패를 해결할 후보이며 아직 통과한 구현이 아니다.
